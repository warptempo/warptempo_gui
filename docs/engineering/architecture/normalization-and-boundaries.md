### Load-Lenient, Render-Normalizing Boundaries
Gestures move freely and NOTHING POPS, ever: markers and trim bounds may sit arbitrarily close, overlap exactly, and cross during gestures on both columns, and no commit opens a modal — the defect-resolution funnel is RETIRED (directive #11, architect 2026-07-15). Ambiguous authored states are NORMALIZED at the render/preview boundary instead of refused or force-resolved: every ambiguous tempo resolves to 1.00. The chokepoint is `resolve_warp_markers_for_render` (staged pipeline and output invariants at its header, `warp_frame_map_build.h`), which every render path AND the target-view recompute funnel through, so display and render cannot disagree: (1) filter to survivors (disabled + cascade), (2) collapse each EXACT-same-frame surviving group to ONE plain enabled 1.00 owner, no labels (a def dying in a collapse makes its refs dangling, normalized in turn — deterministic cascade), (3) silently seed a plain 1.00 owner at frame 0 when no survivor sits there — MANDATORY CORRECTNESS: `build_warp_frame_map` seeds {0,0} and attributes the opening segment to the first resolved marker wherever it sits, so a missing frame-0 SURVIVOR (disabled-at-0 included) would otherwise render silently wrong bytes; the seed is decided on the surviving list by explicit ruling and is silent (the documented default, not ambiguity), (4) materialize passes through the ref-OPAQUE inheritance walk — a surviving enabled label ref terminates the walk with the 1.00 fallback (a ref owns a duration equation, not a rate), (5) normalize label refs: dangling, or implied effective tempo outside the authored per-marker envelope [0.125, 8.0] (`kRefImpliedTempoMin/Max`, scale-free so hover mirrors it without seeing the settings scale) → a plain 1.00 owner at its own frame. Every normalization except the seed prints ONE stderr line per timestamp PER RESOLVE (no dedup or session state — a resting ambiguous store re-prints on each preview recompute, the intended signal). The hover surfaces (`marker_effective` / `compute_hover_popup_text`) share the walk and the envelope constants: a normalized ref reads `= 1.00 (undefined label)` / `= 1.00 (extreme label ratio)` (hard `=`, exact literal), a ref-hit pass reads `= 1.00` with no provenance (the ctrl+c copy notice left the popup text 2026-07-20; the copy behavior itself is unchanged). The GUI STORE stays the authored truth — coincident-group members still paint, hover, and Tab-pick individually; the collapse is render-domain (accepted display split, stderr the signal). NORMALIZATION-RED (2026-07-21, opus session): a marker that renders as the 1.00 fallback ALSO paints its FLAG red (kAccent fill + kAccentOutline ring) — a display cue alongside the stderr, revising the pure stderr-is-the-signal rule for the coincident case (an earlier attempt reddening the wave SEGMENT was reverted — a floating red span had no bound and read oddly, the marker flag is the bounded cue). The red set is computed SILENTLY GUI-side from the COMMITTED store (a memoized generation-keyed helper, `warp_red_flag_set_cached` / `phase_reset_red_flag_set_cached` in warp_frame_map_view; committed-store + generation memo = a red flag HOLDS through a marker drag and re-evaluates only at commit, mirroring the displayed-map wait): the ref/pass fallbacks via `marker_effective` (source_idx == -1 with a ref reason — UndefinedLabel/ExtremeRatio — OR the `from_ref` bit, so a PASS reddens only when it inherits from a ref, NOT when it inherits a real value from a synthetic prior — the frame-0 seed or a collapsed owner), and the exact-frame collapse via a same-frame count of 2+ effectively-enabled members reddening EVERY member (the overlapping stack reads as ONE red flag, matching the single stderr line). No frozen resolver out-param is needed (the 1730d99 out-param was reverted as redundant); the frozen touches here are TWO granted siblings on `MarkerEffective`, each a value the walk already computed and discarded: the `from_ref` bool (2026-07-21) and `owner_idx` (2026-07-22, 2aa5738 — the ref-opaque backward walk's terminal owner as a raw store index, -1 whenever no raw owning marker exists; sole consumer is the tempo drag's label-coupling guard). Phase resets get the SAME red on a coincident enabled collapse (a same-frame count on the phase-reset store — the symmetric sibling; no marker_effective analog, phase resets carrying no tempo/labels). Selection is NOT a color class and never masks red (2026-07-27, the kSelected/kSelectedOutline deletion: a selected red marker keeps its red pair, so the normalization cue always shows); the frame-0 seed is silent and unreddened; no new flag-cache fingerprint field (the red set only changes on a generation bump the flag cache already keys on). Phase reset column: exact-equal enabled resets collapse to one event inside `build_phase_reset_source_frames`, one stderr line per timestamp (positions are whole frames, so sub-frame spacing IS equality). `kFingerprintVersion` was bumped to 7 with this contract (extreme refs previously rendered their unclamped ratio). The marker stores are ALWAYS time-sorted at rest, ties legal with stable order; every time-mutating gesture routes through `reorder_markers_by_time` + `remap_marker_indices_after_reorder` (`app_state.h`). MARKER gesture walls are absolute — zero and total-1 for BOTH columns (warp structurally, phase reset by ruling: a reset in the last source frame has nothing to re-ground, and total-1 keeps every marker inside the playhead's [0, total-1] domain; a stored reset at exactly total is adversarial load-fatal); mouse drags compose the walls with the visible-strip clamp; nudges have no viewport gate, so the walls are exactly reachable by nudge. The playhead rests in [0, total-1] of its live view after any gesture (ruling spelled ONCE at `clamp_playhead_to_live_domain`, `app_state.h` — every playhead write funnels through it: `Viewport::move_playhead_to`, the gesture-side sync/pin sites, and the load/Ctrl+Tab/adopt live-ization routes; persisted playhead == total stays load-legal, runtime clamp owns it at first use). TRIM (ruling at the `TrimState` store, `app_state.h`): begin and end are authored named roles — no role swap ever — whole int64 source frames like marker times (persistence is exact integer text through `frame_format.h`). Both bounds wall at the shared [0, total-1] domain (the former exclusive end-at-total wall is retired); no partner walls, crossing free during gestures, but crossed/equal can no longer REST anywhere: every trim COMMIT (the `x` trim-to-region set, drag release) runs `auto_clear_crossed_trim` — a bound committed onto or across its partner (`end <= begin`, exact integer compare) destroys BOTH bounds, silently (the chips vanish) — and a persisted per-tab pair with `end <= begin` clears both of that tab's bounds at load with one stderr line (placed AFTER the adversarial past-EOF hard-fail, so a crossed pair containing a past-EOF bound still aborts identically in both products). A LONE bound (exactly one set — settings-editor/load-reachable) COMPLETES to its extreme at the render boundary (missing begin → 0, missing end → total; architect 2026-07-19) and renders its obvious window, matching the navigation semantics Home/End, the Space gate, and `compute_trim_samples`' per-side extremes always had — the store keeps the authored lone bound and lone remains gesture-inert (pair required). A set trim (any bound) also LOOPS the audition (architect 2026-07-19): the Space launch captures the loop verdict and window ONCE — like `end_sample`, mid-session follow/trim edits take effect at the next launch — and the audio callback wraps the read position from the window end back to the trim begin, a raw cut with clicks accepted by ruling (no crossfade/declick); the wrap is a ruled predictor resync event, detected main-thread via `GuiPlayback::loop_wrap_seq()` (a monotonic audio-thread counter — the clamped `cursor()` cannot reveal the backward jump), independent of follow mode (follow off just means no viewport tracking of the wrapped scanner); the click-keep-alive reseek preserves the session's captured verdict via `app.playback_loop_start_sample`. An unhonorable trim window that still reaches render renders UNTRIMMED with one stderr line — TWO reachable refusals: "trim end at or before trim begin" (reachable exactly via a lone END at frame 0 completing to (0, 0); set pairs can never rest crossed/equal) and a target span rounding below one output sample under a fast tempo (`plan_trim`'s refusals, fallbacks, not failures) — and the one downstream read that must mirror the completion-then-refusal outcome is the target-buffer playback anchor (`compute_buffer_start_frame_for`, which completes identically and re-derives both refusal verdicts in `validate_trim_frames`' check order, so a fallback buffer anchors 0 and its `fallback_reason` names the case at the reuse-rung diagnostics). Trim BOUNDS stay outside the selection system (architect 2026-07-18: never selected, never Tab stops, no Delete, no keyboard nudge), but the trim WINDOW joined the selection-highlight coupling by architect order (the lane click model, 2026-07-23): a plain chip-row click, both trim drags' motion/release/Esc-restore, and the shift/ctrl chip-row bound sets all run `sync_highlight_to_trim_window` — both bounds set → the region takes the window's clamped active-domain extent UNLESS the two mapped bounds round coincident, which takes the clear arm instead (the coincident-span policy — see the PROVENANCE rule; a full authored pair does NOT imply an active TrimWindow region); lone/none/dissolved → the region clears (the no-window rule) — the SELECTION is never touched either way (downward-only, architect 2026-07-23: selection → region → trim, nothing upward — trim gestures touch neither the playhead nor the selection; `select_contained_in_span` is deleted) — while the playhead is NEVER touched (the 2026-07-18 rule holds there); ctrl MOVES the BEGIN bound and ctrl+shift the END at the clicked column AND arms the single-bound drag on it (motion past the threshold drags it live; the Esc-restore origin is the PRE-PRESS pair — set_click makes the restore unconditional — so Esc undoes the whole gesture, click-set included, while the drag base stays the clicked column for jump-free tracking), ADJUST-ONLY — a silent no-op without a resting full pair (the window is created by region→x; the settings editor stays the deliberate lone-bound route; authored_frame_at_column on the displayed basis, walls, the auto_clear_crossed_trim tail; the labwc co-display sighting was a lone bound's one-sided out-of-trim dim contrast misread as the highlight (that dim is itself retired since the 2026-07-26 opaque-recolor arc), the highlight/split suppression itself airtight by the R5 audit), read-only refusing the sets but keeping the navigation sync; `x`/`Shift+X`, the chip/bridge drags, the chip-row clicks, and Home/End are trim's whole interface. Any further trim-vs-marker time asymmetry needs architect approval. Warp marker zero is an ordinary marker — the default `0|1.00` seeded into a missing `.warpmarkers` file at source load — deletable, movable, disable-able (the render-time seed covers its absence). Label defs are deletable with live refs — the orphaned refs render as 1.00 with stderr lines; the text editor's red-flash guard remains the input-time surface (you cannot TYPE a dangling ref), and the flag editor's rename cascade applies only to non-empty new names. Rapid keyboard gestures COALESCE their undo granularity: a burst of the same eligible gesture — warp/phase-reset nudges (Alt+Left/Right) and tempo cent steps (Alt+Up/Down; no wheel route) — landing within `kGestureCoalesceMs` (500 ms — raised from 150 so deliberate manual repetition coalesces like held-key repeat; the command-adjacency guard makes the wider window safe) as CONSECUTIVE COMMANDS collapses to ONE undo entry, so a single Ctrl+Z reverts the whole burst (the burst's first press pushes the pre-burst snapshot; continuation presses SKIP their push via `Undo::coalesce_gesture` and route the surviving per-press side effect through `Undo::note_coalesced_commit` — the hover-clear; the visible move, reorder/remap, dirty, and the target-view preview stay per-press). The merge is guarded by COMMAND ADJACENCY alone: `AppState::command_seq` bumps once per discrete user command at the three dispatch entry points (`on_key`, `on_button_press`, `on_wheel` — the platform delivers only actionable key PRESSES to `on_key`, dropping bare modifiers and releases first), and two eligible presses coalesce only when the second is the IMMEDIATELY-NEXT command (`command_seq == recorded + 1`), of the same `GestureKind`, inside the window, with a non-empty stack (`record_gesture` re-stamps the command after each eligible commit). So ANY intervening command — a click, Tab, `p`, trim-click, save, undo/redo, paste, zoom, a tab/column switch, or any other keypress — breaks the burst; "same selection / same tab / same history" all follow for free, because none can change without a command in between (a preview buffer swap is same-target). This single closed instrumentation point deliberately REPLACED an earlier multi-counter guard (a per-mutation `selection_gen` plus `undo_epoch`, incl. a `mark_saved` bump for the save case) whose scattered bump sites kept leaking missed selection paths — the wind-down "remove the leaking surface, don't patch each finding" rule; the save case now rides command adjacency (Ctrl+S is a command). Trim (history-less, no undo) and mouse drags (already one commit at release) are ineligible; the render/preview path is unchanged (its kill-on-redispatch already coalesces the target-view previews).

The two-category boundary rule (architect-ruled, #11 form): a state the GUI lets the user COMMIT always LOADS and always RENDERS — normalized to 1.00 / no-trim where ambiguous, with stderr lines as the signal; a state the GUI can NEVER produce is ADVERSARIAL and hard-fails the load, stderr only, FIRST error only (no friendly listing — fixing one defect can create another, so one-shot completeness is futile, and adversarial input earns no user-friendliness). Load-fatal (adversarial): syntax errors, unopenable files, duplicate label definitions, DECREASING marker times, out-of-bracket or non-positive values, fractional/negative/malformed/non-finite frame positions (including the old timestamp format), hash lines that are not valid disabled markers (comment lines are not part of the authored grammar; legacy '#' passthrough survives only in the migration tool), sub-44100 sample rates, settings-schema violations (the whole-file readers above — unknown keys, duplicates, malformed or out-of-vocabulary values), a settings title whose composed render output path lands on the source file (`render_output_source_collision`, `render_output_naming.h` — refused at editor commit, at BOTH product loads, with the render worker as breach backstop), malformed WAV containers (a declared chunk size past EOF, a RIFF size contradicting the physical container — 8 + riff_size == file size required; the `0xffffffff` streamed-placeholder tolerances are REMOVED, such files hardfail — duplicate fmt/data chunks, a byte_rate contradicting sample_rate times block_align, a WAVE_FORMAT_EXTENSIBLE cbSize running past its own fmt chunk, and a zero-frame data chunk; the PCM24 writer refuses non-finite input as the outbound breach guard; probe failures print the owner diagnostic verbatim — the render worker included — with the convert-once hint appearing GUI-side only for `kUnknownAudioMagicError`), and PAST-EOF positions — any marker past its column wall or any tab's trim bound past its per-bound wall, disabled markers included, checked identically in GUI and CLI through the ONE implementation (`first_past_eof_wall_defect`, `marker_store_validate.h`; a file set is loadable or not, the same in both binaries; markers apply only to the audio they were authored against — swapping the audio happens outside the GUI). Opening a `.samples`/`.peaks` cache file prints a stderr refusal and exits (the launch-only loader has no blank state to fall back to) — never a silent redirect to a guessed owner. Loads intact and renders, normalized where ambiguous: equal/close marker times, dangling label refs, a pass inheriting from a label ref, any (or no) first marker, the empty file, equal or INVERTED trim bounds (cleared at load per tab, stderr line), and a trim bound under a map format (the map render silently ignores it).

What remains of the render boundary is tripwire-class: `build_warp_frame_map`'s `std::expected` errors — invalid metadata, past-EOF marker time (breach backstop, column-symmetric by ruling), sub-frame segment (kept: the engine validates strict ascent but NOT the >=1-frame gap — the one map defect that would render silently wrong), dangling label ref (kept: the engine never consumes refs — a breach would be raw UB, not a loud refusal), and non-positive tempo product (REACHABLE: the ruled async-stderr backstop for the sweep batches' per-cell computed tempo mutations, deliberately unbracketed; kept HERE for message vocabulary — the engine would only say "not strictly ascending", this site names the tempo). The engine-duplicated finite/vanish/divisor trio was removed 2026-07-17 — breaches land on the engine's own loud init validators. `resolve_warp_markers_for_render` returns a PLAIN vector (a total normalizer, infallible by design — only the partial-compiler builder keeps `std::expected`). Plus `build_phase_reset_source_frames`' past-EOF wall, and `validate_trim_frames` (`src/prepost/trimmer.h`), which stays the sole AUTHOR of the trim-validity vocabulary while its refusal now means "render untrimmed" at both orchestrators (GUI `do_render`, CLI), one stderr line, never a failed render. The engine's strict-ascent and cap tripwires are unchanged breach guards for hand-edited artifacts, unreachable from program-written input.


The design premise: the GUI assumes a non-adversarial user — gestures are never guarded mid-flight, and ambiguous states are RESOLVED BY THE RENDER (1.00 / no-trim, stderr lines), not reported, gated, or force-walked. Tab/Shift+Tab reaches every member of a mouse-unpickable MARKER group (exact-frame stacks and cross-column ties are legal at rest); trim bounds are not Tab stops — they are unselectable, and Home/End is their navigation. Text-editor commits refuse with the red-flash (the iter-bracket commit gates base_tempo plus either bound against the tempo bracket this way — the sweep's cells are bounded by the bracket endpoints, so a bracket whose cells could not all re-parse at promote refuses at its own input surface; a later tempo change under a live bracket is deliberately not re-gated, session-only state with the build refusal and strict promote parse as backstops, and a refused `'` adopt of a bad entry sidecar red-flashes the commit editor — the standalone `adopt_render_entry` reads and validates every sidecar before mutating authoring and returns false untouched). Prompt text and options join with single spaces; GUI and stderr output never contain a double space (the WARPTEMPO_PROFILE instrumentation that carried the sole exception is removed).
