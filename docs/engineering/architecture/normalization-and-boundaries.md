### Load-Lenient, Render-Normalizing Boundaries
Gestures move freely and NOTHING POPS, ever: markers and trim bounds may sit arbitrarily close, overlap exactly, and cross during gestures on both columns, and no commit opens a modal — the defect-resolution funnel is RETIRED (directive #11, architect 2026-07-15). Ambiguous authored states are NORMALIZED at the render/preview boundary instead of refused or force-resolved: every ambiguous tempo resolves to 1.00. The chokepoint is `resolve_warp_markers_for_render` (staged pipeline and output invariants at its header, `warp_frame_map_build.h`), which every render path AND the target-view recompute funnel through, so display and render cannot disagree: (1) filter to survivors (disabled + cascade), (2) collapse each EXACT-same-frame surviving group to ONE plain enabled 1.00 owner, no labels (a def dying in a collapse makes its refs dangling, normalized in turn — deterministic cascade), (3) silently seed a plain 1.00 owner at frame 0 when no survivor sits there — MANDATORY CORRECTNESS: `build_warp_frame_map` seeds {0,0} and attributes the opening segment to the first resolved marker wherever it sits, so a missing frame-0 SURVIVOR (disabled-at-0 included) would otherwise render silently wrong bytes; the seed is decided on the surviving list by explicit ruling and is silent (the documented default, not ambiguity), (4) materialize passes through the ref-OPAQUE inheritance walk — a surviving enabled label ref terminates the walk with the 1.00 fallback (a ref owns a duration equation, not a rate), (5) normalize label refs: dangling, or implied effective tempo outside the authored per-marker envelope [0.125, 8.0] (`kRefImpliedTempoMin/Max`, scale-free so hover mirrors it without seeing the settings scale) → a plain 1.00 owner at its own frame. Every normalization except the seed prints ONE stderr line per timestamp PER RESOLVE (no dedup or session state — a resting ambiguous store re-prints on each preview recompute, the intended signal). The hover surfaces (`marker_effective` / `compute_hover_popup_text`) share the walk and the envelope constants: a normalized ref reads `= 1.00 (undefined label)` / `= 1.00 (extreme label ratio)` (hard `=`, exact literal), a ref-hit pass reads `= 1.00` with no provenance (the ctrl+c copy notice left the popup text 2026-07-20; the copy behavior itself is unchanged). The GUI STORE stays the authored truth — coincident-group members still paint, hover, and Tab-pick individually; the collapse is render-domain (accepted display split, stderr the signal). NORMALIZATION-RED (2026-07-21, opus session): a marker that renders as the 1.00 fallback ALSO paints its FLAG red (the marker lane's own red pair kMarkerFlagFillRed/kMarkerFlagEdgeRed since row 5 — the retired kAccent pair's successor) — a display cue alongside the stderr, revising the pure stderr-is-the-signal rule for the coincident case (an earlier attempt reddening the wave SEGMENT was reverted — a floating red span had no bound and read oddly, the marker flag is the bounded cue). The red set is computed SILENTLY GUI-side from the COMMITTED store (a memoized generation-keyed helper, `warp_red_flag_set_cached` / `phase_reset_red_flag_set_cached` in warp_frame_map_view; committed-store + generation memo = a red flag HOLDS through a marker drag and re-evaluates only at commit, mirroring the displayed-map wait): the ref/pass fallbacks via `marker_effective` (source_idx == -1 with a ref reason — UndefinedLabel/ExtremeRatio — OR the `from_ref` bit, so a PASS reddens only when it inherits from a ref, NOT when it inherits a real value from a synthetic prior — the frame-0 seed or a collapsed owner), and the exact-frame collapse via a same-frame count of 2+ effectively-enabled members reddening EVERY member (the overlapping stack reads as ONE red flag, matching the single stderr line). No frozen resolver out-param is needed (the 1730d99 out-param was reverted as redundant); the frozen touches here are TWO granted siblings on `MarkerEffective`, each a value the walk already computed and discarded: the `from_ref` bool (2026-07-21) and `owner_idx` (2026-07-22, 2aa5738 — the ref-opaque backward walk's terminal owner as a raw store index, -1 whenever no raw owning marker exists; its sole consumer was the tempo drag's label-coupling guard, so it went caller-less with contortion ruling 8 and is now DELETED — 2026-07-29, under an explicit surgical freeze approval; `from_ref` beside it stays, its normalization-red consumer being alive, and `resolve_inherited_tempo`'s defaulted `owner_index` out-parameter stays as an unused capability). Phase resets get the SAME red on a coincident enabled collapse (a same-frame count on the phase-reset store — the symmetric sibling; no marker_effective analog, phase resets carrying no tempo/labels). Selection is NOT a color class and never masks red (2026-07-27, the kSelected/kSelectedOutline deletion: a selected red marker keeps its red pair, so the normalization cue always shows); the frame-0 seed is silent and unreddened; no new flag-cache fingerprint field (the red set only changes on a generation bump the flag cache already keys on). Phase reset column: exact-equal enabled resets collapse to one event inside `build_phase_reset_source_frames`, one stderr line per timestamp (positions are whole frames, so sub-frame spacing IS equality). `kFingerprintVersion` was bumped to 7 with this contract (extreme refs previously rendered their unclamped ratio). The marker stores are ALWAYS time-sorted at rest, ties legal with stable order; every time-mutating gesture routes through `reorder_markers_by_time` + `remap_marker_indices_after_reorder` (`app_state.h`). MARKER gesture walls are absolute — zero and total-1 for BOTH columns (warp structurally, phase reset by ruling: a reset in the last source frame has nothing to re-ground, and total-1 keeps every marker inside the playhead's [0, total-1] domain; a stored reset at exactly total is adversarial load-fatal); mouse drags compose the walls with the visible-strip clamp; nudges have no viewport gate, so the walls are exactly reachable by nudge. The playhead rests in [0, total-1] of its live view after any gesture (ruling spelled ONCE at `clamp_playhead_to_live_domain`, `app_state.h` — every playhead write funnels through it: `Viewport::move_playhead_to`, the gesture-side sync/pin sites, and the load / Ctrl+Tab / load-in-place live-ization routes; persisted playhead == total stays load-legal, runtime clamp owns it at first use). TRIM (ruling at the `TrimState` store, `app_state.h`): begin and end are authored named roles — no role swap ever — whole int64 source frames like marker times (persistence is exact integer text through `frame_format.h`). TRIM IS ALWAYS SET (architect 2026-07-30, the region simplification arc): the window always holds a full ordered pair — REST INVARIANT 0 <= begin < end <= total-1 for a source of 2+ frames, the canonical full pair [0,0] on a load-legal one-frame source — and the UNSET STATE IS DELETED, has-bits, lone bounds, `-1` spelling and all (the `-1` grammar died in the FROZEN parser under an explicit same-day grant, recorded at each site; a sidecar still carrying `-1` is adversarial and load-fatal in both products, hand-edit the ruled recovery — no migration tool by ruling). THE FULL WINDOW [0, total-1] IS SEMANTICALLY THE OLD UNSET STATE through ONE shared predicate, `trim_window_is_full` (settings_file.h — deliberately in the shared schema header, the kMinZoom precedent, so both products recognize it identically): it renders UNTRIMMED (no trim plan at the three orchestrators — a (0, total-1) pair through the frozen trimmer would NOT be byte-identical, the crop fires and the authored end-wall drops the last frame's target span, so the translation is load-bearing), normalizes to {0, total} / {0, live_total} at the two playback/navigation range owners (`compute_trim_samples`, `Viewport::trim_range` — End reaches total-1, near-end launches stay legal), hashes as the old unset bytes at the render fingerprint (full-window renders reuse pre-arc untrimmed cache identities, no version bump), falls to the whole-song arm at the zoom framer, and is recognized BEFORE the crossed/sub-sample diagnostics so a one-frame source renders untrimmed with no false fallback. The first-open template stamps the full window on both tabs; every reset seeds it (`full_trim_window`). Both bounds wall at the shared [0, total-1] domain; partner walls are PER-ROUTE since 2026-08-02 (the blanket no-partner-walls clause is split, authoritative at input_trim.cpp's header): the SINGLE-BOUND DRAG CLAMPS INCLUSIVELY AT ITS PARTNER — the handles cannot move past each other, the moving bound can land ON the resting one, and a coincident release resets to the full window through the unchanged commit rule, making drag-onto-partner the drag's own trim-clear route — while the bridge drag needs no wall (rigid delta, invariant gap), the bound-set clicks keep their stricter strictly-inside refusal, and the typed/loaded routes still cross freely; crossed/equal can no longer REST anywhere: every trim COMMIT (the `x` trim-to-region set, drag release, the settings trim keys' live arm) runs `auto_clear_crossed_trim` — a bound committed onto or across its partner (`end <= begin`, exact integer compare, tested FULL-WINDOW-FIRST so the one-frame [0,0] never self-resets) RESETS BOTH bounds to the song edges, silently (the endcaps jump to the edges as the signal) — with ONE route refusing rather than feeding it: `x` REFUSES A DEGENERATE RESULT (ARCHITECT-CONFIRMED 2026-07-29; when the region's inverse-mapped, wall-clamped pair comes out `end <= begin` — a narrow span over ~16x bracket-legal compression whose endpoints inverse-map onto one source frame — `x` writes NOTHING at all and trim, region and selection all rest; the refusal tests the pair `x` would WRITE, blind to where the span came from, so `x` can never reach the auto-clear's reset arm, which stays reachable where the user AIMS it: the bound-set click and the drag release, where the endcaps visibly jump). A persisted per-tab pair with `end <= begin` RESETS to that tab's full window at load with one stderr line (placed AFTER the adversarial past-EOF hard-fail, so a crossed pair containing a past-EOF bound still aborts identically in both products). THERE IS NO AUDITION LOOPING ANYWHERE (architect 2026-07-30: "looping behavior is not that useful. ok to remove all looping" — deleting the 2026-07-19 set-trim-loops ruling and its whole apparatus: the launch-captured loop verdict, the loop_start plumbing, the audio-callback wrap, the loop_wrap_seq predictor-resync counter, and the keep-alive reseek's verdict preservation): every audition plays once from its launch position to its end — the trim window's end, which for the full window is the song's natural end — and stops through the natural-end path, which is now the only terminal. Mid-session trim edits still take effect at the next launch (`end_sample` is launch-captured as before), and a trim mutation still STOPS a live audition in both views (the keyboard stop rule). An unhonorable trim window that still reaches render renders UNTRIMMED with one stderr line — ONE refusal reachable from live state under always-set trim: a target span rounding below one output sample under a fast tempo (`plan_trim`'s refusal, a fallback, not a failure; the "trim end at or before trim begin" refusal is breach-only now — lone bounds are gone and a crossed pair cannot rest) — and the one downstream read that must mirror the outcome is the target-buffer playback anchor (`compute_buffer_start_frame_for`, which recognizes the FULL WINDOW FIRST — no plan, no fallback_reason — then re-derives the refusal verdicts in `validate_trim_frames`' check order for a sub-window, so a fallback buffer anchors 0 and its `fallback_reason` names the case). Trim BOUNDS stay outside the selection system (architect 2026-07-18: never selected, never Tab stops, no Delete, no keyboard nudge), and THE TRIM-WINDOW HIGHLIGHT COUPLING IS RETIRED (2026-07-30, the region simplification): no route publishes the window as a region any more — `sync_region_to_trim_window` and both wrappers are deleted, RegionProvenance with them — because the window's permanent display is its ALWAYS-PAINTED bar and endcaps (always-set trim; the has-gates died with the unset state). WHAT SURVIVES OF RULING 2 IS THE SETTER DESELECT (architect 2026-07-29, re-affirmed 2026-07-30: "clicking trim means ready to move on" / "a typed commit is a commit"): every route that WRITES a bound clears the selection past its own refusals — the ctrl / ctrl+shift bound-set click, bare `x`, the endcap/bridge drag at its FIRST ACCEPTED bound change (motion arms and release — where the drag's trim-mutation STOP now lives too, relocated 2026-07-30 from the retired press-time stop), and the settings trim keys' active-tab arms (a parked-band commit deselects nothing). THE NON-SETTERS: `Shift+X` (the MAXIMIZER — it writes the full window behind an already-full identity guard, touching no region and no selection) and every entry/restore route (load, the Ctrl+Tab band pull, `t`, `p`, the load-in-place), which rest pairs bare. Motion past the threshold drags the set bound live; nothing is snapshotted — the click-set is committed the moment it is made, trim being history-less; authored_frame_at_column on the displayed basis, walls first, then the strictly-inside guard); `x`/`Shift+X`, the endcap/bridge drags, the bound-set clicks, and Home/End are trim's whole interface. Label defs are deletable with live refs — the orphaned refs render as 1.00 with stderr lines; the text editor's red-flash guard remains the input-time surface (you cannot TYPE a dangling ref), and the flag editor's rename cascade applies only to non-empty new names. Rapid keyboard gestures COALESCE their undo granularity through a HYBRID OF TWO RULES (architect 2026-08-01, superseding the pure repeat-identity model's separate-presses clause on the live complaint that rapid manual taps each pushed their own entry): (1) REPEAT IDENTITY for a HELD key — a HELD key's synthesized repeats collapse into ONE undo entry with the physical press that started the hold, NO clock consulted, so a hold coalesces at any compositor repeat delay/rate; and (2) THE TAP WINDOW for consecutive PHYSICAL presses — a same-kind physical press within `kTapCoalesceMs` = 500 of the last ACCEPTED coalesce event merges too, PROVIDED THE SUBJECT STILL STANDS (the stamped selection and A/B tab — the tap arm's structural stand-in for the repeat contract's event-edge disarms, without which a different marker's nudge could merge into the first marker's entry). Either way a single Ctrl+Z reverts the whole burst; presses beyond the window, or after a subject change, are separate entries. The eligible kinds are enumerated at `GestureKind` (undo.h) — THREE, re-derived 2026-07-29 when the TEMPO-IMAGE STEP and its own kind were deleted with the tempo-image family (contortion ruling 8): the warp and phase-reset position nudges (bare Left/Right with a selection, in each column's home view), and the tempo cent step (bare Up/Down; no wheel route), whose singleton and group arms share one kind and so make FOUR eligible routes over THREE `coalesce_gesture` call sites. THE MECHANISM: the platform stamps every synthesized repeat it delivers with `GuiInputState::synthesized_repeat` (set in exactly ONE place, `maybe_fire_repeat` — a platform-boundary fact like `codepoint`); the burst's PHYSICAL press pushes the pre-burst snapshot and stamps its kind (`Undo::record_gesture`); a press that commits and coalesces SKIPS its push (`Undo::coalesce_gesture` — a synthesized repeat on same kind + non-empty stack with NO clock and NO counter, or since 2026-08-01 a physical tap inside the 500ms window with the subject standing) and routes the surviving per-press side effects through `Undo::note_coalesced_commit` (the hover-clear) and `Undo::refresh_coalesced_touched_live` (final-state identity hints — a later press in the burst can reorder members); the visible move, reorder/remap, dirty, and the target-view preview stay per-press. RAPID MANUAL TAPS COALESCE THROUGH THE TAP WINDOW since 2026-08-01 (the old "separately undoable — the more literal gesture boundary" delta is the clause the architect reversed; a tap that misses the window or finds a changed subject still opens its own entry). COMMAND ADJACENCY SURVIVES STRUCTURALLY rather than numerically: the platform repeat contract's event-edge disarms (layer (1) at `maybe_fire_repeat`, now recorded there as LOAD-BEARING for undo correctness) kill a hold at any intervening pointer-button press, completed wheel emission, or key press, so no synthesized repeat can arrive after an intervening command — and the one route the disarms cannot see (state changing under an async worker publish flipping a refusal mid-hold, no command in between) is closed from BOTH ENDS by two stamp rules, the second added 2026-07-29 by the final codex round's MEDIUM 2. (a) EVERY STACK-TOP CHANGE OUTSIDE THE BURST clears the recorded kind — all four `push_*` helpers AND the undo/redo restore's pop (`restore_history_entry`) — so a stale kind can never coexist with a foreign stack top. (b) AN ELIGIBLE PHYSICAL PRESS INVALIDATES THE STAMP ON ARRIVAL: `coalesce_gesture` clears the kind whenever the press asking it is physical rather than synthesized — since 2026-08-01 AFTER computing that press's own tap verdict (verdict first, invalidate second, else the invalidate would kill the very stamp the tap arm reads), and `record_gesture` re-stamps only on the accepted path, so a refusing press still leaves the stamp invalid. Rule (b) is what covers a press that REFUSES — a nudge at its wall, a zero-step press, an ineligible tempo step — since a refusal pushes nothing and so triggers none of (a); without it, a refused press left the PREVIOUS burst's stamp standing, and if the async publish then flipped the refusal the burst's own first repeat would merge a DIFFERENT subject's edit into that older entry, leaving one Ctrl+Z to revert two holds with identity hints naming different markers. Because the invalidate lives inside the entry question itself, each eligible route gets it by construction, and each route asks that question ahead of everything that can refuse on geometry or walls. The old headline "SEPARATE PRESSES ARE SEPARATE ENTRIES" HELD EXACTLY from 2026-07-29 until the architect reversed it 2026-08-01 (the tap window above); what survives of it exactly is the REFUSAL half — a refused press never enables a later merge into an older entry, tap or repeat — and the beyond-the-window / changed-subject arms. (`record_gesture` still runs after the push at every eligible route, so intended merges are unaffected; the derivation for both rules lives at `coalesce_gesture`.) NO ACCEPTED DELTA REMAINS AT THE GATE on either arm: the one that stood here — two same-kind bursts with no command between them merging across the release gap when the second burst's PHYSICAL press refused, the stamp surviving because a refusal pushes nothing — died with the invalidate-on-arrival rule above, and the hybrid preserves the property (`record_gesture` stamps only on the accepted path). Trim (history-less, no undo) and mouse drags (already one commit at release) are ineligible; the render/preview path is unchanged (its kill-on-redispatch already coalesces the target-view previews).

The two-category boundary rule (architect-ruled, #11 form): a state the GUI lets the user COMMIT always LOADS and always RENDERS — normalized to 1.00 / no-trim where ambiguous, with stderr lines as the signal; a state the GUI can NEVER produce is ADVERSARIAL and hard-fails the load, stderr only, FIRST error only (no friendly listing — fixing one defect can create another, so one-shot completeness is futile, and adversarial input earns no user-friendliness). Load-fatal (adversarial): syntax errors, unopenable files, duplicate label definitions, DECREASING marker times, out-of-bracket or non-positive values, fractional/negative/malformed/non-finite frame positions (including the old timestamp format, and including the retired trim `-1` unset spelling — deleted 2026-07-30 with always-set trim, so it is now just a negative value), hash lines that are not valid disabled markers (comment lines are not part of the authored grammar; legacy '#' passthrough survives only in the migration tool), sub-44100 sample rates, settings-schema violations (the whole-file readers above — unknown keys, duplicates, malformed or out-of-vocabulary values), a settings title whose composed render output path lands on the source file (`render_output_source_collision`, `render_output_naming.h` — refused at editor commit, at BOTH product loads, with the render worker as breach backstop), malformed WAV containers (a declared chunk size past EOF, a RIFF size contradicting the physical container — 8 + riff_size == file size required; the `0xffffffff` streamed-placeholder tolerances are REMOVED, such files hardfail — duplicate fmt/data chunks, a byte_rate contradicting sample_rate times block_align, a WAVE_FORMAT_EXTENSIBLE cbSize running past its own fmt chunk, and a zero-frame data chunk; the PCM24 writer refuses non-finite input as the outbound breach guard; probe failures print the owner diagnostic verbatim — the render worker included — with the convert-once hint appearing GUI-side only for `kUnknownAudioMagicError`), and PAST-EOF positions — any marker past its column wall or any tab's trim bound past its per-bound wall, disabled markers included, checked identically in GUI and CLI through the ONE implementation (`first_past_eof_wall_defect`, `marker_store_validate.h`; a file set is loadable or not, the same in both binaries; markers apply only to the audio they were authored against — swapping the audio happens outside the GUI). Opening a `.samples`/`.peaks` cache file prints a stderr refusal and exits (the launch-only loader has no blank state to fall back to) — never a silent redirect to a guessed owner. Loads intact and renders, normalized where ambiguous: equal/close marker times, dangling label refs, a pass inheriting from a label ref, any (or no) first marker, the empty file, equal or INVERTED trim bounds (RESET to that tab's full window at load, stderr line — always-set trim, 2026-07-30), and a trim bound under a map format (the map render silently ignores it).

What remains of the render boundary is tripwire-class: `build_warp_frame_map`'s `std::expected` errors — invalid metadata, past-EOF marker time (breach backstop, column-symmetric by ruling), sub-frame segment (kept: the engine validates strict ascent but NOT the >=1-frame gap — the one map defect that would render silently wrong), dangling label ref (kept: the engine never consumes refs — a breach would be raw UB, not a loud refusal), and non-positive tempo product (REACHABLE: the ruled async-stderr backstop for the sweep batches' per-cell computed tempo mutations, deliberately unbracketed; kept HERE for message vocabulary — the engine would only say "not strictly ascending", this site names the tempo). The engine-duplicated finite/vanish/divisor trio was removed 2026-07-17 — breaches land on the engine's own loud init validators. `resolve_warp_markers_for_render` returns a PLAIN vector (a total normalizer, infallible by design — only the partial-compiler builder keeps `std::expected`). Plus `build_phase_reset_source_frames`' past-EOF wall, and `validate_trim_frames` (`src/prepost/trimmer.h`), which stays the sole AUTHOR of the trim-validity vocabulary while its refusal now means "render untrimmed" at both orchestrators (GUI `do_render`, CLI), one stderr line, never a failed render. The engine's strict-ascent and cap tripwires are unchanged breach guards for hand-edited artifacts, unreachable from program-written input.


The design premise: the GUI assumes a non-adversarial user — gestures are never guarded mid-flight, and ambiguous states are RESOLVED BY THE RENDER (1.00 / no-trim, stderr lines), not reported, gated, or force-walked. Tab/Shift+Tab reaches every member of a mouse-unpickable MARKER group (exact-frame stacks and cross-column ties are legal at rest); trim bounds are not Tab stops — they are unselectable, and Home/End is their navigation. Text-editor commits refuse with the red-flash (the iter-bracket commit gates base_tempo plus either bound against the tempo bracket this way — the sweep's cells are bounded by the bracket endpoints, so a bracket whose cells could not all re-parse at promote refuses at its own input surface; a later tempo change under a live bracket is deliberately not re-gated, session-only state with the build refusal and strict promote parse as backstops, and a refused `'` load-in-place of a bad entry sidecar red-flashes the load editor — the standalone `load_render_entry_in_place` reads and validates every sidecar before mutating authoring and returns false untouched). Prompt text and options join with single spaces; GUI and stderr output never contain a double space (the WARPTEMPO_PROFILE instrumentation that carried the sole exception is removed).
