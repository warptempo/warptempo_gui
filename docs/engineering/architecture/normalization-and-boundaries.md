### Load-Lenient, Render-Normalizing Boundaries
Gestures move freely and NOTHING POPS, ever: markers and trim bounds may sit arbitrarily close, overlap exactly, and cross during gestures on both columns, and no commit opens a modal — the defect-resolution funnel is RETIRED (directive #11, architect 2026-07-15). Ambiguous authored states are NORMALIZED at the render/preview boundary instead of refused or force-resolved: every ambiguous tempo resolves to 1.00. The chokepoint is `resolve_warp_markers_for_render` (staged pipeline and output invariants at its header, `warp_frame_map_build.h`), which every render path AND the target-view recompute funnel through, so display and render cannot disagree: (1) filter to survivors (disabled + cascade), (2) collapse each EXACT-same-frame surviving group to ONE plain enabled 1.00 owner, no labels (a def dying in a collapse makes its refs dangling, normalized in turn — deterministic cascade), (3) silently seed a plain 1.00 owner at frame 0 when no survivor sits there — MANDATORY CORRECTNESS: `build_warp_frame_map` seeds {0,0} and attributes the opening segment to the first resolved marker wherever it sits, so a missing frame-0 SURVIVOR (disabled-at-0 included) would otherwise render silently wrong bytes; the seed is decided on the surviving list by explicit ruling and is silent (the documented default, not ambiguity), (4) materialize passes through the ref-OPAQUE inheritance walk — a surviving enabled label ref terminates the walk with the 1.00 fallback (a ref owns a duration equation, not a rate), (5) normalize label refs: dangling, or implied effective tempo outside the authored per-marker envelope [0.125, 8.0] (`kRefImpliedTempoMin/Max`, scale-free so hover mirrors it without seeing the settings scale) → a plain 1.00 owner at its own frame. Every normalization except the seed prints ONE stderr line per timestamp PER RESOLVE (no dedup or session state — a resting ambiguous store re-prints on each preview recompute, the intended signal). The hover surfaces (`marker_effective` / `compute_hover_popup_text`) share the walk and the envelope constants: a normalized ref reads `= 1.00 (undefined label)` / `= 1.00 (extreme label ratio)` (hard `=`, exact literal), a ref-hit pass reads `= 1.00` with no provenance (the ctrl+c copy notice left the popup text 2026-07-20; the copy behavior itself is unchanged). The GUI STORE stays the authored truth — coincident-group members still paint, hover, and Tab-pick individually; the collapse is render-domain (accepted display split, stderr the signal). NORMALIZATION-RED (2026-07-21, opus session): a marker that renders as the 1.00 fallback ALSO paints its FLAG red (kAccent fill + kAccentOutline ring) — a display cue alongside the stderr, revising the pure stderr-is-the-signal rule for the coincident case (an earlier attempt reddening the wave SEGMENT was reverted — a floating red span had no bound and read oddly, the marker flag is the bounded cue). The red set is computed SILENTLY GUI-side from the COMMITTED store (a memoized generation-keyed helper, `warp_red_flag_set_cached` / `phase_reset_red_flag_set_cached` in warp_frame_map_view; committed-store + generation memo = a red flag HOLDS through a marker drag and re-evaluates only at commit, mirroring the displayed-map wait): the ref/pass fallbacks via `marker_effective` (source_idx == -1 with a ref reason — UndefinedLabel/ExtremeRatio — OR the `from_ref` bit, so a PASS reddens only when it inherits from a ref, NOT when it inherits a real value from a synthetic prior — the frame-0 seed or a collapsed owner), and the exact-frame collapse via a same-frame count of 2+ effectively-enabled members reddening EVERY member (the overlapping stack reads as ONE red flag, matching the single stderr line). No frozen resolver out-param is needed (the 1730d99 out-param was reverted as redundant); the frozen touches here are TWO granted siblings on `MarkerEffective`, each a value the walk already computed and discarded: the `from_ref` bool (2026-07-21) and `owner_idx` (2026-07-22, 2aa5738 — the ref-opaque backward walk's terminal owner as a raw store index, -1 whenever no raw owning marker exists; sole consumer is the tempo drag's label-coupling guard). Phase resets get the SAME red on a coincident enabled collapse (a same-frame count on the phase-reset store — the symmetric sibling; no marker_effective analog, phase resets carrying no tempo/labels). Selection is NOT a color class and never masks red (2026-07-27, the kSelected/kSelectedOutline deletion: a selected red marker keeps its red pair, so the normalization cue always shows); the frame-0 seed is silent and unreddened; no new flag-cache fingerprint field (the red set only changes on a generation bump the flag cache already keys on). Phase reset column: exact-equal enabled resets collapse to one event inside `build_phase_reset_source_frames`, one stderr line per timestamp (positions are whole frames, so sub-frame spacing IS equality). `kFingerprintVersion` was bumped to 7 with this contract (extreme refs previously rendered their unclamped ratio). The marker stores are ALWAYS time-sorted at rest, ties legal with stable order; every time-mutating gesture routes through `reorder_markers_by_time` + `remap_marker_indices_after_reorder` (`app_state.h`). MARKER gesture walls are absolute — zero and total-1 for BOTH columns (warp structurally, phase reset by ruling: a reset in the last source frame has nothing to re-ground, and total-1 keeps every marker inside the playhead's [0, total-1] domain; a stored reset at exactly total is adversarial load-fatal); mouse drags compose the walls with the visible-strip clamp; nudges have no viewport gate, so the walls are exactly reachable by nudge. The playhead rests in [0, total-1] of its live view after any gesture (ruling spelled ONCE at `clamp_playhead_to_live_domain`, `app_state.h` — every playhead write funnels through it: `Viewport::move_playhead_to`, the gesture-side sync/pin sites, and the load/Ctrl+Tab/adopt live-ization routes; persisted playhead == total stays load-legal, runtime clamp owns it at first use). TRIM (ruling at the `TrimState` store, `app_state.h`): begin and end are authored named roles — no role swap ever — whole int64 source frames like marker times (persistence is exact integer text through `frame_format.h`). Both bounds wall at the shared [0, total-1] domain (the former exclusive end-at-total wall is retired); no partner walls, crossing free during gestures, but crossed/equal can no longer REST anywhere: every trim COMMIT (the `x` trim-to-region set, drag release) runs `auto_clear_crossed_trim` — a bound committed onto or across its partner (`end <= begin`, exact integer compare) destroys BOTH bounds, silently (the chips vanish) — with ONE route now refusing rather than feeding it: `x` REFUSES A DEGENERATE RESULT (2026-07-29, PLANNER-DECIDED PENDING ARCHITECT CONFIRMATION, the one interpretation in the ruling-2 arc — when the region's inverse-mapped, wall-clamped pair comes out `end <= begin`, `x` writes NOTHING at all and trim, region and selection all rest). It exists because deleting the coincident arm left a one-column TrimWindow region resting active, and `x` over it inverse-maps both stored endpoints to the SAME source frame, which the auto-clear above would read as crossed and destroy — silently, with trim having no undo. The refusal tests the pair `x` would WRITE, so it is provenance-blind by intent: a narrow FREE span over stretched audio whose endpoints inverse-map onto one source frame is refused too, retiring that pre-existing destruction route as well, and `x` can no longer reach the auto-clear's destructive arm at all (the crossed destruction stays reachable where the user AIMS it — the bound-set click and the drag release, where the chips visibly vanish as the signal) — and a persisted per-tab pair with `end <= begin` clears both of that tab's bounds at load with one stderr line (placed AFTER the adversarial past-EOF hard-fail, so a crossed pair containing a past-EOF bound still aborts identically in both products). A LONE bound (exactly one set — settings-editor/load-reachable) COMPLETES to its extreme at the render boundary (missing begin → 0, missing end → total; architect 2026-07-19) and renders its obvious window, matching the navigation semantics Home/End, the Space gate, and `compute_trim_samples`' per-side extremes always had — the store keeps the authored lone bound and lone remains gesture-inert (pair required). A set trim (any bound) also LOOPS the audition (architect 2026-07-19): the Space launch captures the loop verdict and window ONCE — like `end_sample`, mid-session follow/trim edits take effect at the next launch — and the audio callback wraps the read position from the window end back to the trim begin, a raw cut with clicks accepted by ruling (no crossfade/declick); the wrap is a ruled predictor resync event, detected main-thread via `GuiPlayback::loop_wrap_seq()` (a monotonic audio-thread counter — the clamped `cursor()` cannot reveal the backward jump), independent of follow mode (follow off just means no viewport tracking of the wrapped scanner); the click-keep-alive reseek preserves the session's captured verdict via `app.playback_loop_start_sample`. An unhonorable trim window that still reaches render renders UNTRIMMED with one stderr line — TWO reachable refusals: "trim end at or before trim begin" (reachable exactly via a lone END at frame 0 completing to (0, 0); set pairs can never rest crossed/equal) and a target span rounding below one output sample under a fast tempo (`plan_trim`'s refusals, fallbacks, not failures) — and the one downstream read that must mirror the completion-then-refusal outcome is the target-buffer playback anchor (`compute_buffer_start_frame_for`, which completes identically and re-derives both refusal verdicts in `validate_trim_frames`' check order, so a fallback buffer anchors 0 and its `fallback_reason` names the case at the reuse-rung diagnostics). Trim BOUNDS stay outside the selection system (architect 2026-07-18: never selected, never Tab stops, no Delete, no keyboard nudge), but the trim WINDOW joined the selection-highlight coupling by architect order (the lane click model, 2026-07-23): a plain chip-row click, both trim drags' motion/release, and the shift/ctrl chip-row bound sets all publish the highlight through `sync_region_to_trim_window`, which since the 2026-07-29 contortion ruling 2 has exactly TWO ARMS — both bounds set → the region takes the window's clamped active-domain extent, COINCIDENT MAPPED IMAGES INCLUDED (a window compressed onto ONE target frame rests ACTIVE at that one column: the old middle arm that cleared the highlight there is deleted, its sliver-rule and protect-the-pair justifications both spent, and the degenerate paint shape was already owned — no ground at zero width, `render_split_playhead`'s explicit one-column form, the same shape the group undo restore's all-coincident extent already rests at), so A FULL AUTHORED PAIR NOW DOES IMPLY AN ACTIVE TrimWindow REGION (the 2026-07-23 through 2026-07-28 rule that it did not is REVERSED); lone/none/dissolved → the region clears (the no-window rule) — and EVERY TrimWindow SETTER CLEARS THE SELECTION (architect 2026-07-29, ruling 2: the trim-bar click is the span-form sibling of the plain waveform click's deselect-all, "clicking trim means ready to move on"), so a TrimWindow region rests ONLY beside an EMPTY selection. THE SETTERS, grep-derived at the one helper that pairs the deselect with the publish (`deselect_and_sync_trim_window_highlight`): the plain chip-row click in all three arms (the read-only press's direct sync, the writable unclaimed-spot sync, and the deferred motionless completions), the ctrl / ctrl+shift bound-set click (one function, so one deselect), bare `x`, and the chip/bridge DRAG's live sync (both motion arms and the release). Each deselects PAST ITS OWN REFUSALS — a read-only bound set, a chip-row claim with no resting pair, degenerate geometry, and a drag event that moved no bound publish no highlight and so deselect nothing. THE NON-SETTERS keep the bare sync and never deselect: `Shift+X` (a trim CLEARER) and the settings editor's two trim maintainers; that is the whole list, the trim gestures' Esc-cancel re-syncs having died with the cancels themselves. Trim still never SELECTS (downward-only, architect 2026-07-23: selection → region → trim, nothing upward; `select_contained_in_span` is deleted) — it only ever EMPTIES the selection, which inverted the reason the sync takes a `Selection&`: its one surviving clear arm still carries the never-span-less collapse, but no SETTER can reach it (the selection is already empty), leaving `Shift+X` and the settings trim commit as that tail's live callers. The b44ad2e pre-gesture snapshots are GONE with every other cancel capture (contortion rulings 3+4, 2026-07-29 — pointer gestures have no cancel), so a chip drag's deselect RESTS exactly as `x`'s does; the playhead is still NEVER touched (the 2026-07-18 rule holds there); ctrl MOVES the BEGIN bound and ctrl+shift the END at the clicked column AND arms the single-bound drag on it (motion past the threshold drags it live; nothing is snapshotted — the click-set is committed the moment it is made, trim being history-less — and the drag's `orig_*` pair now holds the post-click-set values, which is what its rigid-pair delta and its release moved-bound test want), ADJUST-ONLY — a silent no-op without a resting full pair (the window is created by region→x; the settings editor stays the deliberate lone-bound route; authored_frame_at_column on the displayed basis, walls, the auto_clear_crossed_trim tail; the labwc co-display sighting was a lone bound's one-sided out-of-trim dim contrast misread as the highlight (that dim is itself retired since the 2026-07-26 opaque-recolor arc), the highlight/split suppression itself airtight by the R5 audit), read-only refusing the sets but keeping the navigation sync; `x`/`Shift+X`, the chip/bridge drags, the chip-row clicks, and Home/End are trim's whole interface. Any further trim-vs-marker time asymmetry needs architect approval. Warp marker zero is an ordinary marker — the default `0|1.00` seeded into a missing `.warpmarkers` file at source load — deletable, movable, disable-able (the render-time seed covers its absence). Label defs are deletable with live refs — the orphaned refs render as 1.00 with stderr lines; the text editor's red-flash guard remains the input-time surface (you cannot TYPE a dangling ref), and the flag editor's rename cascade applies only to non-empty new names. Rapid keyboard gestures COALESCE their undo granularity BY REPEAT IDENTITY (2026-07-29, contortion ruling 7 — replacing the wall-clock window): a HELD key's synthesized repeats collapse into ONE undo entry with the physical press that started the hold, so a single Ctrl+Z reverts the whole run. The FOUR eligible kinds are enumerated at `GestureKind` (undo.h) — the warp and phase-reset position nudges (bare Left/Right with a selection, in each column's home view), the TEMPO-IMAGE STEP (the same bare Left/Right in W+target, its own kind so a burst of image steps coalesces with itself and never with the position nudges), and tempo cent steps (bare Up/Down; no wheel route). THE MECHANISM: the platform stamps every synthesized repeat it delivers with `GuiInputState::synthesized_repeat` (set in exactly ONE place, `maybe_fire_repeat` — a platform-boundary fact like `codepoint`); the burst's PHYSICAL press pushes the pre-burst snapshot and stamps its kind (`Undo::record_gesture`); a synthesized repeat that commits SKIPS its push (`Undo::coalesce_gesture` — synthesized + same kind + non-empty stack, NO clock, NO counter) and routes the surviving per-press side effects through `Undo::note_coalesced_commit` (the hover-clear) and `Undo::refresh_coalesced_touched_live` (final-state identity hints — a later press in the burst can reorder members); the visible move, reorder/remap, dirty, and the target-view preview stay per-press. RAPID MANUAL TAPS ARE SEPARATELY UNDOABLE — the deliberate delta of the model, the more literal gesture boundary. COMMAND ADJACENCY SURVIVES STRUCTURALLY rather than numerically: the platform repeat contract's event-edge disarms (layer (1) at `maybe_fire_repeat`, now recorded there as LOAD-BEARING for undo correctness) kill a hold at any intervening pointer-button press, completed wheel emission, or key press, so no synthesized repeat can arrive after an intervening command — and the one route the disarms cannot see (state changing under an async worker publish flipping a refusal mid-hold, no command in between) is closed by the stamp-clear guard: every stack-top change outside the burst — all four `push_*` helpers AND the undo/redo restore's pop (`restore_history_entry`) — clears the recorded kind, so a stale kind can never coexist with a foreign stack top (the derivation lives at `coalesce_gesture`; `record_gesture` runs after the push at all four eligible routes, so intended merges are unaffected). DELETED with the window (the compositor's key-repeat delay ceases to participate in undo semantics — the whole "window drifted out of sync with the desktop's repeat delay" defect class dies): `kGestureCoalesceMs` and its compositor-delay derivation, the steady clock, `GestureCoalesce`, and `AppState::command_seq` with its three dispatch bumps (the counter's subsumption job — same selection / same tab / same history — now follows from the structural adjacency; it had itself replaced an earlier leaking multi-counter guard, and the replacement chain ends here). Accepted delta recorded at the gate: two same-kind bursts with NO command between them merge across the release gap when the second burst's physical press refuses (over-merge only — the surviving entry's snapshot predates both bursts, one Ctrl+Z reverts both). Trim (history-less, no undo) and mouse drags (already one commit at release) are ineligible; the render/preview path is unchanged (its kill-on-redispatch already coalesces the target-view previews).

The two-category boundary rule (architect-ruled, #11 form): a state the GUI lets the user COMMIT always LOADS and always RENDERS — normalized to 1.00 / no-trim where ambiguous, with stderr lines as the signal; a state the GUI can NEVER produce is ADVERSARIAL and hard-fails the load, stderr only, FIRST error only (no friendly listing — fixing one defect can create another, so one-shot completeness is futile, and adversarial input earns no user-friendliness). Load-fatal (adversarial): syntax errors, unopenable files, duplicate label definitions, DECREASING marker times, out-of-bracket or non-positive values, fractional/negative/malformed/non-finite frame positions (including the old timestamp format), hash lines that are not valid disabled markers (comment lines are not part of the authored grammar; legacy '#' passthrough survives only in the migration tool), sub-44100 sample rates, settings-schema violations (the whole-file readers above — unknown keys, duplicates, malformed or out-of-vocabulary values), a settings title whose composed render output path lands on the source file (`render_output_source_collision`, `render_output_naming.h` — refused at editor commit, at BOTH product loads, with the render worker as breach backstop), malformed WAV containers (a declared chunk size past EOF, a RIFF size contradicting the physical container — 8 + riff_size == file size required; the `0xffffffff` streamed-placeholder tolerances are REMOVED, such files hardfail — duplicate fmt/data chunks, a byte_rate contradicting sample_rate times block_align, a WAVE_FORMAT_EXTENSIBLE cbSize running past its own fmt chunk, and a zero-frame data chunk; the PCM24 writer refuses non-finite input as the outbound breach guard; probe failures print the owner diagnostic verbatim — the render worker included — with the convert-once hint appearing GUI-side only for `kUnknownAudioMagicError`), and PAST-EOF positions — any marker past its column wall or any tab's trim bound past its per-bound wall, disabled markers included, checked identically in GUI and CLI through the ONE implementation (`first_past_eof_wall_defect`, `marker_store_validate.h`; a file set is loadable or not, the same in both binaries; markers apply only to the audio they were authored against — swapping the audio happens outside the GUI). Opening a `.samples`/`.peaks` cache file prints a stderr refusal and exits (the launch-only loader has no blank state to fall back to) — never a silent redirect to a guessed owner. Loads intact and renders, normalized where ambiguous: equal/close marker times, dangling label refs, a pass inheriting from a label ref, any (or no) first marker, the empty file, equal or INVERTED trim bounds (cleared at load per tab, stderr line), and a trim bound under a map format (the map render silently ignores it).

What remains of the render boundary is tripwire-class: `build_warp_frame_map`'s `std::expected` errors — invalid metadata, past-EOF marker time (breach backstop, column-symmetric by ruling), sub-frame segment (kept: the engine validates strict ascent but NOT the >=1-frame gap — the one map defect that would render silently wrong), dangling label ref (kept: the engine never consumes refs — a breach would be raw UB, not a loud refusal), and non-positive tempo product (REACHABLE: the ruled async-stderr backstop for the sweep batches' per-cell computed tempo mutations, deliberately unbracketed; kept HERE for message vocabulary — the engine would only say "not strictly ascending", this site names the tempo). The engine-duplicated finite/vanish/divisor trio was removed 2026-07-17 — breaches land on the engine's own loud init validators. `resolve_warp_markers_for_render` returns a PLAIN vector (a total normalizer, infallible by design — only the partial-compiler builder keeps `std::expected`). Plus `build_phase_reset_source_frames`' past-EOF wall, and `validate_trim_frames` (`src/prepost/trimmer.h`), which stays the sole AUTHOR of the trim-validity vocabulary while its refusal now means "render untrimmed" at both orchestrators (GUI `do_render`, CLI), one stderr line, never a failed render. The engine's strict-ascent and cap tripwires are unchanged breach guards for hand-edited artifacts, unreachable from program-written input.


The design premise: the GUI assumes a non-adversarial user — gestures are never guarded mid-flight, and ambiguous states are RESOLVED BY THE RENDER (1.00 / no-trim, stderr lines), not reported, gated, or force-walked. Tab/Shift+Tab reaches every member of a mouse-unpickable MARKER group (exact-frame stacks and cross-column ties are legal at rest); trim bounds are not Tab stops — they are unselectable, and Home/End is their navigation. Text-editor commits refuse with the red-flash (the iter-bracket commit gates base_tempo plus either bound against the tempo bracket this way — the sweep's cells are bounded by the bracket endpoints, so a bracket whose cells could not all re-parse at promote refuses at its own input surface; a later tempo change under a live bracket is deliberately not re-gated, session-only state with the build refusal and strict promote parse as backstops, and a refused `'` adopt of a bad entry sidecar red-flashes the commit editor — the standalone `adopt_render_entry` reads and validates every sidecar before mutating authoring and returns false untouched). Prompt text and options join with single spaces; GUI and stderr output never contain a double space (the WARPTEMPO_PROFILE instrumentation that carried the sole exception is removed).
