# Input Conventions (modality, bare-e mouse key, type names, naming symmetry)

Moved verbatim from CLAUDE.md in the 2026-07-25 slim-down (project feature-complete). This file is now the authoritative home for this detail; CLAUDE.md carries only a digest and a pointer here. Keep it current with landed rulings.

### Modality is Bottom-Strip
Modal surfaces live on the bottom strip: the three bottom-strip editors — the settings editor, the bpm editor (top_flag_editor with Kind::BpmBracket), and the render-commit editor (`commit_editor`, Kind::RenderCommit, opened by bare `'` to adopt a `renders/` entry by name — the standalone `adopt_render_entry`, a running-render-guarded wholesale adopt that replaces the retired render-view Ctrl+Alt+C) — and every prompt. While a bottom-strip editor is open, only the editor's own keys plus bare Esc, Ctrl+S, and Ctrl+Q get through (`modal_editor_key_blocked`, the sibling of the read-only allowlist); the mouse works only inside the editor; playback stops when any modal surface opens and cannot restart until it closes. The TOP-strip flag editor (FlagPayload, iter grammar included) IS KEYBOARD-MODAL TOO (architect 2026-07-28, REVERSING the long-standing "deliberately not modal — commands punch through" ruling): it admits exactly the same set, so an unbound chord is now structurally inert rather than a command that discarded the edit on its way to running. It keeps red-flash-or-exit-without-commit. MODALITY HERE IS ABOUT CHORDS ONLY: the flag editor stays transparent to the POINTER (any left press elsewhere still closes it without committing) and to the WHEEL (zoom and pan are navigation, not commands), and opening one still does not stop playback — those two behaviors are held apart from the keyboard gate (`keyboard_modal_editor_active`) and each has ONE owner of its own: `modal_bottom_strip_editor_active` has exactly ONE caller, the `wheel_context` swallow, and since 2026-07-28 the playback stop is `GuiPlaybackLifecycle::stop_playback_for_modal_open` — called by every opening site (the three bottom-strip editors and the three prompts), refusal-gated as before (the stop fires only once an open's own guards have passed), with the decision table AND the flag editor's explicit exemption recorded at its declaration. A new modal surface therefore inherits the wheel swallow from the predicate and its playback answer from that owner — it grows neither by hand. One consequence, accepted: Ctrl+Z is not in the admitted set, so in-editor typing has NO UNDO — the identical gap the bottom-strip editors have always had. All four editors now share ONE contract function (`route_modal_editor_key`), the flag editor's bespoke flow and its cancel-then-fall-through tail deleted with the ruling. BPM mode is exactly its editor session: Esc abandons (exit_bpm_mode wipes), Enter dispatches (the sweep's success tail wipes and closes); `m` is not an exit (just a typed char while the editor is open); mode-without-editor is unreachable. The honest invariant stands: the GUI never writes a LOAD-invalid state — every committable state is load-legal by construction, and [s]ave always writes a loadable (and now always-renderable) file. (All program-authored GUI/terminal text is ALL-LOWERCASE by ruling 2026-07-17 — prompts, keycap labels, engine pass lines, diagnostics; data/identifier strings, settings value vocabulary (S/T, W/P, A/B), and user content keep their case.)

### Bare `e` is the Left Mouse Button
`kLeftClickKey` (gui_input.h, = `GuiKeys::E`; the single rebind point — hardcoded by ruling 2026-07-17 mirroring the architect's feh bindings; a configurable settings-key design and a q/backtick round were considered and REJECTED) is translated into BTN_LEFT at the PLATFORM boundary (`platform_wayland.cpp`), not in on_key: press = button down at the live pointer position, hold = button held (so `e`+motion drags and Ctrl/Alt compose), release = button up. Delivery follows the logical edge model — logical left is `pointer_left_held_ || synth_left_held_`, press on the 0→1 edge, release on the 1→0 edge (the evdev duplicate-BTN_LEFT model) — so physical and synthesized sources never double-deliver, and `current_mods()` ORs both into `primary_button_held`. Downstream the key IS the mouse and inherits every mouse gate (read-only tabs, drag gates, prompt/editor modality). ONE exception, decided at PRESS time: while a text editor is open (the `any_text_editor_active` probe — all three text editors, the FlagPayload flag editor included — that editor is KEYBOARD-modal since 2026-07-28, but modality is CHORDS ONLY and this key IS the mouse, so the probe is unchanged) the key is a normal character with normal repeat arming. Any modifier state rides along to the button, exactly as for a physical BTN_LEFT device. As the button it is swallowed as a key event entirely (no repeat — a held button must not re-press) and acts only while `pointer_focused_`. The release is NEVER gated (not by probe, shift, or focus — it is keycode-owned) and is also synthesized at keyboard leave and keyboard-capability loss, so a held button cannot orphan. Because e-chords can never reach dispatch, the miscellaneous render moved off Ctrl+Alt+E to Ctrl+Alt+Shift+R.

The former `kCtrlModKey` (bare `2` synthesizing Ctrl STATE) was REMOVED 2026-07-17 in the gesture pivot — bare `2` is an ordinary, currently unbound key, and `current_mods()` reads the real `mod_ctrl_` alone. Bare `e` therefore never reaches the key dispatch outside editors — do not bind it.


### Type Names
Marker and related GUI types carry the `Gui` prefix (`GuiWarpMarker`, `GuiPhaseResetMarker`, `GuiAudio`, `GuiPlayback`, etc.). New marker-side types follow the same convention.

### Warp / Phase Reset Naming Symmetry
Warp and phase reset are co-equal axes, and every pipeline surface names them as parallel columns. The artifact pair is `.warpframemap`, `.phaseresetframemap` (MIDI support is removed). Extensions concatenate without separators; identifiers underscore the same concepts (`warp_frame_map`, `phase_reset_frame_map`). "Phase reset" is one concept token and is never shortened to "reset" in names. New pipeline surfaces must ship both columns, or record the asymmetry in a comment at the site. Existing recorded asymmetries: scale is warp-only, the resolver cascade (`resolve_warp_markers_for_render`) is warp-only, the trimmer's window restriction keeps a connected map (out-of-window breakpoints drop and the seed/closing anchors take their place) versus range-filters point events away (phase reset column; recorded at `plan_trim`), the phase reset derivation (`derive_phase_reset_frame_map`) has no warp sibling (the warp frame map is already the engine's input domain; a phase reset position crosses to the deliverable target domain only for the render-end participation verdict, then shifts by the constant `N/2` into the engine query domain), the phase reset overlay (a paint-only, phase-reset-only surface — painted in target view, a target/output-domain display where a uniform window-origin shift preserves the constant target-time span, never source view; recorded at `paint_phase_reset_overlay_ring`; the overlay shows for a single focused reset only — suppressed while the selection has 2+ members or region.active, the span-state suppression), the frame-0 seed and the label-ref/pass normalizations being warp-only in the resolver (phase resets carry no tempo, labels, or inheritance — their whole normalization is the exact-equal collapse), and trim living outside the selection system (bounds unselectable, no Tab stops, no Delete/nudge — markers select; the former per-bound wall split is RETIRED, all authored positions sharing the [0, total-1] domain). The engine validators are fully symmetric per column; the map's two columns versus the reset list's one is arity, not asymmetry. The GUI pair vocabulary is `warp_X` / `phase_reset_X` (`warp_markers` / `phase_resets`, `warp_dirty` / `phase_reset_dirty`); warp is never the unmarked default.


### Strict Modifier Validation
STRICT MODIFIER VALIDATION (architect 2026-07-28, project-wide): a modifier combination with no explicit binding is a NO-OP, uniformly. Every predicate that used to accept a key "under any modifiers" was tightened — Space is bare-exact at its one shared owner (`is_play_pause_key`, read by both the dispatch and the read-only allowlist), Escape is bare-exact at ALL of its readers — re-derived 2026-07-29 after contortion ruling 5 deleted the selection/region ladder, leaving the prompt mapper, the editor-text-drag escape hatch, the drag-modal gate's swallow, `handle_escape_cancels`, the allowlist, and the editor classifier (the pointer gestures' Esc hatch went with their cancels, rulings 3+4), the editors' session keys (Escape / Return / KpEnter) are bare-exact, the editors' clipboard chords (A/C/X/V) are CTRL-exact, and the bottom-strip prompt is CASE-SENSITIVE — its letter, Delete, and Escape responses all match bare only, `!shift` included, because the platform case-folds letters and delivers the unshifted key with `mods.shift` set. THREE PREDICATE FAMILIES ARE DELIBERATELY NOT TIGHTENED because the modifier is a REAL BINDING there rather than laxity: `is_tab_cycle` (Shift+Tab is reverse cycle), Ctrl+Z (Shift selects redo), and the editors' MOTION arm, which admits its six keys under ctrl and shift in every combination but NEVER alt (architect 2026-07-28, the last lax predicate found). The line is drawn at alt and NOT at exactness, deliberately: ctrl and shift carry real meaning on all six keys — Ctrl+Left is word motion, Ctrl+BackSpace is word erase, Shift extends the selection — and they degrade to the plain gesture where they add nothing, exactly as an ordinary one-line field does (Ctrl+Home still goes to the start, Shift+BackSpace still backspaces), so making them exact would BREAK them. Alt binds nothing anywhere in the family, and admitting it is what let Alt+Left move the caret and Ctrl+Alt+BackSpace erase a WORD inside a surface that had just been declared inert to unlisted chords. Printable insertion likewise keeps shift (capitals) and excludes ctrl and alt.

SUPER IS DROPPED AT THE PLATFORM BOUNDARY (architect 2026-07-30 — "i use super in labwc config so it's not used in GUI"). The strict-validation rule above was FALSE for Super for its first two days: the modifier mask never modelled LOGO, so every bare-exact predicate read three bools, a held Super left `mods == {false,false,false}`, and Super+Escape reached the editors' cancel, Super+Return their commit (labwc grabs many Super chords, but Escape/Return/Space/Delete/the arrows/Home/End are ungrabbed and reach the client). The fix is the boundary drop, not a fourth bool in every predicate: the platform tracks `mod_super_` (XKB LOGO, effective) and `deliver_key` — the single shared delivery path for physical presses AND synthesized repeats — delivers nothing while it is held; a press arriving under Super also arms no repeat (its burst would otherwise deliver post-release carrying the repeat bit, merging into an older undo entry from a press the app never saw); the bit resets on keyboard-leave and seat-capability loss so a labwc-grabbed chord cannot latch it. Key releases stay platform-internal (never gated — a skipped release would orphan a synthesized-left hold), pointer events are untouched, and Super+`e` still synthesizes the left button (bare `e` IS the mouse at this boundary). The authoritative comment is at `deliver_key` (platform_wayland.cpp). So "an unbound modifier combination is a no-op everywhere" is now true BY CONSTRUCTION for the one modifier this program never binds.

### Why the Editors Need No Stray-Modifier Class
A key that wears a stray modifier on a shape the editor owns (Ctrl+Escape, Ctrl+Enter, Ctrl+Shift+V, Ctrl+Alt+A) is simply NotEditorKey like any other unbound chord, and drops at the keyboard-modal gate before anything can act on it. It was not always this simple: while the flag editor was non-modal its NotConsumed tail CANCELLED the in-progress edit on the way to global dispatch, so "unbound" and "not ours" could not be allowed to look alike — a `KeyClass::StrayModifierKey` named the first and claimed it inert. THE MODALITY RULING DELETED THAT MACHINERY (2026-07-28, hours after it landed): with the tail gone both classes end in nothing happening, the only residual difference being one wasted repaint of unchanged pixels, so the enumerator was removed and the classifier returned to its plain form with the two arms simply modifier-exact (bare for the session keys, ctrl-exact for the chords). RECORDED BECAUSE THE REASONING GENERALIZES: a destructive fall-through is what forces a codebase to distinguish "unbound" from "unowned"; remove the destruction and the distinction stops paying rent. Prefer removing the surface to maintaining the class that guards it.

### The Plain/Augmented Convention is Retired
THE PLAIN-VERSUS-AUGMENTED MODIFIER CONVENTION IS DEAD (architect 2026-07-28). It survived in exactly one place — bare `s` dropped a plain marker while Alt+S dropped the augmented one, in both columns, mirrored by the empty flag/triangle-lane double-click's plain/shift split. The AUGMENTED form is now the only form on both surfaces: bare `s` and the bare lane double-click drop the copy-previous owner in W and the lead-in reset in P, because the augmented drop is the render-neutral one in the ordinary case (it splits a section without changing the map, where a plain 1.00 drop mid-warp audibly changes the section it lands in). TWO RULED EXCEPTIONS to that neutrality, both architect-confirmed 2026-07-28 as non-problems rather than defects: a drop onto an ALREADY-OCCUPIED frame creates a 2+-survivor exact-frame group that the resolver replaces with one synthetic 1.00 owner (`find_immediate_prior` searches strictly before the drop frame, and `drop_marker` deliberately permits the coincidence) — accepted because the collapse is NORMALIZATION-VISIBLE, the affected markers turning red at once, which is exactly what the red flag is for; and a drop inside a LABEL DEFINITION's section shortens the definition, whose cached target duration every reference reproduces — accepted as an understood property of definitions, a definition's span being its meaning and because the lead-in drop's `−N/2` is the exact inverse of Space's `+N/2` audition. A shift press on that lane now claims nothing at all. There is no surviving bare/modified pairing where the modifier selects a VARIANT of the same gesture.
