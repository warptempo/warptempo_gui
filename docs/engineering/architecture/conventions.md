# Input Conventions (modality, bare-e mouse key, type names, naming symmetry)

Moved verbatim from CLAUDE.md in the 2026-07-25 slim-down (project feature-complete). This file is now the authoritative home for this detail; CLAUDE.md carries only a digest and a pointer here. Keep it current with landed rulings.

### Modality is Bottom-Strip
Modal surfaces live on the bottom strip: the three bottom-strip editors — the settings editor, the bpm editor (top_flag_editor with Kind::BpmBracket), and the render-commit editor (`commit_editor`, Kind::RenderCommit, opened by bare `'` to adopt a `renders/` entry by name — the standalone `adopt_render_entry`, a running-render-guarded wholesale adopt that replaces the retired render-view Ctrl+Alt+C) — and every prompt. While a bottom-strip editor is open, only the editor's own keys plus Esc, Ctrl+S, and Ctrl+Q get through (`modal_editor_key_blocked`, the sibling of the read-only allowlist); the mouse works only inside the editor; playback stops when any modal surface opens and cannot restart until it closes. The TOP-strip flag editor (FlagPayload, iter grammar included) is deliberately NOT modal — red-flash-or-exit-without-commit, commands punch through. BPM mode is exactly its editor session: Esc abandons (exit_bpm_mode wipes), Enter dispatches (the sweep's success tail wipes and closes); `m` is not an exit (just a typed char while the editor is open); mode-without-editor is unreachable. The honest invariant stands: the GUI never writes a LOAD-invalid state — every committable state is load-legal by construction, and [s]ave always writes a loadable (and now always-renderable) file. (All program-authored GUI/terminal text is ALL-LOWERCASE by ruling 2026-07-17 — prompts, keycap labels, engine pass lines, diagnostics; data/identifier strings, settings value vocabulary (S/T, W/P, A/B), and user content keep their case.)

### Bare `e` is the Left Mouse Button
`kLeftClickKey` (gui_input.h, = `GuiKeys::E`; the single rebind point — hardcoded by ruling 2026-07-17 mirroring the architect's feh bindings; a configurable settings-key design and a q/backtick round were considered and REJECTED) is translated into BTN_LEFT at the PLATFORM boundary (`platform_wayland.cpp`), not in on_key: press = button down at the live pointer position, hold = button held (so `e`+motion drags and Ctrl/Alt compose), release = button up. Delivery follows the logical edge model — logical left is `pointer_left_held_ || synth_left_held_`, press on the 0→1 edge, release on the 1→0 edge (the evdev duplicate-BTN_LEFT model) — so physical and synthesized sources never double-deliver, and `current_mods()` ORs both into `primary_button_held`. Downstream the key IS the mouse and inherits every mouse gate (read-only tabs, drag gates, prompt/editor modality). ONE exception, decided at PRESS time: while a text editor is open (the `any_text_editor_active` probe — all three text editors, the non-modal FlagPayload flag editor included) the key is a normal character with normal repeat arming. Any modifier state rides along to the button, exactly as for a physical BTN_LEFT device. As the button it is swallowed as a key event entirely (no repeat — a held button must not re-press) and acts only while `pointer_focused_`. The release is NEVER gated (not by probe, shift, or focus — it is keycode-owned) and is also synthesized at keyboard leave and keyboard-capability loss, so a held button cannot orphan. Because e-chords can never reach dispatch, the miscellaneous render moved off Ctrl+Alt+E to Ctrl+Alt+Shift+R.

The former `kCtrlModKey` (bare `2` synthesizing Ctrl STATE) was REMOVED 2026-07-17 in the gesture pivot — bare `2` is an ordinary, currently unbound key, and `current_mods()` reads the real `mod_ctrl_` alone. Bare `e` therefore never reaches the key dispatch outside editors — do not bind it.


### Type Names
Marker and related GUI types carry the `Gui` prefix (`GuiWarpMarker`, `GuiPhaseResetMarker`, `GuiAudio`, `GuiPlayback`, etc.). New marker-side types follow the same convention.

### Warp / Phase Reset Naming Symmetry
Warp and phase reset are co-equal axes, and every pipeline surface names them as parallel columns. The artifact pair is `.warpframemap`, `.phaseresetframemap` (MIDI support is removed). Extensions concatenate without separators; identifiers underscore the same concepts (`warp_frame_map`, `phase_reset_frame_map`). "Phase reset" is one concept token and is never shortened to "reset" in names. New pipeline surfaces must ship both columns, or record the asymmetry in a comment at the site. Existing recorded asymmetries: scale is warp-only, the resolver cascade (`resolve_warp_markers_for_render`) is warp-only, the trimmer's window restriction keeps a connected map (out-of-window breakpoints drop and the seed/closing anchors take their place) versus range-filters point events away (phase reset column; recorded at `plan_trim`), the phase reset derivation (`derive_phase_reset_frame_map`) has no warp sibling (the warp frame map is already the engine's input domain; a phase reset position crosses to the deliverable target domain only for the render-end participation verdict, then shifts by the constant `N/2` into the engine query domain), the phase reset overlay (a paint-only, phase-reset-only surface — painted in target view, a target/output-domain display where a uniform window-origin shift preserves the constant target-time span, never source view; recorded at `paint_phase_reset_overlay`; the overlay shows for a single focused reset only — suppressed while the selection has 2+ members or region.active, the R7 span-state rule), the frame-0 seed and the label-ref/pass normalizations being warp-only in the resolver (phase resets carry no tempo, labels, or inheritance — their whole normalization is the exact-equal collapse), and trim living outside the selection system (bounds unselectable, no Tab stops, no Delete/nudge — markers select; the former per-bound wall split is RETIRED, all authored positions sharing the [0, total-1] domain). The engine validators are fully symmetric per column; the map's two columns versus the reset list's one is arity, not asymmetry. The GUI pair vocabulary is `warp_X` / `phase_reset_X` (`warp_markers` / `phase_resets`, `warp_dirty` / `phase_reset_dirty`); warp is never the unmarked default.
