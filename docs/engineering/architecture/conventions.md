### Modality is the Modal Dialog
Modal surfaces are REAL POPUP DIALOGS since 2026-08-12 (architect: "we should institute real modals" — kdenlive's own dialog model achieved IN-WINDOW: no new Wayland surface, ONE centered box painted by the one renderer over an inert window, chrome sampled off modal_popup.png — the design record, the sampled constants and the box anatomy are kdenlive-redesign.md's dialog section; "Modal surfaces live on the bottom strip" is REPEALED — the prompts and the four editors lived on row 9's status lane from row 7 until this arc, and that lane keeps only its non-modal jobs). A PROMPT is its message line plus one REAL BUTTON per response, right-aligned, wearing the response's plain word ("Save" / "Discard" / "Cancel" / "Retry" / "Yes", "OK" on the dismiss-only error notice — the bracket-accelerator labels retired with the row; PromptState owns the label rule) at the toolbar row's button size (the 32px box — the dialog's OWN constants since the 2026-08-12 relayout deleted that row, kModalBtnBoxPx, paint_handler.cpp) in the icon row's face colors (the architect's explicit mix), NO button wearing the crop's highlighted default face — this prompt system has no Enter answer, so a default would be an invention (recorded at PromptState). AN EDITOR dialog is its prefix as the LABEL, the buffer in a DARK INSET FIELD (editor.png's look — the existing text_editor machinery whole: selection, caret, byte-identical editing; the invalid red flash RECOLORS THE FIELD in the marker-flag red pair), plus OK + Cancel buttons dispatching the session's own Enter and Esc through the one modal key route — button-is-its-chord. The TOP-STRIP FLAG EDITOR IS DELIBERATELY NOT A DIALOG: it is positional, editing the marker where it stands, and stays the pointer-transparent unrolled flag. The FOUR dialog editors — the settings editor, the bpm editor (top_flag_editor with Kind::BpmBracket), the load editor (`load_editor`, Kind::LoadInPlace, opened by bare `'` to load a `renders/` entry in place by name — the standalone `load_render_entry_in_place`, a running-render-guarded wholesale load-in-place that replaces the retired render-view Ctrl+Alt+C), and, since 2026-08-07, the COMMIT-TITLE editor (`commit_title_editor`, Kind::CommitTitle, opened by Ctrl+S while the `h` history view stands (Ctrl+Alt+R until 2026-08-08, when the architect moved the Save-and-Commit act onto the SAVE button's chord — the act runs the ordinary save as its first step; github-recheck.md owns the move), prefilled with the checkpoint's default `Update <id>` message and committing the Save-and-Commit act under whatever it holds — it REPLACED that act's confirmation prompt, so the prompt count went down as the editor count went up; github-recheck.md owns it) — and every prompt. While a dialog editor is open, only the editor's own keys plus bare Esc, Ctrl+S, and Ctrl+Q get through (`modal_editor_key_blocked`, the sibling of the read-only allowlist — the keyboard contract is BYTE-IDENTICAL across the move to the dialog); the pointer meets THE VEIL: the window behind the box is FULLY INERT — every press, motion and wheel outside the box is consumed (no dim layer: the palette is fully opaque by ruling and kdenlive's own parent window stays undimmed, so inertness is behavioral), the box's own pointer surfaces being the editor's FIELD (click-to-caret and the F2.1 text drag, through the painter-published geometry) and its BUTTONS, and the cursor is the Arrow over veil, box and buttons alike. THE OLD BOTTOM-STRIP POINTER MODEL IS SUPERSEDED BY THE VEIL, recorded loudly: a click outside the dialog CONSUMES and the dialog closes only by its own buttons and keys (the architect's words: "once I've done that pop-up modal, I can't do anything else in the window behind it") — WITH ONE DERIVED EXCEPTION since 2026-08-11, THE MODAL-TRAP FIX (architect, from the road: an accidentally opened settings editor on GLASS, with no physical keyboard, was an EXIT-LESS STATE — the Quit button did nothing): a plain left press on a roster button whose chord the editors' modal contract ADMITS AS A COMMAND dispatches through the ordinary one dispatch body — membership DERIVED from the admission (`modal_editor_admits_command_chord`, input_pointer.cpp, the contract's Esc/Ctrl+S/Ctrl+Q command tail restated for the pointer; today that resolves to QUIT and SAVE), never hand-listed, so the two buttons are their chords exactly where the chords are admitted (Ctrl+S saves with the editor open, Ctrl+Q runs the teardown and the close route) and every other press stays swallowed. The two menu ANCHORS carry no chord, so no press can open a popup under an editor and the popup/editor structural exclusion stands; the pointer-transparent flag editor never blocked these presses and needed nothing. Faces are untouched: the modal gates stay deliberately absent from `redesign_button_enabled` (a modal greying the chrome would be a fourth face nobody asked for), so the admitted pair already wears the enabled face — face and press agree where the press acts. Playback stops when any modal surface opens and cannot restart until it closes. The TOP-strip flag editor (FlagPayload, iter grammar included) IS KEYBOARD-MODAL TOO (architect 2026-07-28, REVERSING the long-standing "deliberately not modal — commands punch through" ruling): it admits exactly the same set, so an unbound chord is now structurally inert rather than a command that discarded the edit on its way to running. It keeps red-flash-or-exit-without-commit. MODALITY HERE IS ABOUT CHORDS ONLY: the flag editor stays transparent to the POINTER (any left press elsewhere still closes it without committing) and to the WHEEL (zoom and pan are navigation, not commands), and opening one still does not stop playback — those two behaviors are held apart from the keyboard gate (`keyboard_modal_editor_active`) and each has one owner of its own: `modal_dialog_editor_active` (RENAMED from modal_bottom_strip_editor_active with the move — the membership, these exact four editors, is unchanged; SEVEN callers since the dialog arc — the `wheel_context` swallow, the cursor map's blanket Arrow, the modal-trap block above, the dialog button claim, the dialog-hover motion branch, the roster hover walk's veil term, and the dialog painter's fork by proxy; the authoritative roster is its declaration's, input_handler.h), and since 2026-07-28 the playback stop is `GuiPlaybackLifecycle::stop_playback_for_modal_open` — called by every opening site (the four dialog editors and the three prompts — the commit-title editor's call is a structural no-op, the history view being silent by ruling, and it is there because the rule is the modal's rather than the surface's), refusal-gated as before (the stop fires only once an open's own guards have passed), with the decision table AND the flag editor's explicit exemption recorded at its declaration. The honest invariant stands: the GUI never writes a LOAD-invalid state — every committable state is load-legal by construction, and the close prompt's Save answer always writes a loadable (and now always-renderable) file. (THE CASE RULE IS NOW ONE, PROPER CAPITALIZATION EVERYWHERE: the 2026-08-01 split — GUI-facing proper, terminal all-lowercase pending a dedicated pass — CLOSED 2026-08-02 when THE TERMINAL CAPITALIZATION PASS LANDED, the pre-announced wide frozen touch recorded per file "(architect approval 2026-08-02)". ### Text is UTF-8 in Free Text, ASCII in Grammars
Architect-ruled 2026-08-02, retiring the "non-ASCII is unsupported" project line as a fossil of the deleted cairo monospace path — HarfBuzz on Liberation Sans renders Latin-script UTF-8 correctly today, so the restriction had outlived its cause. THE SCOPE IS TWO-SIDED. FREE TEXT takes UTF-8 verbatim: the five editors' buffers (the commit title among them since 2026-08-07 — a commit message is free text, and git carries UTF-8), the free-text settings values (`title`, `bpm`, `notes`, `url`, `cover`, `audio_player`), and the whole load/display/edit/recall/save round trip, which is byte-identical end to end (the old `autocomplete_value` recall-strips-non-ASCII exception is CLOSED, since the filter that caused it is the one that relaxed). STRUCTURAL GRAMMARS STAY ASCII, unrelaxed and unquestioned: marker labels (`is_valid_label_format`'s ranges, which also enforce lowercase), every numeric spelling, the settings keys and value vocabularies, the canonical-line payload grammar. Marker FLAG TEXT is therefore ASCII by construction — nothing composed into a flag box comes from a free-text field — which is what lets `cap_marker_label` walk it by byte (render.h, kMarkerLabelGlyphBudget). Render-entry identifiers are FILESYSTEM PATHS, bytes rather than text, and are untouched by the ruling.

TWO EXCLUSIONS, both accepted rather than deferred: NO FONT FALLBACK (one face; an uncovered codepoint draws .notdef — the one-face rule is the model, and Pango stays out of the tree), and NO BIDI OR COMPLEX SHAPING (single-direction LTR runs only). A third belongs with them: GRAPHEME CLUSTERS ARE OUT OF SCOPE — the editors move by CODEPOINT, so a combining mark carets and deletes on its own.

THE MECHANISM IS THREE PARTS, each with one owner. (a) The INCOMING FILTER is `text_editor::replace_selection` alone: printable ASCII and well-formed multi-byte UTF-8 pass; ASCII control bytes and malformed sequences (a lone continuation byte, an overlong form, a truncated tail, a surrogate) drop one byte at a time so the good text around them survives. Its malformed arm HAS A LIVE PRODUCER since the system clipboard landed the same day: a Ctrl+V hands another application's bytes to this filter unexamined — the platform reads the pipe and passes the payload through whole, deliberately, because one incoming filter is the design and a second one at the platform boundary would be the duplicate predicate the topology forbids. (b) The TYPED PATH needs no boundary fix: `xkb_state_key_get_utf32` already hands over a full codepoint, so a compose or dead-key sequence arrives whole and the editor UTF-8 encodes it into one insertion. (c) EDITOR INTERNALS index by BYTE but MOVE BY CODEPOINT — Left/Right, BackSpace/Delete, the Ctrl word walks (bytes ≥ 0x80 classify as word, which makes the byte walks boundary-safe without a decoder), the double-click run selector, and the click-to-byte search, which cannot return a mid-codepoint index because `byte_offsets_px` gives a cluster's interior bytes its START pen and the nearest-boundary tie keeps the lower index. `cursor_pos` and `selection_anchor` are codepoint boundaries by construction; the per-Kind caps are BYTE caps. The contract is authoritative at the head of `text_editor.h`.

A hand-edited file carrying malformed bytes still LOADS VERBATIM — no new refusal, no migration; those bytes shape as .notdef or garbage, which the architect accepted.

### The Clipboard is the System Clipboard
Architect-ordered 2026-08-02, restoring the Wayland clipboard half of what `e0c988c` removed as collateral when the in-session file load was killed. Drag-and-drop and the file load STAY DEAD — nothing of them came back, and the `wl_data_device` listener's four DnD slots are inert stubs that exist only because libwayland aborts on a NULL slot. Primary selection (middle-click paste) is out of scope: `zwp_primary_selection` is not bound.

THE REACH IS EXACTLY WHAT IT ALREADY WAS — no new chord, no new binding, no new gate. `Ctrl+C` / `Ctrl+X` / `Ctrl+V` inside the editors (ctrl-exact, as the strict-modifier rule below has them, and already admitted editor keys) and the readout's `Ctrl+C` are the whole vocabulary; the ruling moved only where the bytes go and come from. Copy and cut publish the selected text straight to the compositor, and the readout copy does likewise. THE PAYLOAD HAS ONE REPRESENTATION, the platform's `clipboard_send_text_` — which must exist anyway to service the compositor's later `send` event, and which owns the self-paste short circuit. `AppState::text_clipboard`, the session-only string the editors used before this, is DELETED: every reader it ever had was a pass-through handing it back to `clipboard_set_text`, so a second copy bought nothing but drift risk, and a copy site now composes its string, hands it over, and keeps none of it. (The phase-reset propagate clipboard is a different concept and is untouched.) A paste asks the platform: our own payload while we still hold the selection (the self-paste short circuit — reading our own selection back through the pipe would deadlock the single-threaded loop against itself), another application's text once somebody else has taken it. AN EMPTY ANSWER IS A CONSUMED NO-OP — no offer, no acceptable text mime, or a failed read all mean there is nothing to paste, and pasting nothing must not delete the selection instead. That closed a real pre-arc edge as a side effect: `Ctrl+V` with nothing ever copied used to delete the selection.

THE PROTOCOL SIDE. `wl_data_device_manager` is CORE protocol, so it needed no library, no pkg-config entry and no generated stub; it is a REQUIRED global under the `xdg-decoration` precedent (see validation_topology.md's platform-startup row), with v2 as the bind floor and v3 the cap. The accepted mimes are `text/plain;charset=utf-8` preferred and bare `text/plain` as fallback, compared case-insensitively because the charset parameter is (GTK and Qt applications disagree on the spelling), and the EXACT offered token is what `receive` is handed back. The read is synchronous — a keyboard-triggered short string can afford it — deadline-bounded at one second and capped at 1 MiB, with every failure returning nothing rather than a partial paste. `set_selection` rides the serial of the triggering key event, cached at `on_keyboard_key`. The lifetime rules (an announcement is not a claim; one teardown, two exits; NULL is a real selection event; ownership is a bit, not an object) are authoritative in the clipboard section header of `platform_wayland.cpp`.


### Bare `e` is the Left Mouse Button
`kLeftClickKey` (gui_input.h, = `GuiKeys::E`; the single rebind point — hardcoded by ruling 2026-07-17 mirroring the architect's feh bindings; a configurable settings-key design and a q/backtick round were considered and REJECTED) is translated into BTN_LEFT at the PLATFORM boundary (`platform_wayland.cpp`), not in on_key: press = button down at the live pointer position, hold = button held (so `e`+motion drags and Ctrl/Alt compose), release = button up. Delivery follows the logical edge model — logical left is `pointer_left_held_ || synth_left_held_ || touch_left_held_` (the third source joined 2026-08-11 with the touch translation — `touch.md` owns that arc; this precedent is its stated model), press on the 0→1 edge, release on the 1→0 edge (the evdev model for devices sharing BTN_LEFT) — so the physical, synthesized and touch sources never double-deliver, and `current_mods()` ORs all three into `primary_button_held`. Downstream the key IS the mouse and inherits every mouse gate (read-only tabs, drag gates, prompt/editor modality). ONE exception, decided at PRESS time: while a text editor is open (the `any_text_editor_active` probe — all three text editors, the FlagPayload flag editor included — that editor is KEYBOARD-modal since 2026-07-28, but modality is CHORDS ONLY and this key IS the mouse, so the probe is unchanged) the key is a normal character with normal repeat arming. Any modifier state rides along to the button, exactly as for a physical BTN_LEFT device. As the button it is swallowed as a key event entirely (no repeat — a held button must not re-press) and acts only while `pointer_focused_`. The release is NEVER gated (not by probe, shift, or focus — it is keycode-owned) and is also synthesized at keyboard leave and keyboard-capability loss, so a held button cannot orphan — AND AT POINTER-CAPABILITY LOSS since 2026-08-08 (codex): that edge ends the logical hold in BOTH sources, the synthesized one included, because the gesture it arms is a POINTER gesture in every other respect and a hold left standing would be inherited by the next stream (a capability return synthesizes an enter motion, whose first event would read the old hold as down and resume the gesture at the new coordinates with no click in between). Ending it is a commit, not a cancel, at the last known coordinates, and it zeroes the owning keycode so the eventual `e` keyup matches nothing; each hard edge stands alone and neither relies on the other having fired. Because e-chords can never reach dispatch, the miscellaneous render moved off Ctrl+Alt+E to Ctrl+Alt+Shift+R.

The former `kCtrlModKey` (bare `2` synthesizing Ctrl STATE) was REMOVED 2026-07-17 in the gesture pivot — bare `2` returned to the ordinary key space (and has since become the T+P absolute view selector, 2026-08-01), and `current_mods()` reads the real `mod_ctrl_` alone. Bare `e` therefore never reaches the key dispatch outside editors — do not bind it.


### Type Names
Marker and related GUI types carry the `Gui` prefix (`GuiWarpMarker`, `GuiPhaseResetMarker`, `GuiAudio`, `GuiPlayback`, etc.). New marker-side types follow the same convention.

### Warp / Phase Reset Naming Symmetry
Warp and phase reset are co-equal axes, and every pipeline surface names them as parallel columns. The artifact pair is `.warpframemap`, `.phaseresetframemap` (MIDI support is removed). Extensions concatenate without separators; identifiers underscore the same concepts (`warp_frame_map`, `phase_reset_frame_map`). "Phase reset" is one concept token and is never shortened to "reset" in names. New pipeline surfaces must ship both columns, or record the asymmetry in a comment at the site. Existing recorded asymmetries: scale is warp-only, the resolver cascade (`resolve_warp_markers_for_render`) is warp-only, the trimmer's window restriction keeps a connected map (out-of-window breakpoints drop and the seed/closing anchors take their place) versus range-filters point events away (phase reset column; recorded at `plan_trim`), the phase reset derivation (`derive_phase_reset_frame_map`) has no warp sibling (the warp frame map is already the engine's input domain; a phase reset position crosses to the deliverable target domain only for the render-end participation verdict, then shifts by the constant `N/2` into the engine query domain), the phase reset overlay (a paint-only, phase-reset-only surface — painted in target view, a target/output-domain display where a uniform window-origin shift preserves the constant target-time span, never source view; recorded at `paint_phase_reset_overlay_ring`; the overlay shows for a single focused reset only — suppressed while the selection has 2+ members (the multi-select suppression; the region gate died 2026-07-30 as dead code — a region rests only beside an empty selection, so it cannot coexist with a focused subject — the derivation at the band, paint_handler.cpp), the single-focus suppression), the frame-0 seed and the label-ref/pass normalizations being warp-only in the resolver (phase resets carry no tempo, labels, or inheritance — their whole normalization is the exact-equal collapse), and trim living outside the selection system (bounds unselectable, no Tab stops, no Delete/nudge — markers select; the former per-bound wall split is RETIRED, all authored positions sharing the [0, total-1] domain). The engine validators are fully symmetric per column; the map's two columns versus the reset list's one is arity, not asymmetry. The GUI pair vocabulary is `warp_X` / `phase_reset_X` (`warp_markers` / `phase_resets`, `warp_dirty` / `phase_reset_dirty`); warp is never the unmarked default.

"LOAD IN PLACE" IS LIKEWISE ONE CONCEPT TOKEN (architect 2026-08-04, dissolving the commit/adopt collision): the act that applies a saved state into the live session — a render entry via `'`, a checkpoint via `'` in the history mode, and since 2026-08-08 a STATE OF THE SESSION'S OWN UNDO/REDO TIMELINE via `'` on that mode's Local tab — is named "load in place" on every surface: prose says "load a render in place", identifiers spell `load_in_place` (`load_render_entry_in_place`, `load_history_commit_in_place`, `load_history_local_entry_in_place`, the `load_editor` family, `Kind::LoadInPlace`), because the act IS a load (it runs the source load's own applier, disk untouched) and "in place" says the session stays while the state changes. It is never shortened to bare "load" where it names the act (bare "load" stays the launch-time source load's word), "adopt" is retired, and "commit" thereby means exactly one thing again, the git checkpoint commit — while the editors' generic Enter-commits-the-line vocabulary keeps its ordinary sense, being no part of the collision — including the COMMIT-TITLE editor's, whose name is the git sense and whose Enter is the generic one.


### Strict Modifier Validation
STRICT MODIFIER VALIDATION (architect 2026-07-28, project-wide): a modifier combination with no explicit binding is a NO-OP, uniformly. Every predicate that used to accept a key "under any modifiers" was tightened — Space is bare-exact at its one shared owner (`is_play_pause_key`, read by both the dispatch and the read-only allowlist), Escape is bare-exact at ALL of its readers — re-derived 2026-07-29 after contortion ruling 5 deleted the selection/region ladder, leaving the prompt mapper, the editor-text-drag escape hatch, `handle_escape_cancels`, the allowlist, and the editor classifier (the drag-modal gate left this list 2026-07-30 — it tests only Ctrl+Q and reads Escape nowhere; mid-gesture Esc is swallowed by its general drag-modality, not an Esc predicate) (the pointer gestures' Esc hatch went with their cancels, rulings 3+4), the editors' session keys (Escape / Return / KpEnter) are bare-exact, the editors' clipboard chords (A/C/X/V) are CTRL-exact, and the modal prompt is CASE-SENSITIVE — its letter, Delete, and Escape responses all match bare only, and since 2026-07-30 the letter arm compares the CODEPOINT rather than relying on `!shift` (the platform case-folds letter keysyms, so `!shift` alone let CapsLock deliver a visually-uppercase Y that still answered `[y]es`; `mods.codepoint` carries the true character under shift AND lock, so a capital never matches a lowercase response key however it was produced). THREE PREDICATE FAMILIES ARE DELIBERATELY NOT TIGHTENED because the modifier is a REAL BINDING there rather than laxity: `is_tab_cycle` (Shift+Tab is reverse cycle), Ctrl+Z (Shift selects redo — the ONE meaningful bit on the family, the arm reading `ctrl && !alt && key == Z`; ALT briefly selected a stay-put restore, 2026-08-06..07, and that pair was ROLLED BACK because labwc owns the chords, so alt is once again unbound here, `selection-model.md`), and the editors' MOTION arm, which admits its six keys under ctrl and shift in every combination but NEVER alt (architect 2026-07-28, the last lax predicate found). The line is drawn at alt and NOT at exactness, deliberately: ctrl and shift carry real meaning on all six keys — Ctrl+Left is word motion, Ctrl+BackSpace is word erase, Shift extends the selection — and they degrade to the plain gesture where they add nothing, exactly as an ordinary one-line field does (Ctrl+Home still goes to the start, Shift+BackSpace still backspaces), so making them exact would BREAK them. Alt binds nothing anywhere in the family, and admitting it is what let Alt+Left move the caret and Ctrl+Alt+BackSpace erase a WORD inside a surface that had just been declared inert to unlisted chords. Printable insertion likewise keeps shift (capitals) and excludes ctrl and alt.

THE ALT VOCABULARY, whole (re-derived 2026-08-12, the eighth glass ruling — PAN-PRIMARY emptied alt's pointer half): ALT = THE FOUR KEYBOARD Ctrl+Alt RENDER/PROPAGATE CHORDS AND NOTHING ELSE — Ctrl+Alt+R / Ctrl+Alt+Shift+R (the render pair; R absorbed the iteration sweep 2026-08-02, retiring Ctrl+Alt+I unbound) and Ctrl+Alt+P / Ctrl+Alt+Shift+P (the propagate pair). THE SUCCESSION: "alt is the pointer/arrow authoring modifier" (the 2026-07-17 gesture pivot) → "alt is pointer-only: pan, drag and wheel" (2026-07-28, every alt keyboard gesture going bare) → "pointer-plus-four" through 2026-08-12's morning (the alt+drag grab-pan and alt+wheel stepped pan, plus the four chords; the ALT BRIDGE DRAG of the merged trim band lived one day, 2026-08-11..12, and left with that arc's revert; the stay-put undo pair Ctrl+Alt+Z / Ctrl+Alt+Shift+Z lived one day, 2026-08-06..07, and was rolled back because labwc owns those chords) → EMPTY ON THE POINTER (2026-08-12, the eighth ruling: the grab-pan moved onto the PLAIN drag as the navigation surface's primary gesture, and the stepped pan onto the PLAIN wheel — "alt+wheel is step pan... that comes from Reaper", the convention following the pan to its new home). An alt-modified press or wheel is a strict consumed no-op everywhere; alt binds nothing in the editors' motion family (the exactness line above); the four chords are the whole of it.

SUPER IS DROPPED AT THE PLATFORM BOUNDARY (architect 2026-07-30 — "i use super in labwc config so it's not used in GUI"). The strict-validation rule above was FALSE for Super for its first two days: the modifier mask never modelled LOGO, so every bare-exact predicate read three bools, a held Super left `mods == {false,false,false}`, and Super+Escape reached the editors' cancel, Super+Return their commit (labwc grabs many Super chords, but Escape/Return/Space/Delete/the arrows/Home/End are ungrabbed and reach the client). The fix is the boundary drop, not a fourth bool in every predicate: the platform tracks `mod_super_` (XKB LOGO, effective) and `deliver_key` — the single shared delivery path for physical presses AND synthesized repeats — delivers nothing while it is held; a press arriving under Super also arms no repeat (its burst would otherwise deliver post-release carrying the repeat bit, merging into an older undo entry from a press the app never saw); the bit resets on keyboard-leave and seat-capability loss so a labwc-grabbed chord cannot latch it. Key releases stay platform-internal (never gated — a skipped release would orphan a synthesized-left hold), pointer events are untouched, and Super+`e` still synthesizes the left button (bare `e` IS the mouse at this boundary). The authoritative comment is at `deliver_key` (platform_wayland.cpp). So "an unbound modifier combination is a no-op everywhere" is now true BY CONSTRUCTION for the one modifier this program never binds.

### Why the Editors Need No Stray-Modifier Class
A key that wears a stray modifier on a shape the editor owns (Ctrl+Escape, Ctrl+Enter, Ctrl+Shift+V, Ctrl+Alt+A) is simply NotEditorKey like any other unbound chord, and drops at the keyboard-modal gate before anything can act on it. It was not always this simple: while the flag editor was non-modal its NotConsumed tail CANCELLED the in-progress edit on the way to global dispatch, so "unbound" and "not ours" could not be allowed to look alike — a `KeyClass::StrayModifierKey` named the first and claimed it inert. THE MODALITY RULING DELETED THAT MACHINERY (2026-07-28, hours after it landed): with the tail gone both classes end in nothing happening, the only residual difference being one wasted repaint of unchanged pixels, so the enumerator was removed and the classifier returned to its plain form with the two arms simply modifier-exact (bare for the session keys, ctrl-exact for the chords). RECORDED BECAUSE THE REASONING GENERALIZES: a destructive fall-through is what forces a codebase to distinguish "unbound" from "unowned"; remove the destruction and the distinction stops paying rent. Prefer removing the surface to maintaining the class that guards it.

### The Plain/Augmented Convention is Retired
THE PLAIN-VERSUS-AUGMENTED MODIFIER CONVENTION IS DEAD (architect 2026-07-28). It survived in exactly one place — bare `s` dropped a plain marker while Alt+S dropped the augmented one, in both columns, mirrored by the empty flag/triangle-lane double-click's plain/shift split. The AUGMENTED form is now the only form on both surfaces: bare `s` and the bare lane double-click drop the copy-previous owner in W and the lead-in reset in P, because the augmented drop is the render-neutral one in the ordinary case (it splits a section without changing the map, where a plain 1.00 drop mid-warp audibly changes the section it lands in). TWO RULED EXCEPTIONS to that neutrality, both architect-confirmed 2026-07-28 as non-problems rather than defects: a drop onto an ALREADY-OCCUPIED frame creates a 2+-survivor exact-frame group that the resolver replaces with one synthetic 1.00 owner (`find_immediate_prior` searches strictly before the drop frame, and `drop_marker` deliberately permits the coincidence) — accepted because the collapse is NORMALIZATION-VISIBLE, the affected markers turning red at once, which is exactly what the red flag is for; and a drop inside a LABEL DEFINITION's section shortens the definition, whose cached target duration every reference reproduces — accepted as an understood property of definitions, a definition's span being its meaning and because the lead-in drop's `−N/2` is the exact inverse of Space's `+N/2` audition. A shift press on that lane now claims nothing at all. There is no surviving bare/modified pairing where the modifier selects a VARIANT of the same gesture.
