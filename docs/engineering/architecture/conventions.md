# Input Conventions (modality, bare-e mouse key, type names, naming symmetry)

Moved verbatim from CLAUDE.md in the 2026-07-25 slim-down (project feature-complete). This file is now the authoritative home for this detail; CLAUDE.md carries only a digest and a pointer here. Keep it current with landed rulings.

### Modality is Bottom-Strip
Modal surfaces live on the bottom strip: the three bottom-strip editors — the settings editor, the bpm editor (top_flag_editor with Kind::BpmBracket), and the render-commit editor (`commit_editor`, Kind::RenderCommit, opened by bare `'` to adopt a `renders/` entry by name — the standalone `adopt_render_entry`, a running-render-guarded wholesale adopt that replaces the retired render-view Ctrl+Alt+C) — and every prompt. While a bottom-strip editor is open, only the editor's own keys plus bare Esc, Ctrl+S, and Ctrl+Q get through (`modal_editor_key_blocked`, the sibling of the read-only allowlist); the mouse works only inside the editor; playback stops when any modal surface opens and cannot restart until it closes. The TOP-strip flag editor (FlagPayload, iter grammar included) is deliberately NOT modal — red-flash-or-exit-without-commit, commands punch through. BPM mode is exactly its editor session: Esc abandons (exit_bpm_mode wipes), Enter dispatches (the sweep's success tail wipes and closes); `m` is not an exit (just a typed char while the editor is open); mode-without-editor is unreachable. The honest invariant stands: the GUI never writes a LOAD-invalid state — every committable state is load-legal by construction, and [s]ave always writes a loadable (and now always-renderable) file. (All program-authored GUI/terminal text is ALL-LOWERCASE by ruling 2026-07-17 — prompts, keycap labels, engine pass lines, diagnostics; data/identifier strings, settings value vocabulary (S/T, W/P, A/B), and user content keep their case.)

### Bare `e` is the Left Mouse Button
`kLeftClickKey` (gui_input.h, = `GuiKeys::E`; the single rebind point — hardcoded by ruling 2026-07-17 mirroring the architect's feh bindings; a configurable settings-key design and a q/backtick round were considered and REJECTED) is translated into BTN_LEFT at the PLATFORM boundary (`platform_wayland.cpp`), not in on_key: press = button down at the live pointer position, hold = button held (so `e`+motion drags and Ctrl/Alt compose), release = button up. Delivery follows the logical edge model — logical left is `pointer_left_held_ || synth_left_held_`, press on the 0→1 edge, release on the 1→0 edge (the evdev duplicate-BTN_LEFT model) — so physical and synthesized sources never double-deliver, and `current_mods()` ORs both into `primary_button_held`. Downstream the key IS the mouse and inherits every mouse gate (read-only tabs, drag gates, prompt/editor modality). ONE exception, decided at PRESS time: while a text editor is open (the `any_text_editor_active` probe — all three text editors, the non-modal FlagPayload flag editor included) the key is a normal character with normal repeat arming. Any modifier state rides along to the button, exactly as for a physical BTN_LEFT device. As the button it is swallowed as a key event entirely (no repeat — a held button must not re-press) and acts only while `pointer_focused_`. The release is NEVER gated (not by probe, shift, or focus — it is keycode-owned) and is also synthesized at keyboard leave and keyboard-capability loss, so a held button cannot orphan. Because e-chords can never reach dispatch, the miscellaneous render moved off Ctrl+Alt+E to Ctrl+Alt+Shift+R.

The former `kCtrlModKey` (bare `2` synthesizing Ctrl STATE) was REMOVED 2026-07-17 in the gesture pivot — bare `2` is an ordinary, currently unbound key, and `current_mods()` reads the real `mod_ctrl_` alone. Bare `e` therefore never reaches the key dispatch outside editors — do not bind it.


### Type Names
Marker and related GUI types carry the `Gui` prefix (`GuiWarpMarker`, `GuiPhaseResetMarker`, `GuiAudio`, `GuiPlayback`, etc.). New marker-side types follow the same convention.

### Warp / Phase Reset Naming Symmetry
Warp and phase reset are co-equal axes, and every pipeline surface names them as parallel columns. The artifact pair is `.warpframemap`, `.phaseresetframemap` (MIDI support is removed). Extensions concatenate without separators; identifiers underscore the same concepts (`warp_frame_map`, `phase_reset_frame_map`). "Phase reset" is one concept token and is never shortened to "reset" in names. New pipeline surfaces must ship both columns, or record the asymmetry in a comment at the site. Existing recorded asymmetries: scale is warp-only, the resolver cascade (`resolve_warp_markers_for_render`) is warp-only, the trimmer's window restriction keeps a connected map (out-of-window breakpoints drop and the seed/closing anchors take their place) versus range-filters point events away (phase reset column; recorded at `plan_trim`), the phase reset derivation (`derive_phase_reset_frame_map`) has no warp sibling (the warp frame map is already the engine's input domain; a phase reset position crosses to the deliverable target domain only for the render-end participation verdict, then shifts by the constant `N/2` into the engine query domain), the phase reset overlay (a paint-only, phase-reset-only surface — painted in target view, a target/output-domain display where a uniform window-origin shift preserves the constant target-time span, never source view; recorded at `paint_phase_reset_overlay`; the overlay shows for a single focused reset only — suppressed while the selection has 2+ members or region.active, the R7 span-state rule), the frame-0 seed and the label-ref/pass normalizations being warp-only in the resolver (phase resets carry no tempo, labels, or inheritance — their whole normalization is the exact-equal collapse), and trim living outside the selection system (bounds unselectable, no Tab stops, no Delete/nudge — markers select; the former per-bound wall split is RETIRED, all authored positions sharing the [0, total-1] domain). The engine validators are fully symmetric per column; the map's two columns versus the reset list's one is arity, not asymmetry. The GUI pair vocabulary is `warp_X` / `phase_reset_X` (`warp_markers` / `phase_resets`, `warp_dirty` / `phase_reset_dirty`); warp is never the unmarked default.


### Strict Modifier Validation
STRICT MODIFIER VALIDATION (architect 2026-07-28, project-wide): a modifier combination with no explicit binding is a NO-OP, uniformly. Every predicate that used to accept a key "under any modifiers" was tightened — Space is bare-exact at its one shared owner (`is_play_pause_key`, read by both the dispatch and the read-only allowlist), Escape is bare-exact at ALL of its readers (the prompt mapper, the two drag/edit escape hatches, `handle_escape_cancels`, the selection/region ladder, the allowlist, and the editor classifier), the editors' session keys (Escape / Return / KpEnter) are bare-exact, the editors' clipboard chords (A/C/X/V) are CTRL-exact, and the bottom-strip prompt is CASE-SENSITIVE — its letter, Delete, and Escape responses all match bare only, `!shift` included, because the platform case-folds letters and delivers the unshifted key with `mods.shift` set. TWO PREDICATES ARE DELIBERATELY NOT TIGHTENED because shift is a REAL BINDING there rather than laxity: `is_tab_cycle` (Shift+Tab is reverse cycle) and Ctrl+Z (Shift selects redo); the editors' motion keys likewise keep "any modifiers" (Ctrl+Left is word motion) and printable insertion keeps shift (capitals).

### The Stray-Modifier Class
THE TRAP THE RULE CREATES, and its structural answer: the non-modal top flag editor's NotConsumed tail CANCELS the in-progress edit before letting a key through to global dispatch — correct for a real command, destructive for a key that is merely unbound. So "unbound" and "not ours" must not look alike. `text_editor::KeyClass::StrayModifierKey` is that distinction: a press matching an owned key SHAPE that a stray modifier makes unbound classifies as its own class and `handle_key` claims it inert (Consumed, no commit, no cancel, no buffer change), so no caller re-enumerates editor keys and the classifier stays the single owner of the keymap. The PRINTABLE arm is deliberately outside that family — every letter is bare-printable, so a generic "would be an editor key without the modifier" test would swallow Ctrl+S / Ctrl+Z / Ctrl+Q / Ctrl+Tab, the global command chords that MUST punch through an open editor, cancelling the edit first. Only the two modifier-DEFINED arms (bare-exact session, ctrl-exact chords) have a stray-modifier form to name. RECORDED AS OPEN: an unbound modified key that is not an owned shape at all (`Alt+F`, `Ctrl+B`) still reaches that tail and discards the edit for nothing — pre-existing, and closing it would need an explicit global-command list at the tail, which is exactly the "no command list, everything else punches through" design the tail asserts.

### The Plain/Augmented Convention is Retired
THE PLAIN-VERSUS-AUGMENTED MODIFIER CONVENTION IS DEAD (architect 2026-07-28). It survived in exactly one place — bare `s` dropped a plain marker while Alt+S dropped the augmented one, in both columns, mirrored by the empty flag/triangle-lane double-click's plain/shift split. The AUGMENTED form is now the only form on both surfaces: bare `s` and the bare lane double-click drop the copy-previous owner in W and the lead-in reset in P, because the augmented drop is the render-neutral one (it splits a section without changing the map, where a plain 1.00 drop mid-warp audibly changes the section it lands in) and because the lead-in drop's `−N/2` is the exact inverse of Space's `+N/2` audition. A shift press on that lane now claims nothing at all. There is no surviving bare/modified pairing where the modifier selects a VARIANT of the same gesture.
