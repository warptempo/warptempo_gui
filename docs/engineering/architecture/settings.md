# Settings Schema and Editors

Moved verbatim from CLAUDE.md in the 2026-07-25 slim-down (project feature-complete). This file is now the authoritative home for this detail; CLAUDE.md carries only a digest and a pointer here. Keep it current with landed rulings.

### Engine Settings are Typed
`app.engine_settings` (declared in `engine_settings.h`) is the single in-memory source of truth for the engine-relevant settings keys. There is no string-shaped passthrough vector, and there is NO `output_format` key (removed 2026-07-15 like `limiter`, no legacy — a `.settings` still carrying it fails the strict load as an unknown key): the wav is the only render product. FUTURE-PROOFING (architect-ruled): every archival render — GUI disk route AND the CLI, never the preview buffer route — also writes the FULL framemap pair (`<wav-stem>.warpframemap` + `.phaseresetframemap`, exactly the engine's input, via the shared `map_output` writers, byte-identical between products) into `~/.cache/warptempo_gui/<pid>/`; the pair is STRICTLY INERT — no product path reads it back; the intended consumer is a hypothetical future diff-capable algorithm; the `RenderCache` lifecycle owns cleanup (dir removed at GUI shutdown, dead-PID orphans — CLI dirs included — swept at the next GUI launch); the write is non-fatal (one stderr line on failure). MIDI tempo-map support is removed entirely. The limiter is UNCONDITIONAL and is NOT a settings key (removed 2026-07-15, no legacy: a `.settings` still carrying `limiter=` fails the strict load as an unknown key); output is always the limited 24-bit PCM deliverable — the `limiter=false` Float32 clean-render path and its filename prefix are gone, as is Float32 WAV INPUT (sources are 16/24-bit PCM WAV only) and the WavWriter's non-PCM24 write support. The peak parameters are non-settings constants in `src/prepost/peak_limiter.h`. All three boundaries are strict:

- File load (`read_settings_file` in `src/parser/settings_file.{h,cpp}`, the whole-file strict schema run VERBATIM by both GUI and CLI — a sidecar set is loadable in both products or neither): any violation aborts the source load with the first error, same shape as a corrupt audio file — unknown key, keyless non-comment line, duplicate of ANY key, malformed or out-of-vocabulary value (GUI-kind keys included: off-preset playback_speed, out-of-range font_size, out-of-vocabulary zoom), missing ANY canonical key — EVERY key is required (the parser-side `kCanonicalSettingsKeys` list in settings_file.cpp, the membership twin of `kSettingsOrder`; the program writes all keys, so a file short of one is hand-damaged and refuses; there is no absent state and no load-side default). Persisted viewport/playhead values are NOT range-checked at load (display scratch — the runtime clamps own them; the guard was removed 2026-07-15); a slowing map legitimately persists positions past the source total; the check is SKIPPED when the map cannot build — tripwire-class only, since the resolver normalizes marker arrangements and never refuses — and the runtime clamps own the values then); the persisted zoom-vocabulary constants (`kMinZoom`/`kMaxZoom`) live in `settings_file.h` so that refusal is also identical in both binaries.
- Editor commit (`GuiSettingsEditor::commit`): unknown engine keys and invalid values red-flash and don't commit.
- Render dispatch: `req.engine_settings` is copied from `app.engine_settings`; the typed struct cannot hold malformed values by construction.

`kSettingsOrder` in `settings_io.cpp` is the SoT for the on-disk write order and the first-open template; key MEMBERSHIP is `kEngineKeys` via `is_canonical_engine_key` (`engine_settings_io.cpp`; the table pairs each key with its `EngineField` and doubles as the key-to-field lookup), `validate_engine_setting` is the single per-`(key, value)` engine validator used by the schema readers and editor commit alike, and `format_engine_field_value` is the single engine-field byte serializer — the key-keyed `format_engine_setting_value` (autocomplete) and every settings writer delegate to it. The two strict readers share one lexical scanner (`warptempo_settings::scan_settings_file`, `settings_file.h`), and its lexing is BYTE-EXACT: each line splits at its first `=` verbatim — no BOM, blank-line, `#`-comment, or whitespace tolerance anywhere (the marker parsers are equally byte-exact; `strip_bom` is deleted product-wide; the migration tool keeps its own legacy latitude) — with the duplicate rule and the required-key tail existing once. Adding a new engine key touches: `EngineSettings` (new field with member default) and `EngineField` (`engine_settings.h`), `kEngineKeys` and `validate_engine_setting` (`engine_settings_io.cpp`), `kSettingsOrder` (`settings_io.cpp`), `kCanonicalSettingsKeys` (`settings_file.cpp`). Six edits, four files.

`kSettingsOrder` also carries GUI-kind keys — view state, `playback_speed`, `font_size`, `audio_player` — that never enter `EngineSettings` or the engine block; they persist through the `.settings` file but are not engine input. The settings editor sets EVERY key that can appear in a `.settings` file: GUI-kind commits route through `GuiSettingsEditor::commit_gui_setting`, which hands (key, value) to `validate_gui_setting` (settings_file.{h,cpp}, parser-side — the GUI-kind sibling of `validate_engine_setting` and the SINGLE grammar/vocabulary owner, called by the whole-file reader AND the editor, so a spelling is loadable iff it commits; it is STATE-FREE — the load-side trim walls stay in `first_past_eof_wall_defect`, and the editor keeps its read-only-tab trim refusal, its own wall compare, and active/inactive routing on top) and applies the typed result through the key's own GESTURE CHOKEPOINT — `set_playback_speed`, `set_follow_mode`, `apply_font_size`, `handle_active_audio_view_toggle`, `toggle_active_markers_view`, `switch_active_tab_view_to`+trigger, `move_playhead_to` / `apply_zoom_change` / assign-then-`clamp_viewport_start` (the ACTIVE-tab playhead-cursor commit joins the navigation-jump class since 2026-07-29 — no exemptions: it clears the selection AND the region before the move, the Home/End sequence verbatim, the rationale at the arm), and the trim commit tail incl. `auto_clear_crossed_trim` — never a parallel writer. Per-tab keys naming the INACTIVE tab write that tab's stored band (load-shaped values; the Ctrl+Tab restore clamps own them; a crossed resulting trim pair RESETS to that tab's full window with one stderr line, the load convention under always-set trim); trim writes red-flash when the named tab is read-only (an authoring mutation — its gestures refuse there too), while viewport/zoom/playhead/read_only stay navigation-class. The four per-tab trim keys ALWAYS EMIT ACTUAL FRAMES (always-set trim, architect 2026-07-30): the `-1` unset spelling is DELETED from the frozen grammar under an explicit same-day grant (recorded at each settings_file.{h,cpp} site) — a trim value is a canonical whole source frame and nothing else, `-1` refusing like any malformed value in both products (a pre-arc sidecar carrying one is adversarial and load-fatal; hand-edit is the ruled recovery, no migration tool by ruling), and the first-open template stamps the full window [0, total-1] on both tabs. Both trim keys' ACTIVE-TAB commits keep the SETTER DESELECT (architect 2026-07-30, "a typed commit is a commit"); an inactive-tab commit writes the parked band only and deselects nothing (the trim-window highlight publish died with the region simplification — a setter WRITES a bound, and the crossed-commit tail now RESETS to the full window, full-window-first so the one-frame [0,0] never self-resets). Numeric settings VALUES are pinned to ONE canonical spelling each — the exact bytes their writer emits: playback_speed by text membership (above); tab_X viewport/playhead through `parse_authored_frame` (digits only, no sign/point/leading zeros — the %lld output); tab_X_zoom by the min-0 `format_value_double` round-trip gate then the continuous vocabulary `[kMinZoom, kMaxZoom]` = [1,17] (the zoom level is a real-valued double — see the continuous-zoom paragraph; `0`, `0.5`, and any non-shortest spelling refuse — no sentinel, no migration); font_size by a %g round-trip gate (`11` and `10.5` load, `11.0` refuses); the settings scale and marker scale by a `format_value_double(v, 4)` round-trip gate (the min-4 padded shortest form is the one spelling; the session-only bpm-bracket bounds gate at min-0 likewise); `parse_double_strict` (parse_text_util.h) and `parse_value_double` (value_format.h) still reject any ASCII alphabetic byte first (no exponents, no inf/nan). The free-text fields (title, notes, cover, url, audio_player) keep caps verbatim — title with three refusals (empty, a wrapping double-quote pair, '/') and NO input latitude (the file boundary is byte-exact; the settings editor still trims its typed line — interactive latitude, not file latitude); bools share `parse_bool_token` schema-wide, and its vocabulary is exactly `{true, false}` (the writer's two spellings). GUI-kind commits are history-less like their gestures: no undo, no dirty, one stderr line, deactivate; a same-value commit no-op-deactivates like the engine no-op gate. Autocomplete's bare-Tab recall works for every key, byte-identical to what a Ctrl+S would write (shared `format_nonengine_value` serializer + `recall_gui_setting_value`, settings_io.cpp). Playback is always already stopped during a commit (the editor is modal; its open stopped playback). `audio_player` is the one GUI-kind key with no gesture at all: an external launcher binary (name or path) consumed by the `l` "Listen to renders" command (posix_spawnp over every `renders/` wav), a required key like every other, ALWAYS emitted by the writer (blank when empty — the free-text empty value, the only spelling of the no-player opt-out). Default is `audacious` in exactly two places (the AppState member initializer = pre-load state, and the first-open template; there is no load fallback — the reader always assigns the field; a spawn failure is one stderr line, nothing more); `:audio_player=<path>` writes it directly with no undo/dirty; `:audio_player=` empty clears it → the writer emits the explicit blank `audio_player=` opt-out. Render-entry `.settings` carry it like every always-emitted key (the dispatch-moment value; adopt applies it 1:1). `font_size` has no gesture (the `Ctrl+Shift+equal`/`minus` step was removed 2026-07-17 in the gesture pivot): the settings editor's `:font_size=` commit is the sole author, keeping the 96-DPI point convention, default 11, no undo history, live-applied through the resize-path geometry rebuild (`apply_font_size`, whose sole caller is that commit; the load path pushes the value through `set_gui_font_size_pt` directly).

Render entries carry the SAME sidecar set a source does: `<basename>.warpmarkers` / `.phaseresetmarkers` (authored domain, iter/bpm variation applied at dispatch) plus a full standard-schema `<basename>.settings` and `.fingerprint` written by `do_render`'s commit-critical tail for wav renders (`active_audio_view=T` always; the commit tab = dispatch tab carries the recipe trim and dispatch-moment view keys; live session prefs are captured at dispatch through `AuthoringSnapshot`). The set is written ONCE and never touched again. There is NO in-app render-view player (the stateless render-entry audio player was removed): auditioning is EXTERNAL — `l` ("Listen to renders") launches the `audio_player` binary over every wav under `renders/` in numeric order via posix_spawnp — and the sole transfer of a render back into authoring is the `'` commit editor (`GuiRendersDir` — renamed from GuiRenderView — is the pure `renders/` enumerator feeding `l` and the editor's autocomplete). `adopt_render_entry` (input_key_dispatch.cpp) re-reads a named entry's frozen set — the marker pair, engine block, recipe trim, both tab bands, and session prefs — reading and validating the wav's existence and all three sidecars BEFORE any store mutation (returns silent-false on any failure → the editor red-flashes), then applies it into the LIVE state 1:1 with a fresh source load of those sidecars — via the shared `apply_settings_engine_and_prefs` (file_loader.h/.cpp, the SAME values-only routine `load_file` runs), so EVERY field a load sets is set identically, INCLUDING `active_markers_view` (the former live-W/P carve-out is RETIRED — no carve-out remains), the tab bands (`view_state_from_settings_tab`), and all session prefs. Adopt is an in-memory 1:1, not a literal mv+load: the commit WORKFLOW is unchanged — one cross-file undo entry, dirty (Ctrl+S persists), and the `renders/` wipe — it does NOT overwrite the source sidecars on disk or reset undo. It lands in TARGET view on the entry's dispatch tab at the DISPATCH-MOMENT position (mirroring load's tab-bands → engine+prefs → live-band activation → side-effects order, so `on_resize` sees the file's live band exactly as a load does). It carries the same running-render guard render view had (the adopt wipes renders/, which must not race a background sweep). The entry sidecars are trusted (written once at dispatch, never hand-edited): a malformed sidecar fails its own parse, but there is no adversarial content re-attestation — the render worker's source-clobber backstop and the engine tripwires remain the last-ditch guards. A successful commit then wipes renders/. A finished batch no longer auto-opens anything — its artifacts rest on disk for a later `l` or `'`.
