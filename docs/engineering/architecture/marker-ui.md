### Marker Gestures
A marker is ONE pointer item: its painted flag box (the painter's stash; one BACKWARD walk, last painted topmost) plus its stem's ±4px upper-half band — FOR PLAIN PRESSES ALONE since 2026-08-01: the shift and ctrl selection clicks bind to the FLAG only (the one resolution site gates the stem term on plain-exact), because both modifiers mean something else on the waveform the stem stands in — a modified press over a stem is the placement press / the strip drag, not a marker hit. THE RULE IS UNIVERSAL SINCE 2026-08-06 (the architect's symmetry ruling; selection-model.md carries it in full): the `h` history view's stem-based multi-select, the one exception this line used to record, is DELETED — every view answers a waveform modifier with a GESTURE, and every view does its selecting in the marker lane. A plain click selects and LANDS THE PLAYHEAD (selection-model.md owns the re-coupling, shift/ctrl semantics, and the never-parked rule); the flag is the drag handle — the press single-selects and arms a `PendingMarkerDrag` (first-class armed gesture: `any_pointer_gesture_active`, the key gate, and the force-end finalizer `finalize_active_drags` all include it), and crossing the one generic `kDragMovedThresholdPx` (8px, Chebyshev, latched) begins `marker_drag.begin_drag(marker, press_x)` — anchored at the PRESS x so the first apply folds the whole catch-up. Shift never arms; read-only selects but never arms. Mid-drag the overlay proposes positions through the displayed map with the fractional time rounded BEFORE the map lookup (`apply_drag_motion` maps `nearbyint(new_t)` — the row-5 refinement fix); the release commits through the pixel-anchored column snap (zoom-viewport-strip.md). POINTER GESTURES HAVE NO CANCEL (rulings 3+4): Esc mid-gesture is a consumed no-op, any end commits, undo is the mitigation.

THE EMPTY MARKER-LANE press has waveform parity: plain click = deselect + playhead placement + region-drag arm (the shared `place_playhead_and_arm_region` body, no stop call — a live session reseeks); plain DOUBLE-CLICK creates a marker at the clicked position — the AUGMENTED drop (warp copy-previous / phase reset N/2 lead-in), the only drop bare `s` performs too, through the standing `_at_playhead` chokepoints (`DoubleClickSurface::EmptyLane`, position-keyed) — home-view + read-only refusing silently. A shift press on the lane claims nothing (falls to the inert top-strip return).

### The Flag Editor and the Editor Lifecycle
ENTER (bare Return/KpEnter, no editor open) opens the flag editor on the FOCUSED marker (W view only — phase resets have no per-flag editor; read-only refuses at the allowlist); a plain DOUBLE-CLICK on a warp flag opens the SAME editor on that marker (the first click single-selected it and armed no drag; P view and read-only refuse silently, matching Enter). The editor is the FLAG UNROLLED (kdenlive-redesign.md row 5 checkpoint C): the box grows from the flag's own painted column to the FULL text width, wearing the marker's resolved face — opening changes the flag's SIZE and nothing else; invalid commits red-flash in the lane's red pair; `text_editor::State::view_offset_px` gives this one surface minimal-travel horizontal scroll; click-to-byte is nearest-boundary ties-low through the ONE owner `editor_byte_index_at` on the shaped run's `byte_offsets_px`. THE LIFECYCLE IS GUARD-FREE (2026-07-22): while the editor is open, a click in its rendered text places the caret; ANY other click CLOSES it without committing (exactly Esc's teardown, `exit_top_flag_edit_no_commit`; Enter stays the sole commit route, the close placed ahead of every band claim so it is unconditional) — a double-click on the open editor's own marker is close-then-reopen, which IS the double-click-opens rule, no special case. EVERY editor opens with its SEEDED content fully selected (open-selected, one universal rule at the `enter_text_edit` chokepoint; the blank-seeded settings/load editors degenerate to caret 0). Modality — which keys reach an open editor, the playback stop, the wheel transparency — is conventions.md's; the bottom-strip editors' band and fixed-section geometry are kdenlive-redesign.md row 7's.

### Double-Click Machinery
All double-clicks are hand-rolled (Wayland delivers none) and arbitrated by ONE surface-tagged `DoubleClickCandidate` (surface ∈ {TrimBar, Marker, EditorText, EmptyLane} — app_state.h; `kDoubleClickMs` 500 / `kDoubleClickSlackPx` 8 = `kDragMovedThresholdPx` by construction; Marker additionally keyed on the marker index) so the surfaces cannot cross-fire. The TrimBar candidate is the span-framing double-click (seed-at-motionless-release, consume-before-arm — zoom-viewport-strip.md); the text-editor double-click selects the maximal run of the clicked character CLASS via `select_word_at` (word `[A-Za-z0-9_]`+bytes≥0x80 / whitespace / punctuation, the Qt/Kate convention; the ≥0x80 word-classing is what keeps a selection edge on a codepoint boundary now that the editors carry real UTF-8, and the probe itself is exact — `byte_index_from_shaped_x` reads the shaped run's own per-byte pen offsets, so non-ASCII earlier in the line shifts nothing). Any intervening keyboard or wheel command, a moved drag, button-lost, the force-end finalizer, or load clears the candidate.

### Key Repeat
Repeat is ELIGIBILITY-GATED at press time (`repeat_eligible`, an application probe the platform consults BEFORE arming): globally only the continuous step gestures repeat — ALL FOUR BARE ARROWS (Left/Right the two-lane playhead step / marker nudge, Up/Down the tempo cent step; the lane split is decided per fire at dispatch, so the arrows repeat as one family and NO modified arrow repeats), PageUp/PageDown, `=`/`-` zoom, the marker-focus cycle (bare Tab / Shift+Tab / IsoLeftTab; the cycle always recenters on the focused marker, AT THE CURRENT ZOOM — the working-zoom landing of 2026-08-05 was reverted the same day), and the THREE repeating Ctrl chords — Ctrl+Shift+Tab plus Ctrl+Z / Ctrl+Shift+Z (history stepping is a continuous step gesture; a shift pressed mid-hold flips undo to redo under the live-modifier rule; Ctrl+Tab stays one-shot) — and inside an open text editor the typing/cursor/edit keys (never Enter/Esc/Tab); every other command is one-shot, and a press that OPENS an editor is judged under the pre-open context so it never repeats into what it opened. Repeat fires recompute modifiers AND codepoint live; any pointer-button press or completed wheel emission disarms the hold. A held key's synthesized repeats coalesce into ONE undo entry by repeat identity (normalization-and-boundaries.md owns the contortion-7 detail).
