# The GitHub Recheck (history mode)

The arc landed 2026-08-03..04 over five commits — dd4757e (the diff model), 3e671a8 (the mode), 3efc64e (adopt-from-commit), 2324f62 (docs), 3b698b4 (the commit act and the two buttons) — whose messages carry the full per-round narratives; this file is the standing ruling record. The feature: bare `/` (also the icon row's twelfth button, Icon::VcsDiff behind a separator gap, selected while the mode stands) opens a read-only view of how the live in-memory authoring state differs from the piece's committed checkpoints, `,`/`.` walk the checkpoints, the marker lane paints the delta as green/red diff flags, `'` adopts a viewed (or pasted) commit's whole sidecar state in memory, and Ctrl+Alt+R — the Render button, wearing "Commit"/Icon::VcsCommit while the mode stands — publishes the current state as a new checkpoint. The architect's purpose: commit checkpoints to GitHub with confidence instead of keeping local file copies, and catch slips of the hand as projects grow.

## Transport and trust

LOCAL GIT, THE READ/WRITE SPLIT AS TWO ENTRY POINTS. The module (`src/gui/history_diff.{h,cpp}`) shells to git with an argv exec (no shell anywhere — corpus paths carry spaces) against the constexpr repo root. `run_git_capture` passes ONLY reads — `log`, `show`, `ls-tree`, `rev-parse`, `status`, `remote get-url` — and `run_git_mutate` (round 5, the commit act's fenced writer and its ONLY site) passes ONLY `add`/`commit`/`push`; both inventory comments are authoritative, and the fence is which function a call site names. No fetch, no credential in the program: every read is against the LOCAL branch (`HEAD` since round 5 — the product is a commit producer, and a checkpoint whose push failed must still be visible history; `origin/main` would hide it until the next successful push), and the push authenticates through the machine's own SSH setup. Subprocess success is "ran and produced output" because main.cpp's `SIG_IGN` SIGCHLD auto-reap (the audio-player precedent) makes `waitpid` return ECHILD — documented at the helper. Tree listings are NUL-separated (`ls-tree -z`) so a UTF-8 base name survives `core.quotePath`.

`projects_repo` (settings.md owns the key's full record) names WHICH repository is the projects home; the local clone is the transport, and init's guard normalizes the setting against the clone's own `origin` URL (scheme, scp `git@host:path`, trailing `.git` all compare equal), refusing a mismatch with one stderr line. An empty value never matches — the feature's opt-out.

## The match and the walk

THE MATCH IS BY COMMITTED FILE NAME UNDER `projects/` (architect 2026-08-03; narrowed from the whole tree 2026-08-04 — the repo-layout convention is `<repo>/projects/`, one folder per piece, and a theoretical other user builds their own repo with a `projects/` folder): the loaded source's sidecar base name (the loader's own `stem()` derivation, mirrored — it strips only the last extension, load-bearing for period-heavy titles) is resolved against HEAD's tree filtered to `projects/`; exactly one directory may carry the sidecars. The walk is `git log -n 20` over `:(glob)projects/**/<base>.<ext>` pathspecs, and each commit's snapshot paths resolve from THAT commit's own tree. ACCEPTED TRADES, recorded: basename matching cannot see history across a SOURCE RENAME, and the `examples/`-era commits left the walk with the round-5 narrowing (legacy-format, refuse-adopt anyway — the walks head at the rename commit until the first commit act). A piece with NO committed history cannot open the mode at all; its bootstrap stays a manual act.

## The diff model

The NOW side is the live in-memory state serialized through the save writers' own string halves (`format_warpmarkers_text` / `format_phaseresetmarkers_text` / `format_settings_text` — the round-1 split; byte-identical to a Ctrl+S, no disk touched) and is FROZEN AT init(); the mode's mutation gate is what keeps the frozen snapshot honest (authoring is blocked while the mode stands, so it cannot go stale by construction). Then-vs-now is an in-tree line LCS (DP with prefix/suffix peeling and a cell cap) typed into per-commit deltas: warp added/removed/changed carrying each line's VERBATIM tempo token (the flag shows the sidecar's own spelling, never a re-derivation), phase resets added/removed/changed (their line is frame plus disable prefix, so a `#` toggle pairs as a genuine change, symmetric with warp), the `scale=` tokens from both sides (THE ONLY SETTINGS KEY THE MODE DISPLAYS — a recorded asymmetry: every other settings delta is deliberately invisible), and raw line counts. A same-frame remove+add pair IS the changed entry — it feeds the double flag. Unparseable legacy lines drop from the typed delta with one stderr line per commit view; the DIFF is parse-free where the ADOPT is parse-gated, which is the two-tier answer to legacy formats. A commit missing a file reads as everything-added — the natural line-diff answer. Deltas compute lazily and cache per commit; stepping revisits are free.

## The mode

`/` (bare-exact; `GuiKeys::Slash`) toggles; `,` older / `.` newer, clamped walls as consumed no-ops; the `i`-mode toggle shape, NO Esc binding (the Esc inventory stays six). The on_key gate sits directly under the drag-modal gate and above the read-only gate — every entry refusal (prompt, dropdown, loading, editors, live gesture) has already run above it, `/` typed in any editor is CLAIMED as a printable, and the read-only tab bit is structurally irrelevant to the mode's own keys. Exits: `/`, a source load, either adopt, quit; resize survives and re-lays-out through the flag-cache fingerprint miss.

READ-ONLY WHILE STANDING — two allowlists plus one lockout. Keyboard admits exactly: Space, `=`/`-`, `0`, PageUp/PageDown, Ctrl+S, Ctrl+Q, `'` (since round 3), and Ctrl+Alt+R with its in-mode meaning (since round 5). Pointer admits: the right-button scrub, alt-pan, ctrl-strip-drag, the ruler drag, the lower-half scrub; everything else is consumed, including both trim-bar ctrl writes. All twenty-two chord buttons drop through `dispatch_redesign_chord` → on_key — no second membership (the history and render-commit buttons' in-mode meanings arrive through the same dispatch). `toggle_dropdown` refuses whole while the mode stands, closing the one dispatch route that reaches no key gate (`finish_dropdown_release`'s Settings half opens the prefilled editor directly) — a popup and the history mode are mutually exclusive in both directions. Two structural guards ride the mode edge: `drop_lane_stash_across_history_edge` clears the flag hit rects at entry/exit/step (the stash's `marker_index` CHANGES DOMAIN across the edge — store index vs diff ordinal — and the stash is tick-cadence), and `pointer_cursor_kind` empties the trim-bar band in-mode so no cue promises a refused gesture (per-zone, the read-only model exactly).

## The lane display

While the mode stands the lane suppresses all live marker flags/stems (the playhead head still paints) and paints the current delta through the SAME `iterate_visible_flags_impl` → `frame_to_paint_sample` mapper live markers ride — identical placement in both views by construction, the current session's warp map doing the target-view mapping for both sides. Text: `[+] <token>` / `[-] <token>`, the `#` disable spelling prefixed when set, applied UNIFORMLY to phase resets (`[+]` / `[+] #`) since their same-frame change IS a disable toggle. The changed pair is ONE double-width flag: red left `[-] then`, green right `[+] now`, one outer border, the fill boundary its only seam, RED stem (deference to the old — architect's ruling). Stems always paint the class's UNSELECTED fill. Diff labels are deliberately NOT nine-glyph-truncated: the token is the flag's whole point (the shared cull's width bound generalized to a parameter for this). Colors are the eight crop-exact `kHistoryAdded*`/`kHistoryRemoved*` constants (render.h palette block, provenance = the four row_5_lane_3 crops, modally sampled — the sampling also established that the LIVE red class already matches its crops exactly: `kMarkerFlagFillRed`/`kMarkerFlagEdgeRed` are the selected red crop's pair, `kMarkerStemRed` the unselected fill).

MODE-LOCAL FOCUS: a plain flag click swaps that flag (both halves of a double) to the selected faces and lands the playhead through `land_playhead_on_source_frame` (hoisted from `land_playhead_on_marker` — one landing recipe); the live store selection is untouched. Empty-lane clicks clear it; modified lane clicks are consumed; it clears on step and exit. The bottom-left corner (the modal editors' rect — never contended, by gate) shows `<n>/<count> <shortsha>` then `Scale: <token>`, or `Scale: [-] <then> [+] <now>` when changed, tokens verbatim, the segment omitted when both sides are empty.

## Adopt from a commit

In the mode, `'` opens the commit editor PREFILLED (open-selected, the flag editor's convention — the product's one prefilling precedent) with the viewed commit's full SHA under a `Commit: ` prefix; any spelling `rev-parse --verify <spelling>^{commit}` resolves is accepted, so a SHA pasted from GitHub's web UI works. The commit's three sidecars resolve by base name from ITS OWN tree and reach the STRICT WHOLE-FILE LOADERS through an RAII per-commit scratch directory under the system temp root (all three parse entry points are path-only and frozen; a GUI-side string scanner would be the second grammar the strict gate exists to prevent; the directory dies on every exit including refusals). A PARTIAL COMMIT IS A REFUSAL — the display's everything-added reading is the diff's answer, but an adopt is a whole-state replace, and two files from a commit plus one from nowhere composes a state no checkpoint ever was. Every refusal is the editor's red-flash with typed text preserved plus one stderr line, first-error-only, nothing touched — a legacy-format commit fails here BY DESIGN.

The apply mirrors `adopt_render_entry` step for step (settings.md owns that sequence) and drops exactly: the WAV existence check (the corpus stores no audio — the loaded source IS the source), and the `renders/` wipe with its running-batch guard (the guard protects the wipe's race; this path wipes nothing, and a render live from before `/` renders its request snapshot untouched). One cross-file undo entry, dirty set — auditioning then Ctrl+Z back is the point. The mode closes as part of the act (the frozen now side no longer matches the live state). Autocomplete Tab is a consumed no-op in the mode (render-entry identifiers are the wrong vocabulary). Outside the mode, `'` and the commit editor are byte-identical to before.

## The commit act (round 5)

Ctrl+Alt+R while the mode stands IS the checkpoint commit — the iteration-mode precedent exactly, the mode bit selecting the command inside the one render route; outside the mode the chord is byte-identical to before, and Ctrl+Alt+Shift+R stays consumed in the mode. The Render button wears the act (label "Commit", Icon::VcsCommit — the row's second stateful string, after "Render Iterations") and dispatches through its existing chord. The product's FOURTH PROMPT confirms (case-sensitive `[Y]es`, Esc through the prompts' existing binding, the prompt class's playback stop; the title is never asked — always `Update <id>`).

The act: the three sidecar byte strings are REBUILT FRESH via `build_history_now_side` (the session's frozen now side provably drifts on the settings file — the per-tab view band moves under the mode's own allowed navigation — and the fresh rebuild is also what makes the after-commit empty diff true), written into the matched `projects/<id>/` directory through the atomic writer, then a pathspec-scoped `git commit -m "Update <id>" -- <the three paths>` (foreign staged work can never ride along) and `git push`. VERDICTS ARE REPOSITORY OBSERVATIONS, never child status (the SIGCHLD regime): commit = `rev-parse HEAD` before/after, push = the remote-tracking ref catching up, and a pre-flight `status --porcelain` names the NothingToCommit non-failure distinctly. Push hardening: stdin /dev/null + ssh BatchMode, so a credential prompt fails in one line instead of freezing the GUI. A push failure after a landed commit says so distinctly — the checkpoint exists locally and the HEAD-based walk shows it. Success re-inits the session in place (`open_history_mode_fresh`, the one mode-entry owner): the walk heads at the new checkpoint, index 0, and the lane reads an EMPTY diff — the visual confirmation. THE MODE STAYS OPEN (architect). The program embeds no identity and no credential: author and transport are the machine's git config and SSH setup.

## Accepted costs and open items

- A render launched before `/` hides its progress line (the mode's corner line outranks it) and cannot be Esc-cancelled until the mode closes (Esc is not on the allowlist; admitting it would not add a seventh Esc place, only let existing bindings run — one term if the architect wants it).
- `paint_bottom_strip`'s `delta_at` can in principle run git on a commit's first visit; in practice on_tick's cache rebuild reaches the index first.
- Basename matching cannot see across a source rename (above).
- A READ-ONLY ACTIVE TAB blocks `'` (adopt) AND Ctrl+Alt+R (the commit act) in the mode as it does outside it (neither is on the read-only allowlist, and that gate sits below the mode gate) — inherited, unchanged, awaiting an architect ruling if the mode should be tab-lock-agnostic for either.
- Every checkpoint committed BEFORE this arc refuses adopt today (none carries `gui_scale`; one still carries `font_size`): the strict gate working as ruled. Adopt becomes useful from the first checkpoint committed by this build. Relatedly, the corpus's on-disk `550 - 1` settings file is itself load-invalid for the same reason — the architect's to refresh.
- This clone's `git config user.name` is literally the string `user.email` (a config slip, found round 5): commits the product makes carry it until the architect fixes the config; the act uses the machine's identity by ruling and touches no config.
