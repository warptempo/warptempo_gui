# The Kdenlive Redesign (row-by-row)

Chartered 2026-07-30, implementation began 2026-07-31. The architect works TOP-DOWN, row by row, by dropping screenshot crops into `tmp/screenshots/kdenlive/redesign/` and pointing the planner at them — every state a surface has (rest, hover, clicked, ...) gets its own crop. Do not run ahead of the screenshots. Design parity is "loosely held, with room for tailoring to our needs"; workflow parity stays Ableton. Design and testing happen at 100% `gui_scale`; 1920x1080 remains the only supported resolution.

## The standing rulings (apply to every row)

- THE SCREENSHOTS OVERRIDE ALL PRIOR COLOR WORK (architect 2026-07-30/31). The colors.conf tunable domain is SHRINKING to the WAVEFORM AREA AND THE MARKERS (canvas ground, waveform ink, marker classes); every other color a redesign row touches is HARD-CODED from the sampled crop — constexpr, not a key, not in the config grammar. An existing surface keeps its tunables until its own redesign row retires them; no key deletion happens ahead of that. The recorded carve-out lives at render.h's palette-block header.
- THE SANS FACE IS THE REDESIGN'S DEFAULT FAMILY: cairo toy selector "sans" (fontconfig → Liberation Sans on the target) at 12pt through the existing points×4/3 convention (16px at 100%). The monospace face survives on every un-redesigned surface; each row moves its own text over.
- ALL REDESIGNED TEXT GOES THROUGH THE SHAPING CHOKEPOINT (`src/gui/text_shape.h`, HarfBuzz over the cairo font's own FT face): the shaped run is the single width truth — measurement, paint, truncation and hit geometry all read the same run. No Pango, no cross-font fallback, no bidi — one wide-coverage face is the model.
- REDESIGNED DIMENSIONS RIDE THE gui_scale AXIS (`gui_scale_factor()`, render.h), NOT the monospace font's `gui_font_scale()`. The two axes are independent by design — the ruling and the push plumbing (three application points, mirroring font_size) are at the accessor's declaration. Crop-measured 100% values are the authored constants; every conversion rounds with std::nearbyint. Fills land on integer pixel bounds; axis-aligned 1px strokes, when a row ever has them, take the cairo +0.5 half-pixel alignment so nothing axis-aligned antialiases.
- HIT GEOMETRY IS PUBLISHED BY THE PAINTER where a rect depends on shaped text (the displayed-basis doctrine applied to proportional surfaces): the painter stashes the rect it painted; pointer code reads the stash and never re-shapes.

## Row 1 — the menu row (landed 2026-07-31)

Source crops: `row_1_button_{rest,hover}.png` (46x30). The new TOP LANE 0 (kTopLaneCount 5→6, every prior lane renumbered +1; `top_menu_row_area`, `menu_row_h_px` = 30 at 100%): full-width flat ground #292c30 (the rest crop's first column — a DELIBERATE mismatch with kBackground #202326, the crop wins), no ring, painted in `GuiPaintHandler::paint_menu_row` OUTSIDE the loading/total>0 branches (the one audio-independent surface: visible exactly whenever it is clickable), gated on its own exposure so per-frame scanner damage never pays the HarfBuzz shape.

THE QUIT BUTTON, the row's sole content: label "quit" (all-lowercase per the program-text rule), sans 12pt, #fcfcfc in BOTH states, flush left, 10px padding per side — button width = nearbyint(shaped width) + 2·pad (46 at 100%, matching the crop), baseline solved from the face's own extents (row.y + (h + ascent − descent)/2), never a literal. TWO faces, not three: rest = bare label on the row ground; hover = a filled #3daee9 pill (full button width, 1px vertical inset → 28 tall, corner radius 5, arc-path fill, corners AA exactly as the crop shows) under the unchanged label; A PRESS PAINTS NOTHING NEW — a click keeps the hover face, pointer-out rests it. Hover state is `app.menu_quit_hovered`, recomputed in on_motion's no-gesture tail against the painter-stashed `app.menu_quit_rect`, cleared by the pointer-leave hook; transitions pay one `invalidate_top_strip` each (the strip idiom — no narrow rects). An active gesture freezes hover (the tail doesn't run); both cold states (zero stash, pre-motion (−1,−1) cursor) resolve to not-hovered with no special case.

THE PRESS CLAIM sits ABOVE the `app.loading || total_frames() <= 0` guard in on_button_press (quit stays live during load and on a blank state) and BELOW the modal gates (a prompt or bottom-strip editor swallows the press exactly as it does for every other pointer target; Ctrl+Q reaches the same route from the keyboard anyway). Band semantics are the zoom-row precedent verbatim: modified press = strict consumed no-op; plain left press inside the stashed button rect fires ON PRESS — `finalize_active_drags()` then `prompt.request_close()`, the WM-close ordering, which is Ctrl+Q's exact route (the unsaved-work prompt gates on dirty inside request_close); any other press in the band is a consumed nothing. Nothing in the row drags; there is no arm, no threshold, no release body, no press-state machinery.

Accepted/open at row 1: the wheel over the menu row still resolves to the top-strip context (it zooms) — flagged for an architect ruling; the baseline formula's exact value at 100% is a .5 rounding tie (nearbyint lands it at 20 of 30, reconciling the crop's 1-indexed row 21).
