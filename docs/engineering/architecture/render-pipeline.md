# Render Pipeline (parser compilation, driver geometry, trim stage, dispatch/cancel)

Moved verbatim from CLAUDE.md in the 2026-07-25 slim-down (project feature-complete). This file is now the authoritative home for this detail; CLAUDE.md carries only a digest and a pointer here. Keep it current with landed rulings.

### Parser Owns the Phase Reset Compilation
The parser is the sole authored-to-engine compiler on both columns; the engine consumes only engine-domain inputs — blind to the `N/2` query-origin correction. A phase reset fires exactly at the authored frame: there is NO anticipation offset, no target-domain displacement, and no lead-in dropzone in the parser or engine (the RENDER-TIME offset concept is removed product-wide; the surviving `N/2` uses are all GUI-side and paint/authoring-only — the forward-pointing overlay width, a paint-only two-hop constant in `paint_handler.cpp`, and the target-view lead-in gestures, both now BARE (architect 2026-07-28): bare `s` — the only phase-reset drop there is — AUTHORS a reset at `max(0, playhead − N/2)` (a target-time seed snapped to the nearest whole source frame), and bare `Space` AUDITIONS playback from `playhead + N/2` whenever the phase-reset overlay has a subject (`Selection::phase_overlay_subject`, the selection-state predicate — never the painted band, whose geometry gates would let a scroll or zoom change what Space does). The two N/2 offsets are deliberately inverse, so drop-then-Space auditions from exactly where the cursor was; the authored frame stays a whole source frame the parser fires exactly at, so engine and parser remain offset-free). Phase reset markers are stored at user-clicked/onset positions as whole int64 source frames (`.phaseresetmarkers`, the authored domain). `build_phase_reset_source_frames` (parser) widens each exactly into the double intermediate — and remains the chokepoint applying the past-EOF wall refusal and the exact-equal collapse (equal-frame enabled resets are one event; one stderr line per collapsed timestamp); its output is the authored intermediate used by target-view display (the phase-reset overlay) and the derivation. `derive_phase_reset_frame_map` (parser, `phase_reset_frame_map_build.h`) compiles that intermediate into the engine's origin-centered query domain, always against the FULL map (the parser knows nothing of trim): each position forward-maps to its target image ONLY for the render-end participation verdict (a reset at or past the map's final anchor target drops), then is emitted directly as `S - N/2` — no inverse mapping. The `N/2` is a coordinate-domain correction conforming to canonical PGHI (docs/references/ltfatnote050.pdf: the STFT window is concentrated around the origin, so an analysis position is the window's CENTER), and a reset whose window centers at authored frame `S` has query position `S - N/2`; a reset at frame 0 derives to `-N/2`, the engine's first analysis frame — inert but harmless. Doubles throughout; quantization to the engine's integer query schedule is engine-owned at placement time. The `.phaseresetframemap` artifact is that full derivation against the exact map shipped beside it, so the cache-dir framemap pair is exactly the engine's input, consumed as-is. Trimmed renders take the same full derivation through the prepost trimmer's translate/filter (`plan_trim`), never a separate windowed derivation. Authored-domain surfaces stay authored: marker files, GUI paint positions, and render-entry sidecars carry the user-clicked onset position (a whole int64 source frame; the parser and engine intermediates are the only doubles) unchanged.

### Driver Geometry
The shared geometry contract — `N` and the synthesis hop `R_s = N/4` — lives in `engine_geometry.h` (`kN`, `kRs`); production `N = 4096` yields `R_s = 1024`. The engine consumes BOTH constants directly: `stft_container.h` pins `N = kN`, `M = 2N`, and `R_s = kRs` as compile-time constants (the runtime-N parameter, its per-init derivations, and its validator were removed 2026-07-17 — N and R_s stay symmetric, both from the geometry header). The orchestrator-side parser/prepost stages (`derive_phase_reset_frame_map`, `plan_trim`) still take `N` as an argument, and every driver hands them `kN`.

### Trim is a Prepost Stage
Trim is a transient inspection tool for auditioning a segment, not an archival deliverable (accepted caveats: head phase is wrong until the first phase reset marker; the tail may fade over `R_s` multiples). The pipeline is: parser builds the FULL maps (knows nothing of trim) -> trimmer `pre_trim` for a PROPER SUB-WINDOW only (`plan_trim` in `src/prepost/trimmer.h` — the trimmer REQUIRES both bounds; under ALWAYS-SET trim (architect 2026-07-30) the store always holds a full ordered pair and the FULL WINDOW [0, total-1] takes NO TRIM PLAN AT ALL, rendering untrimmed through the shared predicate `trim_window_is_full` (settings_file.h) at all three orchestrators — a (0, total-1) pair through the trimmer would NOT be byte-identical to untrimmed, the crop fires and the authored end-wall drops the last frame's target span, so the translation is load-bearing; lone bounds and the orchestrator completion are deleted with the unset state ((0, X) trims only the tail — zero head cut, the head-phase caveat vanishes — and (X, total) trims only the head, tail coinciding with the full render's): validates first — a refusal is interpreted by both orchestrators as "render untrimmed" with one stderr line, never a failed render — then cut source view + translated maps) -> engine (trim-ignorant, renders its map wholesale, emits its map's extent; for trimmed renders it also ADOPTS the plan's precomputed source-frame schedule — derived by `plan_trim` from the FULL map's own evaluations and translated by the integer cut, so schedule identity with the full render holds by construction rather than by re-interpolating the translated map; `EngineParams::source_frame_schedule`, count/order-validated, null on full renders) -> trimmer `post_trim` (crop to the exact authored window; `apply_post_trim` returns `expected` and REFUSES a crop the emission cannot supply — internal-breach policy, never zero-fill) -> peak limiter (unconditional; lifted out of the engine, lives in `src/prepost/`) -> encode. Full renders bypass both trimmer stages. The engine is buffer-out only; encode and the shared post-engine chain (`finish_render`, returning `FinishRenderStatus` with an optional cancel flag checked at stage boundaries — the GUI passes it, the CLI passes null) are orchestrator-side, one implementation compiled by both the GUI and `warptempo_cli`. The null condition (a trimmed render phase-inverts to null against the full render past the first phase reset, through the last kept sample) is carried by the hop-multiple target re-anchor plus the by-construction schedule; it is a PHASE/SYNTHESIS contract — the peak limiter when it engages, and the spectral limiter's nonlocal per-peak decision layer, sit outside it by architect ruling (recorded at `plan_trim`, whose comment block carries the full geometry derivation). Trim is a render window on the wav (the only product); the cache-dir framemap pair is always the FULL maps, untouched by trim.

### No Subprocesses in the Render Pipeline
The render path invokes no subprocesses. All DSP runs in-process via the engine sources. (The one product subprocess is OUTSIDE the render path: the `l` command's posix_spawnp of the external `audio_player`.) The former `adapters/` reference folder was deleted from the repo 2026-07-15; git history preserves it.


### Render Dispatch Kills the Running Render
A render dispatch kills the running render, unconditionally (the former session-fingerprint match-wait — where a dispatch identical to the running render waited and adopted instead of killing — was removed as over-engineering; a preview that would have matched now simply re-derives through the reuse rungs below). Archival commands (Ctrl+Alt+R, Ctrl+Alt+Shift+R — the miscellaneous single-cell render into renders/<N>_miscellaneous, appending to the most recent misc folder or creating the next-index one; batch folders are N_iterations / N_bpm / N_miscellaneous — and the iteration and bpm sweeps) kill via the Esc-cancel semantics (request_cancel + queue_cancel_requested) and park the fully built request set in the one-slot `pending_archival` (newest command wins), pumped at worker idle AHEAD of the pending preview (a command outranks a derived preview; the preview defers behind the new session and re-derives after). Target-view preview triggers kill too (source view never triggers — archival renders run in the background there); the preview then re-derives at worker idle and may reuse an identical completed render through dispatch_render_now's two reuse rungs (render_cache — archival completions publish into it synchronously — then the on-disk artifact against its .fingerprint sidecar), avoiding a second synthesis when the inputs are unchanged; the reuse rungs are LOAD-BEARING for the unconditional-trigger model — undo/redo is a COMMON event and its dominant shape is A->B->A, which the cache absorbs (architect 2026-07-17: a proposed cache removal was rolled back for exactly this). THE FINGERPRINT'S PHASE-RESET COMPONENT IS TRIM-AWARE (2026-08-01, closing the spurious out-of-trim re-render the architect reported as the "Updating..." flash): the key serializes the reset set that ACTUALLY REACHES THE ENGINE — under a surviving trim plan, plan_trim's own translated range-filtered list (the trimmer's column asymmetry: point events outside the window filter away); a full window or a plan_trim refusal keys the full set, mirroring the untrimmed engine input. Both fingerprint sites take it — do_render's arm IS the plan optional itself (never a re-derived predicate), and compute_live_render_fingerprint mirrors by CALLING plan_trim over the memoized target-view map (no second arithmetic; a hand-rolled boundary margin would be the one unsafe direction, a wrong-bytes hit) — cross-site identity argued at the live site. NO version bump, by the trim_window_is_full old-bytes precedent (same engine input = same key); the per-keystroke plan_trim under a proper sub-window is the recorded accepted cost. So an out-of-window reset mutation (nudge, drop, delete, disable, drag commit, undo) keeps its fingerprint, hits the cache synchronously, and neither renders nor flashes. Batch-internal continuation is one session; Esc disarms the parked slot along with the running render; killed sessions may leave partial batch folders (accepted — renders/ is transient, wiped wholesale at a `'` commit). A killed session can never publish Success: `do_render` checks the cancel flag before every final-name publication and after every expensive stage, `finish_render` takes the optional flag at stage boundaries (including after the buffer route's in-place PCM24 snap, before Completed), the limiter checks through its pre-queue phases and per-peak loop, and the engine re-checks the raw flag at pass boundaries and before its Success return. The target-buffer route gates twice more: `insert_master_floats` threads the per-dispatch session cancel token into the cache (the token is created fresh per dispatch and never reset, so the writer thread's own loads name exactly the dispatching session; the job drops at `start_writer_job`'s post-join check or at the writer thread's post-encode re-check, both before anything goes externally live) — and a final buffer-route check ahead of `finish_success` keeps a cancelled preview from ever binding its abandoned buffer. Every publication stages then gates: the reuse rungs re-check between the byte copy and the rename. (The cache-dir framemap pair is deliberately ungated — inert future-proofing files, not deliverables; a cancelled render's pair is swept.) Two accepted tails: once the wav has renamed to its final path, the sidecar/cache finalization completes — the publication gate sits before the rename, and finishing an already-published artifact's attestations beats deleting it — and a master-floats cache writer whose session cancel lands only after the writer's post-encode check completes its write (the entry is a complete, fingerprint-consistent render; Success is still refused). Batch completion no longer auto-opens anything (the in-app render-view player was removed, and with it the WAV-only auto-open and its `batch_.wav_browseable` gate): a finished batch just leaves its artifacts on disk, to be auditioned in an external player via `l` or adopted via the `'` commit editor.
