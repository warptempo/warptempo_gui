### Gesture Commits are Pixel-Anchored
Every pixel-stepping POSITION gesture (the Alt+Left/Right nudges in each column's home view — warp in source, phase reset in target; in W+TARGET Alt+Left/Right is the tempo-image step, which authors CENTS through the drag's solve, not a column time) anchors to the on-screen column grid: read the item's currently PAINTED column (`painted_column_of_source_frame`, the stem painters' own math), step by whole columns, commit that column's time (`authored_frame_at_column`, which funnels through `snap_authored_frame`). The painted move is exactly the commanded number of columns per press, unconditionally — the whole-frame rounding error is just under 0.291 px at the deepest zoom under the value brackets and the 44100 floor (0.5 / 1.72265625 at the exact bracket edge — codex round 1 corrected the older "at most 0.29" wording, which was not a strict bound), and re-anchoring each press means nothing accumulates (per-press independent rounding would paint occasional 0/2 px jumps). THE ONE-COLUMN GUARANTEE IS A GRID-FINENESS PROPERTY, not a gesture-family property (architect 2026-07-24, the lesson of the min-step churn): it holds because the authored FRAME grid is finer than the pixel grid (≥ 1.72 source frames per target pixel at the deepest zoom, so every adjacent-column target is representable); the W+target tempo-image step authors CENTS, a grid COARSER than pixels on ordinary spans (one cent moves the image ~2+ px), so the guarantee INVERTS there and the minimum-step rule owns that gesture's step size — one column per press applies to the POSITION gestures only. Mouse drag commits snap the release to its painted column (frozen-map coordinates; stored equals shown), uniform in both views at all zooms; mid-gesture positions stay free. GROUP drags column-snap the GRABBED member ONLY (codex round 3): every other member is a COMPUTED position riding the grabbed member's uniform active-domain delta D = fwd(committed_grabbed) − fwd(original_grabbed) through `snap_authored_frame` (the propagate-paste plain-rounding convention — per-member column snapping re-quantized the group's spacing by up to a column at coarse zoom), which in source view is exact integer rigidity (committed_k = original_k + D) and in target view is displayed-domain rigidity matching the motion (source spacing preserved to ±1 frame, the integer store's limit), the per-member integer walls staying the backstop; the commit D additionally CLAMPS into the motion's active-domain wall intersection (codex round 5) — the grabbed member's column snap could overshoot the edge the group stopped at by up to half a column and re-squash the group through D — and when that clamp engages D BECOMES the clamped value verbatim and the grabbed member RE-DERIVES from it by plain snap_authored_frame rounding, NO column snap: walls win over the grid at the group intersection, stored-equals-shown deliberately yielded for that one saturated case — and D is NEVER recomputed from the re-derived frame (codex round 6, the re-quantization trap: fwd(rounded grabbed) − fwd(orig) re-snaps D onto the grabbed member's local slope grid, up to ~half a bracket-legal slope-16 segment's step, escaping the intersection again; consistency is every member, grabbed included, being the plain rounding of the ONE rigid formula, not D matching the grabbed frame's exact displacement). The motion loop's verbatim short-circuit likewise tests the CLAMPED delta, not the raw pointer delta (codex round 6: an outward drag of a half-offscreen flag clamps to zero effective motion but a raw-delta test would write two-hop residue and let commit column-snap a forbidden inward jump). Walls win over the grid everywhere (walls are integer frames). Propagate paste rounds plainly WITHOUT pixel anchoring (computed, view-independent positions — recorded at the site). Wall semantics are one regime per column under the home-view binding (see that paragraph): each column's POSITION nudge runs in its HOME view only (the 2026-07-24 "third exception" — a both-views warp position nudge — was RE-RULED AWAY the same day: no warp position authoring in target view; in W+target Alt+Left/Right is the TEMPO-IMAGE STEP instead, see the home-view binding): warp nudges in SOURCE view clamp the group's rigid delta into the member wall-headroom intersection (creep-to-the-wall as a unit, walls exactly reachable; a singleton degenerates to the per-marker clamp bit-for-bit); phase-reset nudges run only in target view with the all-or-nothing mapped-domain silent refusal — one regime per column at its home.

The waveform's EFFECTIVE width is quantized to a multiple of 16 px (`waveform_area` floors `a.width` to `w - (w%16)`, leaving a ≤15 px inert right gutter that `render_background` fills automatically over the full-width damage). 16 = `1600/gcd(44100,1600)`, the strictest grid step among standard sample rates (every standard rate's step divides 16), so at a multiple-of-16 width `logical_spp·W` is integral at every INTEGER numeric zoom level and `painter_samples_per_pixel == logical_spp` exactly there — making the GUI's pixel-anchored grid coincide with the migration tool's frame-0 grid regardless of the compositor-configured width. (The zoom level is a CONTINUOUS double as of 2026-07-19 — see the zoom paragraph below; a fractional rest rides the painter quantization `nearbyint(spp·W)/W`, and the bit-exactness claims hold at the integer rungs, notably the working zoom (2.0) every snap gesture lands on.) All grid consumers (the plate/flag caches and the live trim pass, `samples_visible`, the viewport snap, pointer placement, pixel-anchored commits, and the flag/chip column mapping + hit-test — the last threaded a `waveform_width` param through `iterate_visible_flags_impl` so chips never drift from stems) route through `waveform_area(a).w`; only strip backgrounds and invalidation damage use the full `a.width`. No-op at the deployment widths (1920/2560/3840 are all multiples of 16).

The VIEWPORT itself is snapped to whole-pixel (grid) boundaries at numeric zoom levels — the single chokepoint is `clamp_viewport_start` (main.cpp), which every viewport mutation already funnels through immediately after writing `viewport_start_sample`. It snaps to the nearest grid point using the SAME `painter_samples_per_pixel` (now a declared free function in `warp_frame_map_view.h`, shared with `authored_frame_at_column`), then clamps into `[0, max_start_grid]` where `max_start_grid` is the smallest grid point ≥ `max_start = total − visible` — so the FLUSH-RIGHT viewport also rests on the grid, showing <1 px of inert padding past EOF (subsumed in the last painted column; `get_peak_range` clamps past-EOF reads to silence, so no paint change). This is what lets an exact-grid marker commit stay valid at maximum scroll. The snap runs at EVERY level (the retired fit-file mode's skip is gone; at the effective zoom-out ceiling max_start ≈ 0 and the snap parks the start at 0). Consequence: source-view marker and click-playhead commits land EXACTLY on the frame-0 authoring grid (no ±1 residue), via the shared single-rounding basis `source_grid_position_at_column` (`warp_frame_map_view.h`): recover the grid-snapped viewport's column index `m = nearbyint(viewport_start/q)` and round ONCE, `nearbyint((m+col)·q)`, instead of the two roundings `nearbyint(viewport_start + col·q)`. Both `authored_frame_at_column`'s SOURCE branch (guarded `ctx.domain==Source`, funnels through `snap_authored_frame`) and the two click→playhead sites (a shared `playhead_frame_at_click_column` in input_pointer.cpp) use it, so click-drop, drag, and nudge cannot drift. So GUI zoom-level-2 authoring agrees with the migration tool's frame-0 grid BIT-FOR-BIT (the ±1 became 0 once Phase A/B guaranteed every rest viewport is a true grid point). The m-recovery is exact for product-reachable audio lengths (at the deepest numeric zoom `q ≥ ~27.5` frames/px, far above the double ULP), NOT over the whole int64 range. `painted_column_of_source_frame` is UNCHANGED and the round-trip `painted_column(authored_frame_at_column(col))==col` still holds (`|residue| ≤ 1/q < 0.037` px). Target view keeps its inverse-map form (no source-grid claim). The playhead is NOT snapped except at a click; arrow-key fine-tuning (`move_playhead_pixels`) still authors off-grid, deliberately. This made the continuous-pan fractional-sample accumulator redundant — it was removed, and the Alt+drag scroll-drag itself is RETIRED outright (2026-07-19; pan lives on the strip rows — see the strip-row paragraph below), whose drags likewise apply an absolute viewport per event and let the snap re-anchor.

ZOOM IS CONTINUOUS (Ableton-style free rest, architect 2026-07-19): the zoom level is a real-valued DOUBLE exponent resting anywhere in the ONE continuous domain `[kMinZoom, kMaxZoom]` = [1.0, 17.0] — the fit-file 0.0 SENTINEL is ELIMINATED (legacy of the retired digit-key zoom era; there is no fit MODE, no sentinel branches anywhere). ms-per-pixel = `0.625·2^(level−1)` (computed in `samples_per_pixel_at`; the table is deleted), so integer rungs reproduce the historical 2x ladder bit-for-bit. `kMaxZoom` = 17.0 is DERIVED from audio_io's structural source caps, not invented (derivation at the constant, settings_file.h): the RIFF uint32 data limit bounds any loadable source at ≈16232 s (24-bit stereo at the 44100 floor), and 17 is the provably smallest whole level covering that at the 640 px minimum window. The EFFECTIVE per-file ceiling is `effective_max_zoom_level` = `clamp(1 + log2(total·1000/(0.625·sr·width)), kMinZoom, kMaxZoom)` — the fit-equivalent level, where spp·width == total — so FULL ZOOM-OUT RESTS AT WHOLE-SONG-VISIBLE for every loadable file (a multi-hour file just gets a coarse pyramid plate); the ceiling is a GUI-runtime clamp (tick reclamp + on_resize), deliberately NOT schema-checked. `kWorkingZoomLevel` = 2.0 (RENAMED from kSnapZoomLevel — say "working zoom", not "level 2") is the ruled fine-tuning zoom where the authoring-grid bit-exactness claims hold: `c` and the bare `0` toggle land EXACTLY on it. `0` toggles working zoom ↔ full zoom-out (the effective ceiling; `run_zoom_toggle_command`) — and since the chip-row framer dropped its whole-song arm (2026-07-27) it is the ONLY route to full zoom-out. Manual steps (`=`/`-`, plain wheel via `zoom_steps`) walk ±1.0 whole level from the current — possibly fractional — rung, no integer snapping, saturating constructively at the floor (recenter-on-playhead at the floor) and the effective ceiling. `c` = MARKER JUMP + WORKING ZOOM: with a focused marker it first jumps the playhead DIRECTLY onto it via `jump_playhead_to_focused_marker` — the factored Tab-family tail, and the Tab family and this one command are the ONLY routes that land the playhead exactly on a marker — then snaps to the working zoom and recenters; with none it keeps snap-and-center-on-playhead. `tab_X_zoom` persists as a DOUBLE under the min-0 `format_value_double` round-trip gate with vocabulary exactly `[kMinZoom, kMaxZoom]` (settings_file.{h,cpp}, architect-granted frozen touches; a stored `0` REFUSES — pre-release ruling, no migration, the architect hand-edits old files; the default and first-open template write `2`). The LIVE level can never rest above the effective ceiling — the clamp lives at the TOP of `clamp_viewport_start` (`clamp_zoom_level`, main.cpp), the one chokepoint every zoom write already funnels through immediately after assigning, with `apply_zoom_change` pre-clamping its request so a ceiling-bound `c`/`0` is a true no-op; the tick and on_resize reclamps keep only trigger + side-effect roles and delegate. PARKED bands are the deliberate exception (ruling 2026-07-20): an inactive tab's zoom commit stores the schema-legal request VERBATIM and Ctrl+S serializes it — the ceiling is width- and domain-dependent, so a store-time clamp against today's context could destroy a value honorable at activation; parked zoom is display-scratch like the persisted viewport/playhead, and the activation-time chokepoint is the sole owner of honoring it.
