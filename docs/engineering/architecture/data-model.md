# Authored Data Model (frames, tempo cents, value vocabularies)

Moved verbatim from CLAUDE.md in the 2026-07-25 slim-down (project feature-complete). This file is now the authoritative home for this detail; CLAUDE.md carries only a digest and a pointer here. Keep it current with landed rulings.

### Authored Domain is Whole Source Frames (int64_t)
Authored positions — marker times on both columns and both trim bounds — are whole source frames held in `int64_t` everywhere at rest: in-memory stores, sidecar files, walls, validators. A fractional authored position is unrepresentable by type; mid-gesture positions are free doubles, and `snap_authored_frame` (`app_state.h`: banker's `std::nearbyint`, then exact cast) is the ONLY double-to-authored conversion route in the product tree — every gesture commit funnels through it (the standalone migration tool carries its own equivalent `nearbyint`). Ties are real at 44.1 kHz (the 5 ms zoom level is 220.5 frames/px, a half-frame tie on every odd pixel), so banker's is load-bearing. There is no seconds or millisecond-grid representation anywhere in the data path; MM:SS.mmm timestamps are display-only renderings (`format_timestamp(frame / sr)`) on GUI text surfaces. ONE serialization domain in `src/parser/frame_format.h`: the AUTHORED pair (`format_authored_frame` = plain integer text, `parse_authored_frame` = the CANONICAL spelling only: digits, no sign/point/exponent/leading zeros, int64 overflow refused — the spelling IS the grammar; the migration tool guarantees corpus canonicality) is the single on-disk position form, and any other position text — fractional, negative, non-finite, or a non-canonical integer spelling like `44100.0`/`6e+05` — is adversarial load-fatal. (The old RENDER-DISPLAY pair and the `.renderwarpmarkers`/`.renderphaseresetmarkers` sidecars are retired: positions on a render's target axis are computed live by the GUI through the snapshot map and never serialized.) Walls are exact integer comparisons — every authored position, both marker columns and both trim bounds, shares the one inclusive `[0, total-1]` domain (the trim end's former exclusive `total` wall was unified 2026-07-18; an end bound stored at `total` is adversarial load-fatal, no migration) — literally the same compare at gesture time and at the adversarial load guard. Field naming is `*_frame`.

Authored TEMPO is 100-based INTEGER CENTS held in `int64_t` everywhere at rest — the value-domain sibling of the frames ruling above; an off-grid or fractional tempo is unrepresentable by type. Its bracket is `[kTempoMinCents, kTempoMaxCents]` = [25, 400] (i.e. [0.25, 4.00]), exact integer compares at every bracket surface. The `N.NN` spelling (one-plus digits, one dot, exactly two decimals, no leading zeros) is the TEXT INTERFACE only: `format_tempo_cents` / `parse_tempo_cents` (`value_format.h`) are the single serialization pair (direct digit-to-cents, no strtod, byte-identical to the historical min-2-padded form), and `tempo_from_cents(int64_t)` — double overload deleted — is the ONE cents-to-double boundary, crossed at exactly four sites: the DSP slope product (`build_warp_frame_map`), the fingerprint f64 compatibility encoding, the bpm derivation's scale divisor, and the label-ref hover multiplier. Every OTHER value is a double via `src/parser/value_format.h` under BRACKETED vocabularies (the constants there are the SoT): both scales `[kScaleMin, kScaleMax]` = [0.5, 2] (multiplicatively symmetric; the floors bound the resolved product to >= 1/16, which the pixel-nudge guarantee is computed from; scale staying full-double is the recorded tempo/scale asymmetry at the WarpMarker struct), bpm `[10, 400]`, `bpm_beats` int in [1, 9999], iteration deltas in [-400, +400] integer cents (session-only, never serialized; the iter-bracket text commit additionally red-flashes when base tempo plus either bound leaves the tempo bracket — the endpoints bound every cell). Iter state has a hard lifecycle: exiting iteration mode wipes every bracket, and the exit routes are THREE, re-derived by grep on `wipe_iter_state` 2026-08-07 — the `i` toggle's OFF branch, `enter_bpm_mode`'s forced iter-off, and the iteration sweep's success tail — all through the one chokepoint `GuiFlagEditor::wipe_iter_state` (Shift+I is retired; the S→T audio-view toggle LEFT this list on 2026-08-07 when iteration mode became target-legal, and the mode and its brackets now survive the view switch in both directions — tempo-and-home-view.md carries the ruling and the granted target-view exception the first and third routes take; exiting the mode IS the clear; the wipe pushes one undo entry, so plain undo may deliberately restore a bracket set). Tempo changes NEVER clear a bracket (architect 2026-07-19, reversing the earlier tempo-step clear): the flag editor's manual tempo commit and the bare Up/Down step both leave the adjusted marker's bracket in place — a later tempo change under a live bracket is deliberately not re-gated, staleness accepted, backstopped by `build_warp_frame_map`'s refusals (async stderr) and the strict promote parse at the `'` load-in-place. Eligibility LOSS does clear, at both authoring surfaces: Ctrl+N's owner→pass and ref→pass branches reset the marker's bracket in the same undo entry, and the flag editor's commit unconditionally resets the bracket whenever the committed marker is iter-ineligible (regardless of iter grammar or mode, covering a pass/ref payload committed with bracket text left in place and the mode-off conversion of an undo-restored bracketed owner) — so a hidden bracket cannot resurrect through a later pass→owner freeze against a different frozen base; undo is the one sanctioned restore route. BPM state (owner, beats, bounds, endpoint — likewise session-only, never serialized) has the same hard lifecycle: it wipes history-less on every bpm-mode exit (the exit_bpm_mode chokepoint, all off-routes funnel there) and on sweep dispatch (render_bpm_sweep's success tail wipes and closes the mode; a guard-bailed sweep deliberately keeps values and mode for correction), so re-entering either mode always seeds blank. THE SECTION RULE (arc step 5, architect-designed 2026-07-23) governs the `m` sweep and both propagate spans: a marker OWNS the section from itself to the next store marker, the STORE-FINAL marker's section running to the SONG END — WITH ONE 2026-08-01 QUALIFIER FOR THE TWO PROPAGATE SPANS ALONE: their extent is the EFFECTIVE-PARTICIPATION form (`section_end_frame`, phase_reset_propagate.cpp — the next EFFECTIVELY-ENABLED marker, else the song end), because a disabled marker is dropped before the warp map is built and is not a render boundary; its span belongs to the preceding enabled marker, so the resets under it copy, clear, and paste with the section they musically belong to (the old next-in-STORE extent left that span owned by nobody — the architect's reported drop — and silently mis-scaled captured resets against truncated durations). The `m` sweep DELIBERATELY KEEPS the raw store-index form (span-based, `bpm_endpoint`, disabled markers inside the span convert per cell) — the `m` gate takes a non-empty CONTIGUOUS run of selected markers (first = owner; `bpm_endpoint = last+1`, == store size being the song-end sentinel through the commit gate, the sweep, and the descriptor; every selected section included, the old excluded-endpoint-section model retired), the Ctrl+P copy takes the SAME non-empty CONTIGUOUS run (codex round 4: the paste's lockstep label matching assumes one contiguous label sequence, and unlabeled gaps align on both sides; effective-disabled selected markers contribute no block), the paste destination walk gives the store-final ENABLED labeled marker the same song-end extent (its EOF clamp load-bearing; since 2026-08-01 a labeled marker trailed only by disabled ones owns to the song end too — the newly reachable branch of the same guard), and disabled markers are excluded from bpm eligibility (`bpm_popup_eligible_marker` gains !disabled — for an owning marker raw equals effective, the cascade only reaching refs). Out-of-bracket on disk is adversarial load-fatal (the GUI can never author it); typed values red-flash at editor commit; the bpm derivation refuses (never clamps) an out-of-bracket derived tempo or scale; sweep per-cell computed mutations are deliberately unbracketed (async stderr backstop at `build_warp_frame_map`). `playback_speed` is preset-vocabulary-only on disk (the ten one-decimal speeds 0.1..1.0, `playback_speed_presets.h` SoT — parser-side, so the settings schema enforces membership in BOTH binaries; membership is by exact TEXT against the writer's %.1f spellings, each paired with its nearest-float for the live store — no float parse at the boundary; any other spelling hard-fails the source load — the GUI can only author presets). The Shift+digit gesture is REMOVED: the settings editor is the sole authoring surface (`:playback_speed=`, preset membership red-flashed at commit), the default is 0.7, and a set made in target view STORES only — target playback stays at natural rate; the value becomes audible on the return to source view because every launch re-applies from `app.playback_speed`. Writing: tempo through `format_tempo_cents`; scale and bpm shortest padded to minimum decimals — scale 4, bpm 0 — so historical fixed-decimal forms re-serialize byte-identically. The old producer discipline (compute in integer cents, convert once) is now STRUCTURAL: tempo producers (the bare Up/Down step, the bpm derivation's rounded-cents entry, the sweep's per-cell base + delta) do plain integer arithmetic on cents, and the type forbids leaving the grid. The bare Up/Down tempo authoring steps one cent per press and clamps constructively at the cents bracket edges (there is no tempo wheel). The bpm-derived scale is full double precision (no decimal quantization — the shortest round-trip writer makes in-memory and on-disk agree bit-exactly); playback_speed writes one-decimal (`%.1f`, the presets' natural form — and since spellings are matched by text, the written form is the only loadable form). Sources below 44100 Hz refuse to load, and sources are STEREO-ONLY — `channels != 2` refuses beside the floor in both product loaders (mono-for-sale is locked stereo; convert once outside, e.g. ffmpeg; the probe/parser layer stays capability-complete, and the stereo invariant makes every product-written wav payload even, so the RIFF odd-payload pad byte is unreachable — recorded at `WavWriter::close`). Sources are WAV-ONLY, 16/24-bit PCM (FLAC support and Float32 WAV input removed — a FLAC file takes the unknown-magic refusal with the convert-once hint; a Float32 wav takes the unsupported-format refusal). Sidecars are sample-rate-bound by construction; old-format files fail loudly and convert only through `tools/migrate_sidecar_to_frames`.

### The Marker Measure Suffix (architect 2026-08-19; rebranded and tightened 2026-08-20)
EVERY marker line on BOTH sidecars may carry a MEASURE REFERENCE, appended to the otherwise whitespace-free canonical line as `<canonical line><space>//<measure>` — `44100|1.05 //12`, `#66150 //12 7/8`, `88200|1.00 //+1/4`. THE SEPARATOR IS THE FIRST ` //` ON THE LINE, which is unambiguous by construction: the canonical prefix cannot contain a space, so no earlier candidate exists and everything past it is the measure token. It is the ONE place a space may appear in a marker grammar, and THE SEPARATOR IS UNCHANGED by the rebrand — only the payload grammar moved.

**THE FREE-UTF-8 COMMENT CLASS IS RETIRED (architect 2026-08-20, one day after it landed).** The field was a FREE-TEXT COMMENT from 2026-08-19: 1..`kMaxMarkerCommentBytes` = 99 bytes of well-formed UTF-8, control-free, and it was recorded here and at marker-ui.md as the FIRST relaxation of "TEXT IS UTF-8 IN FREE TEXT AND ASCII IN GRAMMARS" on the marker side and as the product's first non-ASCII painted surface. The architect rebranded it the next day into the MEASURE — a score position for the score-video jump — and a measure is a VALUE, so the field returns to the ASCII-grammar class every other structural grammar in the product sits in. Both claims retire with it: there is no marker-side relaxation of the UTF-8/ASCII rule, and the product paints no non-ASCII surface. The retirement is recorded rather than deleted because the RULING the carve-out rested on (one face, no font fallback, no Pango) is unchanged. NO MIGRATION AND NO LENIENCY SHIM: no ` //` suffix was ever written into the project history, so the tightening strands nothing in the `h` walk, the `'` loads or the Ctrl+H revert.

THE MEASURE GRAMMAR, ASCII only, ONE canonical spelling per value (the `frame_format.h` discipline), enforced IDENTICALLY at load and at the editor commit. TWO FORMS. **DIRECT** — `<M>` or `<M> <n>/<d>`, either optionally prefixed `<S>:`: M a decimal integer in [1, 99999] with no leading zeros and no sign; the optional fraction after EXACTLY ONE SPACE, with 1 <= n < d <= 99, no leading zeros on either, and gcd(n, d) == 1, so `12 4/8` is REFUSED and its one spelling is `12 1/2`. It means measure M, n/d of the way through it. **THE SECTION QUALIFIER** (architect approval 2026-08-20, this header's second frozen reopen) is `<S>:` immediately before that spelling with no space in it — `2:12`, `2:12 7/8` — S a decimal integer in [2, 99] with no leading zeros. IT EXISTS BECAUSE A MEASURE IS THE NUMBER THE PAGE PRINTS, never a continuous count cross-referenced against an edition: a movement whose printed numbering RESTARTS mid-way (the K.550 menuetto's trio) has two bars called `12`, and the section — 1 for the opening numbering, +1 at each printed restart in VIDEO ORDER — says which. A BARE SPELLING IS SECTION 1 AND IS ITS ONLY SPELLING: `1:12` is REFUSED as non-canonical, on the same one-spelling-per-value rule that refuses `12 4/8`, and `0:` with it. Almost every piece has one section and spells nothing. **OFFSET** — `+<W>`, `+<n>/<d>` or `+<W> <n>/<d>`: no space after the `+`, W obeying M's rules (so `+0` is refused — offsets are strictly positive), the fraction obeying the fraction rules, and a sub-measure offset's one spelling being the BARE fraction (`+1/2`, never `+0 1/2`). AN OFFSET CARRIES NO SECTION AND CANNOT BE GIVEN ONE (`+2:1` is refused): it is a distance, not a place, and it takes the section of whatever it is measured from. **AN OFFSET NEVER CROSSES A SECTION** — a chain's section is its DIRECT ANCHOR'S, carried through every `+` above it — which is a ruling about what the field means rather than a limitation, a section being a fresh printed numbering rather than a continuation; to address the next section, spell a direct measure in it. THE BYTE BOUND IS `kMaxMarkerMeasureBytes` = 14, and it is TIGHT rather than a policy cap: the longest canonical token spellable is the fully qualified direct form `99:99999 98/99` at 14 bytes — 2 + 1 for the qualifier over the 11-byte `99999 98/99` — which overtook the longest OFFSET (`+99999 98/99`, 12) when the qualifier landed on 2026-08-20. LOAD-FATAL, first error only, identically in both binaries: anything off the grammar, anything past the bound, and THE EMPTY MEASURE (`payload //` at end of line). Every one is GUI-UNPRODUCIBLE, which keeps the two-category rule exact — an EMPTY COMMIT REMOVES the measure rather than storing one, the writer emits no suffix for an empty field, so the bare separator can never be written, and the editor's commit runs the SAME validator the readers do. THE CRLF TRIPWIRE SURVIVES: the single fraction space is the grammar's only whitespace, so a `\r` reaching the validator is refused like any other stray byte.

`+` RESOLUTION IS NOT VALIDITY, and the authoritative statement of it is at `marker_measure.h` rather than here. In short: a `+` adds to the IMMEDIATE PREDECESSOR marker's RESOLVED measure in the SAME column and only that one (no fallback scan); chains resolve, so `12`, `+1`, `+1` resolves the third to 14; a BROKEN LINK — a predecessor with no measure, or one itself unresolvable — leaves this marker UNRESOLVED. An unresolved `+` still commits, saves, loads and paints; resolution gates the CONSUMERS alone. GRAMMAR IS VALIDITY; RESOLUTION IS NOT — load-lenient, act-strict, so re-ordering markers can never make a file refuse to load.

ONE SPELLING OF THE SPLIT AND THE GRAMMAR, in `src/parser/marker_measure.h` (header-only, both binaries, the frame_format.h precedent; it succeeds the deleted `marker_comment.h`): `split_marker_measure`, `parse_marker_measure`, `format_marker_measure` and `validate_marker_measure` plus the bound, with FIVE consumers and no mirror — the two file parsers, the GitHub recheck's two delta extractors, the Ctrl+H revert's reconstitution through the parser's own per-line entry point, and the MEASURE EDITOR'S COMMIT. `parse_single_canonical_line` carries a `bool accept_measure` parameter for exactly that reason: the whole-file loop, `extract_warp_entry` and the revert pass TRUE, while the FLAG EDITOR'S candidate parse passes FALSE, which is what keeps a ` //` typed into the payload buffer a red-flashing grammar error — the measure has its own editor.

THE FIELD IS HOMED ON THE SERIALIZED BASE (`WarpMarker::measure`, `PhaseResetMarker::measure`), because it must round-trip through the file and both readers are shared: the CLI parses it and never re-serializes anything, while the GUI store upcasts the base whole. It reaches no further — no engine marker carries it, and the render fingerprint serializes resolved fields only, so editing a measure can never invalidate a completed render.
