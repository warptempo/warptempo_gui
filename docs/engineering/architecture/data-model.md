# Authored Data Model (frames, tempo cents, value vocabularies)

Moved verbatim from CLAUDE.md in the 2026-07-25 slim-down (project feature-complete). This file is now the authoritative home for this detail; CLAUDE.md carries only a digest and a pointer here. Keep it current with landed rulings.

### Authored Domain is Whole Source Frames (int64_t)
Authored positions — marker times on both columns and both trim bounds — are whole source frames held in `int64_t` everywhere at rest: in-memory stores, sidecar files, walls, validators. A fractional authored position is unrepresentable by type; mid-gesture positions are free doubles, and `snap_authored_frame` (`app_state.h`: banker's `std::nearbyint`, then exact cast) is the ONLY double-to-authored conversion route in the product tree — every gesture commit funnels through it (the standalone migration tool carries its own equivalent `nearbyint`). Ties are real at 44.1 kHz (the 5 ms zoom level is 220.5 frames/px, a half-frame tie on every odd pixel), so banker's is load-bearing. There is no seconds or millisecond-grid representation anywhere in the data path; MM:SS.mmm timestamps are display-only renderings (`format_timestamp(frame / sr)`) on GUI text surfaces. ONE serialization domain in `src/parser/frame_format.h`: the AUTHORED pair (`format_authored_frame` = plain integer text, `parse_authored_frame` = the CANONICAL spelling only: digits, no sign/point/exponent/leading zeros, int64 overflow refused — the spelling IS the grammar; the migration tool guarantees corpus canonicality) is the single on-disk position form, and any other position text — fractional, negative, non-finite, or a non-canonical integer spelling like `44100.0`/`6e+05` — is adversarial load-fatal. (The old RENDER-DISPLAY pair and the `.renderwarpmarkers`/`.renderphaseresetmarkers` sidecars are retired: positions on a render's target axis are computed live by the GUI through the snapshot map and never serialized.) Walls are exact integer comparisons — every authored position, both marker columns and both trim bounds, shares the one inclusive `[0, total-1]` domain (the trim end's former exclusive `total` wall was unified 2026-07-18; an end bound stored at `total` is adversarial load-fatal, no migration) — literally the same compare at gesture time and at the adversarial load guard. Field naming is `*_frame`.

Authored TEMPO is 100-based INTEGER CENTS held in `int64_t` everywhere at rest — the value-domain sibling of the frames ruling above; an off-grid or fractional tempo is unrepresentable by type. Its bracket is `[kTempoMinCents, kTempoMaxCents]` = [25, 400] (i.e. [0.25, 4.00]), exact integer compares at every bracket surface. The `N.NN` spelling (one-plus digits, one dot, exactly two decimals, no leading zeros) is the TEXT INTERFACE only: `format_tempo_cents` / `parse_tempo_cents` (`value_format.h`) are the single serialization pair (direct digit-to-cents, no strtod, byte-identical to the historical min-2-padded form), and `tempo_from_cents(int64_t)` — double overload deleted — is the ONE cents-to-double boundary, crossed at exactly four sites: the DSP slope product (`build_warp_frame_map`), the fingerprint f64 compatibility encoding, the bpm derivation's scale divisor, and the label-ref hover multiplier. Every OTHER value is a double via `src/parser/value_format.h` under BRACKETED vocabularies (the constants there are the SoT): both scales `[kScaleMin, kScaleMax]` = [0.5, 2] (multiplicatively symmetric; the floors bound the resolved product to >= 1/16, which the pixel-nudge guarantee is computed from; scale staying full-double is the recorded tempo/scale asymmetry at the WarpMarker struct), bpm `[10, 400]`, `bpm_beats` int in [1, 9999], iteration deltas in [-400, +400] integer cents (session-only, never serialized; the iter-bracket text commit additionally red-flashes when base tempo plus either bound leaves the tempo bracket — the endpoints bound every cell). Iter state has a hard lifecycle: exiting iteration mode — the `i` toggle or enter_bpm_mode's forced iter-off, both through GuiFlagEditor::wipe_iter_state — wipes every bracket (Shift+I is retired; exiting the mode IS the clear; the wipe pushes one undo entry, so plain undo may deliberately restore a bracket set). Tempo changes NEVER clear a bracket (architect 2026-07-19, reversing the earlier tempo-step clear): the flag editor's manual tempo commit and the bare Up/Down step both leave the adjusted marker's bracket in place — a later tempo change under a live bracket is deliberately not re-gated, staleness accepted, backstopped by `build_warp_frame_map`'s refusals (async stderr) and the strict promote parse at the `'` load-in-place. Eligibility LOSS does clear, at both authoring surfaces: Ctrl+N's owner→pass and ref→pass branches reset the marker's bracket in the same undo entry, and the flag editor's commit unconditionally resets the bracket whenever the committed marker is iter-ineligible (regardless of iter grammar or mode, covering a pass/ref payload committed with bracket text left in place and the mode-off conversion of an undo-restored bracketed owner) — so a hidden bracket cannot resurrect through a later pass→owner freeze against a different frozen base; undo is the one sanctioned restore route. BPM state (owner, beats, bounds, endpoint — likewise session-only, never serialized) has the same hard lifecycle: it wipes history-less on every bpm-mode exit (the exit_bpm_mode chokepoint, all off-routes funnel there) and on sweep dispatch (render_bpm_sweep's success tail wipes and closes the mode; a guard-bailed sweep deliberately keeps values and mode for correction), so re-entering either mode always seeds blank. THE SECTION RULE (arc step 5, architect-designed 2026-07-23) governs the `m` sweep and both propagate spans: a marker OWNS the section from itself to the next store marker, the STORE-FINAL marker's section running to the SONG END — WITH ONE 2026-08-01 QUALIFIER FOR THE TWO PROPAGATE SPANS ALONE: their extent is the EFFECTIVE-PARTICIPATION form (`section_end_frame`, phase_reset_propagate.cpp — the next EFFECTIVELY-ENABLED marker, else the song end), because a disabled marker is dropped before the warp map is built and is not a render boundary; its span belongs to the preceding enabled marker, so the resets under it copy, clear, and paste with the section they musically belong to (the old next-in-STORE extent left that span owned by nobody — the architect's reported drop — and silently mis-scaled captured resets against truncated durations). The `m` sweep DELIBERATELY KEEPS the raw store-index form (span-based, `bpm_endpoint`, disabled markers inside the span convert per cell) — the `m` gate takes a non-empty CONTIGUOUS run of selected markers (first = owner; `bpm_endpoint = last+1`, == store size being the song-end sentinel through the commit gate, the sweep, and the descriptor; every selected section included, the old excluded-endpoint-section model retired), the Ctrl+P copy takes the SAME non-empty CONTIGUOUS run (codex round 4: the paste's lockstep label matching assumes one contiguous label sequence, and unlabeled gaps align on both sides; effective-disabled selected markers contribute no block), the paste destination walk gives the store-final ENABLED labeled marker the same song-end extent (its EOF clamp load-bearing; since 2026-08-01 a labeled marker trailed only by disabled ones owns to the song end too — the newly reachable branch of the same guard), and disabled markers are excluded from bpm eligibility (`bpm_popup_eligible_marker` gains !disabled — for an owning marker raw equals effective, the cascade only reaching refs). Out-of-bracket on disk is adversarial load-fatal (the GUI can never author it); typed values red-flash at editor commit; the bpm derivation refuses (never clamps) an out-of-bracket derived tempo or scale; sweep per-cell computed mutations are deliberately unbracketed (async stderr backstop at `build_warp_frame_map`). `playback_speed` is preset-vocabulary-only on disk (the ten one-decimal speeds 0.1..1.0, `playback_speed_presets.h` SoT — parser-side, so the settings schema enforces membership in BOTH binaries; membership is by exact TEXT against the writer's %.1f spellings, each paired with its nearest-float for the live store — no float parse at the boundary; any other spelling hard-fails the source load — the GUI can only author presets). The Shift+digit gesture is REMOVED: the settings editor is the sole authoring surface (`:playback_speed=`, preset membership red-flashed at commit), the default is 0.7, and a set made in target view STORES only — target playback stays at natural rate; the value becomes audible on the return to source view because every launch re-applies from `app.playback_speed`. Writing: tempo through `format_tempo_cents`; scale and bpm shortest padded to minimum decimals — scale 4, bpm 0 — so historical fixed-decimal forms re-serialize byte-identically. The old producer discipline (compute in integer cents, convert once) is now STRUCTURAL: tempo producers (the bare Up/Down step, the bpm derivation's rounded-cents entry, the sweep's per-cell base + delta) do plain integer arithmetic on cents, and the type forbids leaving the grid. The bare Up/Down tempo authoring steps one cent per press and clamps constructively at the cents bracket edges (there is no tempo wheel). The bpm-derived scale is full double precision (no decimal quantization — the shortest round-trip writer makes in-memory and on-disk agree bit-exactly); playback_speed writes one-decimal (`%.1f`, the presets' natural form — and since spellings are matched by text, the written form is the only loadable form). Sources below 44100 Hz refuse to load, and sources are STEREO-ONLY — `channels != 2` refuses beside the floor in both product loaders (mono-for-sale is locked stereo; convert once outside, e.g. ffmpeg; the probe/parser layer stays capability-complete, and the stereo invariant makes every product-written wav payload even, so the RIFF odd-payload pad byte is unreachable — recorded at `WavWriter::close`). Sources are WAV-ONLY, 16/24-bit PCM (FLAC support and Float32 WAV input removed — a FLAC file takes the unknown-magic refusal with the convert-once hint; a Float32 wav takes the unsupported-format refusal). Sidecars are sample-rate-bound by construction; old-format files fail loudly and convert only through `tools/migrate_sidecar_to_frames`.
