## Why
A cloud build host (Debian-based, apt) could not provide libgit2 at the version the program is built against (Arch's 1.9.7; Ubuntu ships 1.1 / 1.7), and CMake marks libgit2 REQUIRED for the GUI. The cloud does graphical work only — the git road is finished and verified on the laptop and the tablet — so it needs a build that compiles and runs without libgit2, with every git act failing CONSTRUCTIVELY through the program's existing "no repository" outcomes. The laptop and the APK keep the real road: the option defaults ON and nothing in their builds changes.

## The switch
- `option(WARPTEMPO_GUI_GIT "Link libgit2 for the history view's git road (OFF builds a stub: every git act reports no repository)" ON)`, documented beside WARPTEMPO_BUILD_GUI / WARPTEMPO_BUILD_CLI in CMakeLists.txt's head comment in the same voice.
- ON: exactly today's build (byte-identical object code is not required, but the source list, flags and link line are unchanged — `cmake -B build -S . -DWARPTEMPO_BUILD_CLI=ON && cmake --build build -j$(nproc)` must build warnings-clean as before).
- OFF: the Linux branch skips `pkg_check_modules(LIBGIT2 …)` and the libgit2 include/link lines; the Android branch likewise skips WT_ANDROID_GIT and the -lgit2 -lssh2 -lcrypto chain (android/app/build_apk.sh passes nothing new; OFF on Android is allowed but not exercised — say so in the comment); the GUI source list compiles `src/gui/git_repo_stub.cpp` IN PLACE OF `src/gui/git_repo.cpp` (one `if(WARPTEMPO_GUI_GIT) … else() … endif()` at the source list, or a variable; keep the one-site rule: the file swap is stated at exactly one site).
- `src/gui/git_repo_stub.cpp` (new): implements EVERY declaration of git_repo.h with no libgit2 — gui_git_init a no-op; gui_git_discover_root returns GuiGitRoot::CouldNotAsk (or NotAClone — pick the one whose downstream card tells the truth: "git is not available in this build" is closest to CouldNotAsk; read history_diff.h's and the project loop's readers of the enum and say which card appears); gui_git_is_ssh_url keeps its pure string logic (move it to a shared place or duplicate the few lines — state which; a pure function should not have two copies: prefer moving it into git_repo.h as inline or a small git_url.cpp compiled in both modes); every GuiGitRepo method returns its failure vocabulary's "local, could not ask" value (GuiGitFetch::LocalFailed, GuiGitFastForward::NotStarted, the path status's unavailable arm, an empty upstream) with the one stderr line the NO-BACKSTOPS rule allows ("git: not available in this build"), never a crash and never a silent success. The stub's head comment states the rule: it is a BUILD-HOST convenience for graphical work, never a product configuration; the two devices build with the switch ON.
