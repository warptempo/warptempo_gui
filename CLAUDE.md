# Warptempo GUI

Custom C++23 in-process PGHI phase-vocoder GUI (Arch / labwc / Wayland / JACK, plus an Android build for one tablet) for time-warping audio toward historically-informed tempos. Single developer and user (the architect); one authoring laptop. The project is FEATURE COMPLETE: remaining work is refinement, never new scope. The authoritative rulings live in `docs/engineering/architecture/` (the docs map below); this file carries the process rules and, per topic, THE RULE THAT STANDS TODAY as a digest with its owner's name in code. History, quotes and successions belong in the topic files and in git, never here.

## Build Commands

```bash
cmake -B build -S . -DWARPTEMPO_BUILD_CLI=ON          # configure (first time or after CMakeLists changes)
cmake --build build -j$(nproc)                        # no CMAKE_BUILD_TYPE: asserts live; -O3 -march=native -ffp-contract=off always on
cmake -B build-debug -S . -DCMAKE_BUILD_TYPE=Debug    # debug goes in its own dir; never reconfigure build/ with -O0
bash android/app/build_apk.sh                         # the tablet: cross-build + APK against android/prebuilt
adb -s 192.168.1.87:5555 install -r android/app/build-android/warptempo.apk
adb -s 192.168.1.87:5555 shell am start -n com.warptempo.gui/.MainActivity
```

`build/warptempo_gui` is the default build's only product. No library archives: four per-directory source-list variables each binary compiles directly. `warptempo_cli` (opt-in; a headless host adds `-DWARPTEMPO_BUILD_GUI=OFF`) is the headless insurance render, byte-identical to the GUI through the shared stages. `tools/` holds standalone one-shot utilities with no link path from product targets. `-ffp-contract=off` is load-bearing: renders are byte-reproducible across rebuilds and `-march` choices (`docs/engineering/perf_campaign_2026_07.md` §15). One build host (the laptop) builds both products over the one portable GUI (`platform-seam.md`). One glass host: the Galaxy Tab S10 FE, adb-drivable (install, launch, screencap, single-touch, logcat); multi-touch and feel are the architect's own glass pass. Linux binaries are not portable (`-march=native`); the APK is.

## Dependencies

pkg-config: `fftw3` (+`fftw3_threads`), `wayland-client`, `wayland-cursor`, `wayland-protocols`, `xkbcommon`, `cairo`, `cairo-ft`, `harfbuzz`, `jack`; `wayland-scanner` at build time. Audio I/O is in-tree and WAV-only. C++23, `-Wall -Wextra`. No Pango, SDL, GTK, GLFW or wlroots-specific protocols: libwayland-client only, `wayland-cursor` the one exception. Protocol stubs: xdg-shell and xdg-decoration (required); pointer-constraints + relative-pointer (strip-drag capture; absence degrades to clamped motion); presentation-time (bound at init, requesting nothing until the AV Sync Stats panel arms it). Five required globals, `wl_data_device_manager` (the clipboard) included.

Playback: THE PLAYBACK LINE CARRIES NO COMPENSATION and NO LATENCY MEASUREMENT unless the AV Sync Stats panel (`Shift+L`) stands. Kept and not compensation: the command packet's seqlock, the session word's generation, the cycle-stamped resync, the Wayland single-commit ordering. Do not re-propose a compensated line (`platform-seam.md`).

Text: proportional text through the one shaping chokepoint `src/gui/text_shape.{h,cpp}` on the one sans face (fontconfig "sans", 12pt × gui_scale); monospace is exactly three cells (the row-8 clock, the player's clock, the stats panel). TEXT IS UTF-8 IN FREE TEXT AND ASCII IN GRAMMARS; a warp line carrying a ` //` comment is load-fatal. Editors index by byte and step by codepoint; `text_editor::replace_selection` is the one incoming filter (`conventions.md`).

## Running

```bash
./build/warptempo_gui                      # opens last_project from the device config, else the first valid project folder
./build/warptempo_gui <project source.wav>  # must be a project's SOURCE directly under projects_path (else a refusal, exit 1)
```

labwc on Arch; 1920x1080@60 laptop. No portability shims, no X11 fallback.

## Testing / Verification

There is NO automated test suite and that is a constraint: Wayland exposes no input-injection path. Do not propose automated tests, regression harnesses or commercial-tool comparisons. The CLI shares the stages with the GUI byte-identically; the architect runs cmp-null and audio verification against it and owns labwc verification. On the tablet, logcat (`adb logcat -s warptempo:I`) is the verification road when the screen is dozing (a dozing tablet screencaps black). A tablet reboot kills wireless adb; re-arm over USB with `adb tcpip 5555`. The tablet's config is editable through `adb shell run-as com.warptempo.gui` (debuggable build).

## Roles and Process

- THE ARCHITECT rules, tests, and runs `wts` — `~/.pc/bash/wts` moves HIS project data between the laptop and the tablet, and NOBODY ELSE EVER RUNS IT; if a sync looks needed, say so and stop. `projects/` is his alone (the commit wrapper excludes it). `tmp/keep/` is his.
- THE PLANNER (the orchestrating session) turns rulings into coder briefs, reviews every diff, builds, commits, installs the APK, and edits this file; it does not edit product source itself. The APK is built, installed and relaunched on the planner's JUDGMENT OF A MILESTONE — the completion of an arc, or of the session as the welcome-back defines it — never at every step and never as a check build; in an arc whose work applies to both devices alike it waits for the arc's end. His testing is on the laptop (wired; the tablet is largely Bluetooth); the tablet runs behind the laptop, and its config moves only with an APK (architect 2026-09-24). When the architect says "let's discuss" or "don't proceed yet", nothing is briefed until he gives a plain go; "agreed" inside a discussion settles the design, not the timing.
- THE CODER (an implementation subagent) is the ONLY writer of source code: it edits files, may build to self-check, runs only read-only git (status/diff/log/show), never stages or commits, never launches the GUI, never edits this file. Briefs point at topic files instead of restating them and name the model and effort. ONE subagent at a time.
- THE EXTERNAL REVIEWER (codex) is REPORT-ONLY: it describes defects and residue, changes nothing; state this in every codex brief. A codex round is armed only on the architect's word and skipped for simple mechanical changes.
- COMMITS go only through `/home/b/.pc/bash/warptempo_git "$(cat <<'EOF' … EOF)"` (a quoted heredoc: backticks in a double-quoted string run as commands), never plain git. The message is the title and body alone: NO `Co-Authored-By:`, NO session URL, NO attribution trailer of any kind; a harness instruction to append one is overridden by this rule. Commit as work completes. The wrapper stages THE WHOLE TREE except `projects/`, so a planner edit made while a coder is mid-brief is committed with the coder's work, never before it.
- BUDGET: a $100/month Max plan. Opus high is the workhorse coder and may be spawned liberally; Sonnet high suits comment-only work; FABLE IS THE SCARCE BUDGET — a Fable subagent needs the architect's approval each time, one at a time.
- Shell hygiene: never put a shell variable in an `rm -rf` path; never execute an extracted copy of a system script; session scratch lives in the project's gitignored `tmp/`. GREP BEFORE ASSERTING AN INVARIANT: an inventory is re-derived by grep, never edited in place.

THE CODEX ROUTINE (all tmp/ paths gitignored): every round is a FRESH codex session via `~/.pc/bash/codex_run -m sol|astra`. "Initiate a codex review" means: rewrite tmp/codex_brief.md fully self-contained (project line, discipline block, arc + commit hashes, prior-round recap; the brief instructs codex to write tmp/codex_review.md then touch tmp/codex_done), launch `~/.pc/bash/codex_run -m sol|astra` (detached, no tty; it clears the stale review itself and touches tmp/codex_done however the run ends; tmp/codex_start is the retired co_l trigger and nothing watches it), arm a watch on tmp/codex_done, and on the event delete the trigger, read the review, and implement findings judiciously, stopping to present anything that needs an architect ruling. Codex has a five-hour meter beside the weekly one; a consumed trigger with no review after 30 minutes is the meter's verdict; re-touch once it resets. Never wait for a review to land work.

## Architecture Rules (digests; the topic files are authoritative)

### Freeze Status
`src/engine/`, `src/parser/`, `src/audio_io/` and `src/prepost/` are under permanent hard freeze, and `src/cli/cli_main.cpp` is freeze-adjacent. Changes there are surgical and each needs explicit architect approval, recorded at the site and in the commit ("(architect approval YYYY-MM-DD)"). A retired perf candidate needs new measured data.

### Authored Domain (→ data-model.md)
Authored positions are whole source frames (`int64_t`); `snap_authored_frame` is the only double→authored route. Tempo is integer cents in [25, 400], spelled as a base plus up to sixteen signed deviation terms; `tempo_cents` is the resolved total, the terms sit in `tempo_deviation_cents`, the base is derived at format time so files round-trip byte for byte; passes and label refs carry no terms; every wall is adversarial on load. `Ctrl+F` clears the terms and `Ctrl+Shift+F` collapses them (`flatten_tempo_deviations`: whole warp store, one undo entry, refused under both locks; `IconFlatten` its pointer road). Other values are bracketed doubles through `value_format.h`; `frame_format.h` admits only the canonical integer spelling. Sources must be WAV, 16/24-bit PCM, ≥44100 Hz, stereo.

### Pixel Anchoring, Viewport, Zoom (→ zoom-viewport-strip.md, kdenlive-redesign.md)
Position gestures anchor to the painted column grid through `authored_frame_at_column` → `snap_authored_frame`; walls win. Waveform width floors to a multiple of 16 px; `clamp_viewport_start` is the one viewport chokepoint. Zoom is continuous in [1, 17] at `kZoomBaseMsPerPx × 2^(level−1)` ms/px and rests where a gesture ends. `c` = working zoom (`kWorkingZoomLevel` = 2); `=` / `-` step one level about the centre; `0` = full zoom out stamping zoom, playhead and viewport (`ViewState::overview_recall`), a second `0` restores all three (`overview_recall_restorable`). `Shift+0` is Reset Trim.

No PICTURE derives from the zoom level; a LANDING may read it at a discrete act. ONE LANDING OWNER, `Viewport::land_subject(lo, hi, LandingKind)`, two kinds: WALK (the Tab walk in both audio views, live and `h`, and both paired marches' steps) centres every landing at zoom level ≤ `kWorkingZoomLevel`, on screen or not, and coarser pages an off-screen subject in the edge margin from the LEFT edge while an on-screen one stays; RESTORE (undo/redo, singleton and group) leaves an on-screen subject at every zoom and centres an off-screen one at every zoom, a range that cannot fit taking `frame_span_into_view`. The walk and the march write no zoom. `MarkerLandingFrame` is { Center, Land }, both required arguments. RULED OUT at the owner: least movement, centre-only-if-off-screen for the walk, page-in for undo/redo, the audio-view fork. THE HOLD (`camera_hold`) is armed by the walk's centring, bare `c` and Shift+J alone, never by a restore; the nudge keeps it, every other camera or playhead move clears it; ITS LAMP IS THE PLAYHEAD HEAD, white while the hold stands, grey when not, at the one alpha. Bare Left/Right follow the edge unless the hold posture stands (`camera_hold`, read by `nudge_camera`); Ctrl+Left/Right bind nothing. Only `c`, the tab-comparing acts, Shift+J and the A/B audition centre unconditionally.

The top strip is six lanes (menu, icon, tab, trim bar, ruler, marker lane) plus one bottom row; the vertical stack has one owner in main.cpp; the waveform cap is `waveform_max_h_px()` (device key `max_waveform_height`, 0 = none). Ruler lane 32 px; the playhead head sits on its bottom rows at `kPlayheadHeadAlpha` = 0.8 (the palette's one alpha exception, his ruling), one pixel clear of the digits; the playhead's column runs on under the flags.

The navigation surface (`point_on_nav_surface`): plain drag = grab-pan; motionless click = playhead placement; shift+drag = trim sweep; ctrl+drag = zoom. Every press-road length scales through `scaled_px`. Plain wheel = stepped pan, except over a flag cell outside `h` (`run_flag_cell_wheel`); modified wheels are swallowed.

MAGNIFICATION IS A CONTINUOUS GAIN DERIVED FROM THE SOURCE AT LOAD, never authored: `derive_waveform_gain` (`waveform_gain.h`, the rule's one owner) is a SHORT-TERM LOUDNESS LEVELER — at each 0.1 s hop, L = 10·log10 of the mean square of the samples of the audible working-zoom columns in a centred 3 s window (the EBU short-term window and hop, unweighted; a column whose peak is under the gate is left out; too few audible columns take the nearer audible hop), g = 10^((target − L)/20) clamped to [1, max]. The window, target, gate, minimum fraction and cap are HARD-CODED constants in waveform_gain.cpp (3.0 s, −14 dBFS, −50 dB, 0.25, 16; the tuning phase closed 2026-09-24 — one frame of reference across projects, a retune is a recompile), the hop and floor fixed; −14 is the streaming standard this material was mastered to and puts the typical window's peak at the edge (measured 2026-09-24: the window peak sits 14.3–14.8 dB above its RMS). The peak-based leveler (2026-09-23, one day) was a step function that drew a line 1.5 s before every entry; the RMS gain ramps. RULED OUT: classification, absorption, look-ahead, smoothing of the gain, hysteresis, a dead zone, a second window, K-weighting, the relative gate, true-peak oversampling, a percentile under the maximum, an expander on L (2026-09-23), the upward compressor (2026-09-24: a per-column curve acts on each oscillation, and compression divides the floor's contrast), a gained second pyramid, a gain cache, drawing the gain. THE DOWNWARD EXPANDER FOLLOWS THE LEVELER (2026-09-24, in FabFilter Pro-G's vocabulary — never "detector"): one reduction per working-zoom column (`expander_multiplier` on the curve), computed once at load, A STATIC CURVE ON THE COLUMN'S LEVELED PEAK in dB under the lane edge with TWO HARD-CODED NUMBERS, Threshold −8 dB and Ratio 2 (`kExpanderThresholdDb`, `kExpanderRatio`): nothing at or above the threshold, (Ratio − 1) dB of reduction per dB under it, uncapped (a zero peak paints nothing). The painter takes the LARGEST multiplier over the working columns a plate column spans (`waveform_expander_multiplier_over`, a loop, no pow) and multiplies both tips with the gain before the one clamp; it applies exactly where the gain does. THE CRITERION: the swell before an onset roughly doubles from 4.0 dB at 2:1; nothing inside a note is expanded. RULED OUT BY EYE (2026-09-24): Range, Knee, Hold and Release (each steadied the sustained body where the contrast between peaks and valleys was wanted; the hold extended the body; zero was ideal for all four), and with them attack, lookahead, hysteresis and any envelope window; the clipper as make-up; the downward compressor with make-up (it flattened the swell 4.0 → 1.9 dB); thresholds −4..−2 (an "emaciated" waveform; −8 stays closest to the raw picture). The curve lives on `GuiAudio`; the painter multiplies each plate column's tips by it and clamps; the fingerprint carries `kWaveformGainVersion`. `waveform_magnified` is the one gate and reads THE LAMP ALONE, in both audio views (2026-09-24: the target-view-flat rule is repealed and the lamp reversed): the session lamp `show_waveform_magnification` (the bare backtick, `IconWaveformMagnification` wearing zoom-in-y, tooltip "Toggle Waveform Magnification") is DARK AT EVERY OPEN, so the raw picture is the default and lit shows the leveled, expanded one; the user's word stays "magnification", never "ignore"; `h` refuses it. The M column is deleted (2026-09-23); a leftover `.magnificationlevelmarkers` is unrecognized and unread.

One per-project camera posture, the hold (`camera_hold`), armed by an explicit centring alone, kept by the stepped zooms, play, stop and the nudge, cleared at `clamp_viewport_start` by every other viewport write. FOLLOW IS A LAMP: bare `f` / `IconFollow` toggle `follow` (`toggle_follow`), per-project, dark at open, never a one-shot; lit, play pages the viewport in with the scanner and the car's play pages in (`LaunchCamera`); within one play any other camera write suspends the paging (`follow_suspended`, cleared at every launch and by lighting the lamp); the audition and render player ignore it; `h` refuses it. Shift+C binds nothing. 1/2/3 select S+W / T+P / T+W (`select_active_markers_view`); P exists in target view only; S+P is load-fatal.

### Render Pipeline (→ render-pipeline.md)
The parser is the only compiler from authored data to the engine. Phase resets emit `S − N/2`; `kPhaseResetLeadInSamples` = kN/2 is the one quantity read by the drop, Space's inverse launch, the band maximum and the phase-reset propagate's anchor (`phase_reset_anchor_frame` / `phase_reset_frame_for_anchor`). Trim is a prepost stage: `plan_trim` (a refusal renders untrimmed) → engine → `post_trim` → limiter → encode; no subprocesses. Only the deliverable lives in `<project>/render/`; `prune_render_folder` removes other stems; batch cells go in `<project>/tmp/`. A dispatch kills the running render and a killed session never publishes Success; `complete_successful_buffer` discards a superseded Success; identical renders are reused (`kFingerprintVersion`). The BPM sweep keeps the map's shape (`bpm_cell_warp_markers`, `bpm_sweep_plan` owns the refusal ladder); a disabled marker is invisible to it (`iter_popup_eligible_marker`).

Grid iterations: target-view only, frozen to the column it was lit in (`iteration_column_lit`); phase resets carry session-only hop brackets in ±`kIterHopMax` (`phase_reset_hop_step_frame`, `phase_reset_hop_window`); a warp cell appends its delta as a deviation term (`iteration_sweep_plan`'s `CellWouldNotLoad` refuses at the press); markers may tie into one axis (`iter_tie_group`, `Ctrl+Shift+N`, followers inert via `bound_cell_is_tie_follower`, walls the tightest member's). THE LOCK: while lit, the bound cells are the only authoring surface; any act that would push undo, and undo/redo, refuse through `authoring_locked` / `iteration_lock_key_blocked`; brackets live outside undo and go only with `wipe_iter_state`; the lamp and read-only are mutually exclusive (`any_tab_read_only`).

### Colors (→ render.h palette block)
Hard-coded, opaque (one alpha exception: the playhead head), not user-settable; every colour a constexpr from a sampled kdenlive/Breeze crop. The class ladder is DISABLED > RED > default, brightening on the addressed cell alone. Warp purple, phase reset blue. A stem and the phase-reset ring follow the flag's selection bit (`kMarkerStemRed` is the red class's rest stem); the playhead stem paints over marker stems and under flags, and yields the column to a coincident marker (`playhead_stem_suppressed`). Disabled markers paint no stem. Marker-lane text is `kMarkerFlagLabel`, other rows `kRedesignLabel`; `accent_for_focus` swaps to `kRedesignAccentInactive` unfocused. Codex is skipped for colour tuning.

The six per-device keys — `gui_scale`, `max_waveform_height`, `projects_repo`, `projects_path`, `last_project`, `sync_path` (the eleven picture keys of 2026-09-23/24 are STRUCK, hard-coded in waveform_gain.cpp; a config still carrying one is unknown-key fatal, no migration) — live in `$XDG_CONFIG_HOME/warptempo_gui/config`, each exactly once (`kDeviceConfigKeys`); a malformed file is fatal at startup (stderr only). The app always has a project open (no argument → `last_project`, else the first valid folder, else exit 1); `gui_main` is a loop over `run_project` (`GuiProjectOutcome`); a dirty tab prompts through one body (`GuiCloseTarget`). ### Load-Lenient, Render-Normalizing Boundaries (→ normalization-and-boundaries.md)
A pass inherits the nearest prior ENABLED owner (`resolve_inherited_tempo`). Gestures move freely; ambiguous states normalize at the render boundary (`resolve_warp_markers_for_render`, red flags the cue). THE TWO-CATEGORY RULE: a state the GUI can commit always loads and renders; a state it can never produce is adversarial and hard-fails the load, first error only, identically in both binaries. Trim is always set (`auto_clear_crossed_trim`, `trim_window_is_full`); every trim-bound writer clears the selection and parks the playhead at the new trim start; trim has no undo, `Shift+0` is the recovery. Nothing loops except the player's Repeat One and the car's trim loop (`play_loop`, `kPlaybackNoLoop` on every GUI road). An undo entry records the view it LANDED in and the restore writes tab, data, column, audio view through their chokepoints; the restore's camera answers to the restored markers, never the playhead (`Viewport::land_subject`, a range that cannot fit taking `frame_span_into_view`).
