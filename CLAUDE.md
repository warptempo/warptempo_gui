# Warptempo GUI

Custom C++23 in-process PGHI phase-vocoder GUI (Arch / labwc / Wayland / JACK) for time-warping audio toward historically-informed tempos. Single developer/user (the architect); one target laptop. PROJECT STATUS: FEATURE COMPLETE (architect, 2026-07-25). The detailed architecture rulings formerly held in this file now live in `docs/engineering/architecture/` — see the docs map below. This file carries the build/process rules, the per-topic digests, and the pointers; the topic files are the authoritative detail. When a ruling lands, update the topic file (committed) and this file's digest only if the headline changes.

## Build Commands

```bash
# Configure (from project root, first time or after CMakeLists changes)
cmake -B build -S . -DWARPTEMPO_BUILD_CLI=ON

# Build (Release is the project default; -O3 -march=native is always on)
cmake --build build -j$(nproc)

# Debug build into a separate dir; never reconfigure `build/` itself with -O0
cmake -B build-debug -S . -DCMAKE_BUILD_TYPE=Debug
cmake --build build-debug -j$(nproc)
```

`build/warptempo_gui` is the GUI binary and the default build's only product. No library archives: CMake carries four per-directory source-list variables (`WARPTEMPO_AUDIO_IO_SOURCES`, `WARPTEMPO_PARSER_SOURCES`, `WARPTEMPO_ENGINE_SOURCES`, `WARPTEMPO_PREPOST_SOURCES`) each binary compiles directly — object-code duplication accepted deliberately. One opt-in binary, default OFF: `warptempo_cli` (`-DWARPTEMPO_BUILD_CLI=ON`, the headless insurance render path — exactly the terminal Ctrl+Alt+R, byte-identical to the GUI by shared stages). A headless host builds the CLI with `-DWARPTEMPO_BUILD_GUI=OFF`. `tools/` holds standalone one-shot utilities (own CMakeLists, no link path from product targets): currently `migrate_sidecar_to_frames`, the sole conversion route from the legacy MM:SS.mmm sidecar format (grid details in `docs/engineering/architecture/data-model.md`). Binaries are not portable (`-march=native`); rebuild on the target host.

## Dependencies

Checked via pkg-config: `fftw3` (+ `fftw3_threads`), `wayland-client`, `wayland-cursor`, `wayland-protocols`, `xkbcommon`, `cairo`, `cairo-ft`, `harfbuzz`, `jack`. Plus `wayland-scanner` (build-time, generates protocol stubs into `${CMAKE_BINARY_DIR}/wayland-generated`). All audio container I/O is in-tree and WAV-only, so the non-GUI sources need only `fftw3`. HARFBUZZ IS THE RULED TEXT-SHAPING PATH (architect 2026-07-30, resolving the parked UTF-8/text-shaping question): proportional text measures AND paints through the ONE shaping chokepoint `src/gui/text_shape.{h,cpp}` (contract authoritative in its header comment — the shaped run is the single width truth, the monospace glyph-count arithmetic's successor), GUI-only (deliberately absent from the four shared source lists); THE CONVERSION IS COMPLETE (row 7, 2026-08-01): every text surface in the product shapes and paints through the chokepoint on the ONE sans face (fontconfig "sans" → Liberation Sans, 12pt scaled by gui_scale) — the toy-API monospace path is DELETED WHOLE, and the font_size settings key with it. Do not add Pango (font fallback/bidi is deliberately out of scope; one wide-coverage face is the model).

C++23 (the parser uses `std::expected`). `-Wall -Wextra -O3 -march=native` on GCC/Clang. Do not introduce SDL, GTK, GLFW, or wlroots-specific protocols — the GUI is libwayland-client only (`wayland-cursor` is the canonical exception). Generated protocol stubs cover four standard wayland-protocols XMLs: xdg-shell, xdg-decoration, pointer-constraints-unstable-v1, and relative-pointer-unstable-v1 (the last two are the strip-drag pointer capture, the ONLY optional protocols — absence degrades to clamped absolute motion with one stderr line; xdg-decoration is REQUIRED at startup since 2026-07-30, labwc always advertising it).

## Running

```bash
./build/warptempo_gui <source.wav>
```

Target environment: labwc on Arch Linux, single 1920x1080 monitor at 60 Hz. No portability shims, no X11 fallback.

## Testing / Verification

There is no automated test suite, and that is a CONSTRAINT rather than a preference: exercising this product means driving a GUI, which needs synthetic input into a live compositor — and Wayland exposes no such facility (there is no portable equivalent of X11's XTEST, and labwc offers no injection path), so a GUI harness is not buildable here at all. What CAN be verified is verified: the CLI shares the parser/engine/prepost/audio-io stages with the GUI byte-identically, and the architect runs cmp-null and audio verification against it. Verification is otherwise brief-driven: the coder (implementation subagent) is the ONLY writer of source code — it edits files only, and source-only checks requested by a brief are okay. ### Authored Domain (→ data-model.md)
Authored positions (marker times, trim bounds) are whole source frames in `int64_t` everywhere at rest; `snap_authored_frame` (app_state.h) is the ONLY double→authored conversion route. Authored tempo is 100-based integer CENTS in [25, 400]; every other value is a bracketed double via `value_format.h`. One serialization domain (`frame_format.h`): canonical integer spelling only — anything else is adversarial load-fatal. Walls are exact integer compares on the shared inclusive [0, total−1] domain. Sources: WAV-only, 16/24-bit PCM, ≥44100 Hz, stereo-only.

### Render Pipeline (→ render-pipeline.md)

### Modality and Input (→ conventions.md)
Modal surfaces live on the bottom strip, and since 2026-07-28 the top-strip flag editor is KEYBOARD-modal too (architect, reversing the old "commands punch through" ruling): all four editors admit exactly the editor's own keys plus bare Esc, Ctrl+S and Ctrl+Q through ONE `route_modal_editor_key` contract, so an unbound chord is structurally inert rather than a command that discards the edit — which is what closed the flag editor's destructive fall-through tail, and with it the `StrayModifierKey` class that tail alone had justified. Modality is CHORDS ONLY: the flag editor stays pointer- and wheel-transparent and still does not stop playback (`modal_bottom_strip_editor_active` has exactly ONE caller, `wheel_context`; the playback stop has ONE owner since 2026-07-28, `GuiPlaybackLifecycle::stop_playback_for_modal_open` — refusal-gated, three editors + three prompts, the flag editor's exemption explicit at its declaration — the keyboard gate is `keyboard_modal_editor_active`). Accepted cost: no in-editor undo, the gap the bottom-strip editors always had. BPM mode is exactly its editor session. The GUI never writes a load-invalid state. ALL text uses PROPER capitalization (GUI-facing 2026-08-01; terminal stderr/stdout 2026-08-02, THE TERMINAL CAPITALIZATION PASS — text-only, otherwise byte-identical output, the wide frozen touch recorded per file): sentence-initial capitals after the program-name prefix, prose acronyms capped (JACK/WAV/PCM/BPM), data/identifier tokens keep their spelling, identifier-headed messages start verbatim, the engine's progress readout is structured not prose — full rules and the ruled holds in conventions.md. Never a double space. Bare `e` is the left mouse button, translated at the platform boundary (never bind it in dispatch); bare 1/2/3 are the ABSOLUTE VIEW SELECTORS (2026-08-01: S+W / T+P / T+W — combinations, not toggles; composed from the `t` and `p` handlers, audio first then markers so the coincidence auto-select reads the finished combination; S+P deliberately keyless; digits 4..9 unbound). STRICT MODIFIER VALIDATION (architect 2026-07-28): a modifier combination with no explicit binding is a no-op everywhere — Space and Escape bare-exact at every reader, the editors' session keys bare-exact and their clipboard chords ctrl-exact, the prompt case-sensitive; THREE families are deliberately untightened because the modifier is a real binding there — `is_tab_cycle` (Shift+Tab reverse-cycles), Ctrl+Z (Shift selects redo), and the editors' MOTION arm, which keeps ctrl and shift in every combination but excludes ALT (they carry real meaning on all six keys and degrade to the plain gesture where they add nothing, exactly as an ordinary one-line field does, so exactness would break them; alt binds nothing in the family). A stray modifier on an owned key shape is simply NotEditorKey and drops at the gate; the classifier stays the single keymap owner and no caller enumerates editor keys. SUPER IS DROPPED AT THE PLATFORM BOUNDARY (architect 2026-07-30 — super belongs to labwc): the modifier mask never modelled LOGO, so every bare-exact predicate accepted a held Super (Super+Escape discarded an open edit); the platform now tracks `mod_super_` and delivers NO key event while it is held — one gate at `deliver_key` covering physical presses and synthesized repeats, reset on keyboard-leave and capability loss, no fourth bool in any predicate. ALT IS NOW POINTER-ONLY (same ruling): alt+drag pan and alt+wheel pan, plus the five Ctrl+Alt render/propagate chords (R / Shift+R / I / P / Shift+P), and nothing else — the plain/augmented modifier convention died with `Alt+S` (bare `s` and the bare empty-lane double-click both drop the AUGMENTED marker, render-neutral except onto an occupied frame — where the exact-frame collapse to 1.00 is loud, the markers going red — and inside a label definition, whose span its references reproduce; both ruled non-problems 2026-07-28).

Warp and phase reset are co-equal axes; new pipeline surfaces ship both columns or record the asymmetry in a comment at the site. "Phase reset" is one concept token, never shortened to "reset" in names; warp is never the unmarked default. The recorded-asymmetry inventory lives in conventions.md.

### Rounding
Use `std::nearbyint` for banker's rounding wherever fractional values convert to integer-domain values (playhead placement, pixel mapping). No epsilon nudge. For authored positions specifically, `snap_authored_frame` (`app_state.h`) is the single conversion chokepoint; no other site may round or cast an authored position.
