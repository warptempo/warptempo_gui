# Warptempo GUI

Custom C++23 in-process PGHI phase-vocoder GUI, an Android APK for one tablet (the laptop is the APK's cross-build host and the headless CLI's host, nothing more; its own GUI was dropped 2026-10-30), for time-warping audio toward historically-informed tempos. Single developer and user (the architect); one laptop, one tablet. THE PROJECT IS NEAR FEATURE COMPLETE (architect 2026-10-25): what remains is palette updates, small bug fixes and layout refinement (the background sound landed 2026-10-28 as the NOISE lamp, `src/gui/noise.h`). THE DESIGN IS SETTLED: one look, the hi-fi panel; no other visual theme, icon set or chrome vocabulary will ever be built or proposed.

THE CODE IS THE AUTHORITY. Every rule and its reason lives in a comment at the symbol that owns it; when this file, a doc or a memory disagrees with the code, the code wins — read it before asserting anything. `docs/engineering/closed_questions.md` lists, one line each, every question the architect has closed: never re-propose one (its lines about retired looks are moot, not open). `docs/INSTALL.md` is the runbook, `docs/HELP.md` the user's concepts, the tooltips the interface's own words.

## Build Commands

```bash
bash apk/build_apk.sh                                 # THE PRODUCT: cross-build + APK in the main tree, against deps/prebuilt; the commit gate
adb -s 192.168.1.87:5555 install -r apk/build-android/warptempo.apk
adb -s 192.168.1.87:5555 shell am start -n com.warptempo.gui/.MainActivity
cmake -B build -S . && cmake --build build -j$(nproc) # the laptop's one product, build/warptempo_cli; no option, no CMAKE_BUILD_TYPE (asserts live; -O3 -march=native -ffp-contract=off)
cmake -B build-debug -S . -DCMAKE_BUILD_TYPE=Debug    # a debug CLI in its own dir; never reconfigure build/ with -O0
```

CMake has NO OPTIONS (architect 2026-10-30): an Android configuration builds the `warptempo_gui` NativeActivity library, a Linux one builds `warptempo_cli`, the headless insurance render, byte-identical to the GUI through the shared stages. No library archives: per-directory source lists compiled directly. `tools/` holds standalone utilities with no link path from product targets. `-ffp-contract=off` is load-bearing: renders are byte-reproducible across rebuilds and `-march` choices (`docs/engineering/perf_campaign_2026_07.md` §15). The GUI has one platform (`GuiPlatform` is `platform_android.{h,cpp}`, `src/gui/platform.h` its one include) and one canvas road, the GL draw list. The laptop's binary is not portable (`-march=native`); the APK is. THE APK BUILDS IN THE MAIN TREE from the working tree (the `tmp/apk_src` snapshot road is retired); every commit is gated on `bash apk/build_apk.sh`'s real exit code. The tablet (Galaxy Tab S10 FE) is adb-drivable (install, launch, screencap, single-touch, logcat); multi-touch and feel are the architect's own glass pass.

## Dependencies

The CLI on the laptop: pkg-config `fftw3` (+`fftw3_threads`) and nothing else. The APK: every library static from the gitignored `deps/prebuilt/`, cross-built by `deps/*.sh` (fftw, freetype, harfbuzz, pixman, cairo + cairo-ft, OpenSSL's libcrypto under libssh2 under libgit2, resvg from a pinned Rust source by `deps/85_resvg.sh`), the NDK / build-tools / JDK fetched by `deps/toolchain/`; EGL + GLESv3 and AAudio are the platform's. The APK build also needs host `resvg` and ImageMagick 7's `magick` (the launcher icon), `zip`, `meson` + `ninja` for the deps. Cairo stays as the chrome's painter onto the backbuffer under the GL road; the canvas interior is the GPU's draw list alone. Audio I/O is in-tree and WAV-only. C++23, `-Wall -Wextra`. No Pango, SDL, GTK, GLFW. The app paints no window chrome (full screen, both system bars hidden). Hardware keyboards and mice are out of scope on the tablet (`platform_android.cpp`'s key arm owns the ruling; the chord grammar stays, the on-screen keyboard runs on it). Statically linked libraries and licences: `THIRD_PARTY.md`.

Text: one face, LIBERATION SANS (Regular and Bold), the APK's assets from `fonts/`; nothing asks fontconfig. Every string goes through the one shaping chokepoint `src/gui/text_shape.{h,cpp}`; the sizes are one table, `kGuiFaceSizes` (`src/gui/gui_font.h`), authored in device px at 300 % and scaled with gui_scale. Text is UTF-8 in free text and ASCII in grammars; editors index by byte and step by codepoint; `text_editor::replace_selection` is the one incoming filter.

## Testing / Verification

There is NO automated test suite and that is a constraint. Do not propose automated tests, regression harnesses or commercial-tool comparisons. The CLI shares the stages with the GUI byte-identically; the architect runs cmp-null and audio verification against it. THERE IS NO LAPTOP EYEBALL ROAD (2026-10-30): every GUI check is adb on the tablet — `input tap` + `screencap` (two builds driven through the same states and compared byte for byte, the clock legend excepted, is the proof that a change left the picture alone; the drop arc was proven so, tmp/drop/); `adb logcat -s warptempo:I` when the screen dozes (a dozing tablet screencaps black); `dumpsys SurfaceFlinger --timestats` is the cadence proof. A tablet reboot kills wireless adb: re-arm over USB with `adb tcpip 5555`. The tablet's config is editable through `adb shell run-as com.warptempo.gui`. THE COLOR ROAD for any capture or mock he judges in the tablet's gallery (settled on his glass 2026-10-22 after four sessions of flipping; re-derived once since, so never again): THE iCCP TAG SAYS WHAT THE BYTES ARE — his Fossify Gallery honors the Display-P3 tag every screencap and every screenshot of his carries. A `true_colors=on` screencap (P3 bytes, tagged) is right as it is; a `true_colors=off` one (sRGB bytes, tagged) reads oversaturated and is right only with the tag STRIPPED. A color inserted into a tagged mock goes through the app's transform (`road.py`'s `srgb_to_p3`, `display_transform.h` byte for byte); into an untagged mock it is the plain sRGB byte. A mock composed on a fresh canvas (PIL `Image.new`) carries no tag, so its bytes must be sRGB; a JPEG conversion keeps the ICC profile. Never save P3 bytes untagged (pale) or sRGB bytes tagged (hot). `tools/mockup/README.md` owns the rule, `tools/mockup/road.py` is the tool (`capture` reads the tablet's `true_colors` and keeps or strips the tag; `srgb`, `p3`, `check`) — never re-derive it from a screenshot, which cannot see the panel.

## Standing Rules

- THE LOOK IS THE HI-FI PANEL (architect 2026-10-23, settled): a procedural brushed black-aluminium ground baked once per window geometry, the marker lane flat in the ground's mean (architect 2026-10-29: no brushing, no strip, the ring round it unchanged), blank flat keys with an LED and a printed legend naming the act the next press does, two key depths (checked one device px, held two), one-device-px hairlines in two ring tones off the ground's mean, bone F0F0F0 text, an accent off the waveform preset's ink hue for the lit LEDs. A logo lane (the quaver, "Warptempo", the battery + clock legend) is the top strip's upper pad on both devices; the app paints no caption or window frame. No picture replaces the ground: the `tiles/` override folder is retired (architect 2026-10-29, "keep it simple and not give myself options"). Owners: `src/gui/materials.h` (grounds, bake, tones, inks, keys, accent, glow), `cool_edit_paint.h` (`paint_key`, `paint_ce_time_field`), `render.h` (`hairline_px`, `skin_px`, the LOGO LANE block), `paint_handler.cpp` (the legends, `key_legend_layout`), `app_state.h` (`redesign_button_legend`, `redesign_button_enabled`), `src/gui/modal_box.h` (the modal box and controls row), `src/gui/onscreen_keyboard.h`. The only drawings painted are four SVGs in `assets/icons/` (the quaver, the folder, the cards' i and X); the quaver is also the launcher icon.
- WHAT REMAINS OF WINDOWS AND COOL EDIT is what the code holds, nothing more: from Windows, the relief / bevel helpers with mitred two-tone corners and the dialog conventions (underlined access keys on the dialogs' word buttons, OK / Cancel, Enter / Esc); from Cool Edit Pro 2.1, the canvas column's grammar — the view bar, ruler, marker lane, grid and center lines, cues, playhead, stereo divider — with its lengths in `src/gui/program_spec.h` and its tones in `src/gui/cool_edit_derive.h`. Accuracy to Cool Edit ranks below usability. THE WAVEFORM PRESETS ARE COOL EDIT PRO 2.1'S TWENTY, AS THEY ARE (architect 2026-10-26 late: "a full closed self-contained set"; the program's own families and the Terminal twins are gone, git history; no new preset is proposed): `tools/theme_catalog/warptempo_presets.txt` generated into `src/gui/palette_presets.inc` by `tools/theme_catalog/gen_presets.py`, never hand-edited; the user's list `docs/themes/catalog.md` by `catalog_md.py`; each named as Cool Edit's list names it, "Default" for "(Default Scheme)", keyed by that name in the key grammar with no prefix (`xp-blue`), listed alphabetically with Default among them (2026-10-27); the default `default`; the SETTINGS PAGE's `waveform` row lists them (the value list, `folder_overlay.h`; the SETUP key's long press and Shift+; retired 2026-10-28). Whether a preset may change the chrome is "not for now" (2026-10-26).
- ON THE WAVEFORM NOTHING IS SCALED: every line and dot the canvas carries is one device px (`waveform_line_px`); everything off the canvas is scaled. THE PLATE IS ANTIALIASED (architect 2026-10-30, on his glass against Ableton): exact coverage of one filled contour through the column centers with the FULL-INK CORE (every column's own extent stays full), the whole shape grown 0.5 device px (`kWaveformGrowSubcells`, render.h — a REASONED CONSTEXPR, never a tuning key: neighboring pixels spread the weight exactly at .5), the inner's outline the one-px border of the grown inner, blended source-over in byte space by the GL shader alone (`kListFragmentShader`, gl_canvas.cpp; the tips in quarter rows from `render_waveform_columns`); NO TIP RULE, NO GLOW (parked, never re-propose); the lines and dots keep whole cells, no AA. Chrome is not waveform: the divider and frames are inert to every gesture, and a gesture begun on the waveform runs on over chrome until the lift.
- FREEZE: `src/engine/`, `src/parser/`, `src/audio_io/` and `src/prepost/` are under permanent hard freeze, and `src/cli/cli_main.cpp` is freeze-adjacent. A change there is surgical and needs explicit architect approval, recorded at the site and in the commit ("(architect approval YYYY-MM-DD)"); comment-only residue there is pre-approved and still named in the commit. A retired perf candidate needs new measured data (`docs/engineering/perf_campaign_2026_07.md`).
- COMMENTS describe current behavior and rationale only, at the symbol that owns the rule, with the ruling's date; history belongs in git. An exhaustive enumeration lives at exactly one site per concept; before claiming "every site that does X", grep it.
- NO BACKSTOPS FOR ADVERSARIAL USE (architect 2026-09-28): a state reachable only by hand-edited files, tampered git config, a racing second actor or a perverse gesture sequence gets a hard fail and at most a stderr line. THE TWO-CATEGORY RULE at the load boundary: a state the GUI can commit always loads and renders; a state it can never produce hard-fails the load, first error only, identically in both binaries (`src/parser/marker_store_validate.h`). A rare non-silent fault gets no recovery code.
- VALIDATION DOCTRINE: every guard belongs to one of five classes with one owner each — (1) adversarial input → the LOAD boundary, first-error hard fail; (2) ambiguous authored state → the RESOLVER, normalizes and never refuses (`resolve_warp_markers_for_render`); (3) legal-but-unhonorable state → the owning stage refuses CONSTRUCTIVELY (`plan_trim`: a refusal renders untrimmed); (4) program bugs → the ENGINE INIT tripwires; (5) advisory signals, stderr-and-continue. THE TYPE RULE: an error arm exists iff a producer exists; total normalizers return plain values, partial compilers keep `std::expected`. Hit tests, the zone map, the cursor cue and domain clamps are not guards.
- ROUNDING: gui_scale is the integer percent of device px (the tablet 300). `skin_px` takes device px at 300 %; `scaled_px` takes the older W lengths in `program_spec.h`; both round AT THE ELEMENT (`std::nearbyint`), a composite being the sum of its rounded parts. `snap_authored_frame` is the only double→authored route; screen pixels are cells (`containing_pixel`); the painter grid step is in sixteenths of a frame (`painter_quantized_spp`); chrome labels center the cap band via `redesign_baseline`.
- NAMES: marker and related GUI types carry the `Gui` prefix; warp and phase reset are co-equal axes, "phase reset" is one token, warp is never the unmarked default (`src/gui/warpmarkers.h`'s head). American spelling in new text.
- TEXT follows kdenlive's conventions: names Title Case, descriptions sentence case; a tooltip names the act and its key in the accelerator spelling, "Save (Ctrl+S)", plus at most its modifier line (architect 2026-10-27, keep; `redesign_button_tooltip`'s head); a card is one clause and a prompt is a question; a card or label never names a key, the one other key text being the dialogs' and menus' always-shown underlined access keys (`src/gui/notifications.h`'s head).
- ON SCREEN IS AS PAINTED: input acts on the picture last painted (`displayed_or_live_target_map`, `app_state.h`); every button is truthful, greying whenever its act would be a no-op (`redesign_button_enabled`). THREE CLASSES OF SURFACE: the OVERLAYS (the render player, the project picker, the settings page and the value list it swaps in, the trim presets list, the score viewer) are interface — their opener key sits lit and closes them, they stay standing under their own question (the box's button word says what leaving does, `kModalCancelLabel`'s rule: Close on the settings page and the render player, Cancel where a choice is asked, OK / Cancel on the editors); the MODALS (prompts, dialog editors, the progress modal, the flag and bound editors) veil everything, a bound chord silent, Esc and Enter the way out (the key is "Enter" in every product word since 2026-10-29 night, `spell_chord`) (`keyboard_modal_editor_active`, `src/gui/input_handler.h`); the HISTORY VIEW is a view like Source or Phase.
