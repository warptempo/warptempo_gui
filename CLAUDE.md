# Warptempo GUI

Custom C++23 in-process PGHI phase-vocoder GUI (Arch / labwc / Wayland / JACK, plus an Android build for one tablet) for time-warping audio toward historically-informed tempos. Single developer and user (the architect); one authoring laptop, one authoring tablet. THE PROJECT IS COMPLETE (architect 2026-09-30): what remains is small bug fixes and layout refinement, never new scope. THE CODE COMMENTS ARE THE AUTHORITATIVE RECORD of every rule and its reason, each at the symbol that owns it; `docs/engineering/closed_questions.md` lists, one line each, every question the architect has closed — read it before proposing anything, and never re-propose a line of it. This file carries the build, the process rules and a map of where to look. `docs/INSTALL.md` is the runbook (installing, building, the tablet, upkeep); `docs/HELP.md` the user's concepts; the interface's own words are its tooltips.

## Build Commands

```bash
cmake -B build -S . -DWARPTEMPO_BUILD_CLI=ON          # configure (first time or after CMakeLists changes)
cmake --build build -j$(nproc)                        # no CMAKE_BUILD_TYPE: asserts live; -O3 -march=native -ffp-contract=off always on
cmake -B build-debug -S . -DCMAKE_BUILD_TYPE=Debug    # debug goes in its own dir; never reconfigure build/ with -O0
cmake -B build-nogit -S . -DWARPTEMPO_GUI_GIT=OFF     # a build host without libgit2 (the cloud): graphical work only, the git road a stub; the two devices build ON
bash android/app/build_apk.sh                         # the tablet: cross-build + APK against android/prebuilt
adb -s 192.168.1.87:5555 install -r android/app/build-android/warptempo.apk
adb -s 192.168.1.87:5555 shell am start -n com.warptempo.gui/.MainActivity
```

`build/warptempo_gui` is the default build's only product. No library archives: four per-directory source-list variables each binary compiles directly. `warptempo_cli` (opt-in; a headless host adds `-DWARPTEMPO_BUILD_GUI=OFF`) is the headless insurance render, byte-identical to the GUI through the shared stages. `tools/` holds standalone one-shot utilities with no link path from product targets. `-ffp-contract=off` is load-bearing: renders are byte-reproducible across rebuilds and `-march` choices (`docs/engineering/perf_campaign_2026_07.md` §15). One build host (the laptop) builds both products over the one portable GUI (`GuiPlatform`, `src/gui/platform.h`). Linux binaries are not portable (`-march=native`); the APK is. The tablet (Galaxy Tab S10 FE) is adb-drivable (install, launch, screencap, single-touch, logcat); multi-touch and feel are the architect's own glass pass.

## Dependencies

pkg-config: `fftw3` (+`fftw3_threads`), `wayland-client`, `wayland-cursor`, `wayland-protocols`, `xkbcommon`, `cairo`, `cairo-ft` (FreeType, which both binaries drive directly for the embedded faces; no font package is needed), `harfbuzz`, `jack`, `libgit2` (the GUI only, its SSH transport libssh2; the CLI links no git; `-DWARPTEMPO_GUI_GIT=OFF` swaps in `src/gui/git_repo_stub.cpp` for a host that cannot provide libgit2 1.9 — every git act then reports that git is not available); `wayland-scanner` at build time. The APK carries libgit2 over libssh2 over OpenSSL's libcrypto, static from `android/prebuilt` (`android/deps/60–80`), the manifest declaring INTERNET. Audio I/O is in-tree and WAV-only. C++23, `-Wall -Wextra`. No Pango, SDL, GTK, GLFW or wlroots-specific protocols: libwayland-client only, `wayland-cursor` the one exception. Protocol stubs: xdg-shell and xdg-decoration (required); pointer-constraints + relative-pointer (strip-drag capture; absence degrades to clamped motion). Five required globals, `wl_data_device_manager` (the clipboard) included.

Text: proportional text through the one shaping chokepoint `src/gui/text_shape.{h,cpp}`, the faces compiled into both binaries from the repository's `fonts/` (provenance and licences in its README; architect 2026-10-02: "the app becomes its own thing"; the laptop asks fontconfig nothing; `src/gui/gui_font.h` owns them). ONE FACE AT EVERY SCALE (architect 2026-10-06; the period bitmap faces retired the same day: "100 % is completely unusable on the tablet and serves only as a curiosity"): NIMBUS SANS (URW base35's Helvetica, AGPL-3 with its PS/PDF embedding exception, pinned in fonts/README.md; Regular for the body and the small / ruler face, Bold for the caption's title alone) with SLIGHT hinting, its em DERIVED at the install so its height matches THE RECORDED WINDOWS METRICS (`kGuiFaceMetrics`, gui_font.h: MS Sans Serif 8's 13-px cell, ascent 11 + descent 2, caps 9, for the body and the bold; Small Fonts' 7-row digit for the small; Nimbus's own line box, which seats high elsewhere, is never read). THOSE CONSTANTS ARE THE ONLY VERTICAL METRIC SOURCE (line boxes, baselines, the flag box, the lane heights); horizontally Nimbus keeps its own true advances LESS THE TRACKING (`kGuiTrackingPx`, 3/16 W px per glyph at every scale, architect 2026-10-06, judged on the tablet at 400 against the strike x4) and widths are measured from the live face; a glyph poking past a box is accepted; the flag box is the whole cell (17 W px, 2026-10-05). Roboto and Liberation retired. NO MONOSPACE (Roboto Mono retired 2026-10-05): every time shows in the body face's tabular digits inside a fixed-width TIME FIELD, the period's 17-px one-line sunken field (`kTimeFieldHeightPx`, paint_handler.cpp; row 8's clock, the player's position and length). TEXT IS UTF-8 IN FREE TEXT AND ASCII IN GRAMMARS. Editors index by byte and step by codepoint; `text_editor::replace_selection` is the one incoming filter.

## Running

```bash
./build/warptempo_gui                      # opens last_project from the device config, else the first valid project folder
./build/warptempo_gui <project source.wav>  # must be a project's SOURCE directly under projects_path (else a refusal, exit 1)
```

labwc on Arch; 1920x1080@60 laptop. No portability shims, no X11 fallback.

## Testing / Verification

There is NO automated test suite and that is a constraint: Wayland exposes no input-injection path. Do not propose automated tests, regression harnesses or commercial-tool comparisons. The CLI shares the stages with the GUI byte-identically; the architect runs cmp-null and audio verification against it and owns labwc verification. On the tablet, logcat (`adb logcat -s warptempo:I`) is the verification road when the screen is dozing (a dozing tablet screencaps black). A tablet reboot kills wireless adb; re-arm over USB with `adb tcpip 5555`. The tablet's config is editable through `adb shell run-as com.warptempo.gui` (debuggable build).

## Standing Rules

- FREEZE: `src/engine/`, `src/parser/`, `src/audio_io/` and `src/prepost/` are under permanent hard freeze, and `src/cli/cli_main.cpp` is freeze-adjacent. Changes there are surgical and each needs explicit architect approval, recorded at the site and in the commit ("(architect approval YYYY-MM-DD)"); comment-only residue in frozen files is pre-approved (architect 2026-09-28) and still named in the commit. A retired perf candidate needs new measured data (`docs/engineering/perf_campaign_2026_07.md`).
- COMMENTS describe current behavior and rationale only, at the symbol that owns the rule, with the ruling's date; no dead-process citations, no review-round or decision numbers. History belongs in git. Before claiming "every site that does X", grep it; an exhaustive enumeration lives at exactly one authoritative site per concept.
- NO BACKSTOPS FOR ADVERSARIAL USE (architect 2026-09-28): the single user never feeds hostile input; a state reachable only by hand-edited files, tampered git config, a second actor racing the app or a perverse gesture sequence gets a hard fail and at most a stderr line — no recovery paths, no pre-validation layers. THE TWO-CATEGORY RULE at the load boundary: a state the GUI can commit always loads and renders (ambiguity normalized at the render boundary, red flags the cue); a state it can never produce hard-fails the load, first error only, identically in both binaries (`src/parser/marker_store_validate.h`).
- VALIDATION DOCTRINE: every guard belongs to one of five classes with one owner each — (1) adversarial input → the LOAD boundary, first-error hard fail; (2) ambiguous authored state → the RESOLVER, normalizes and never refuses (`resolve_warp_markers_for_render`); (3) legal-but-unhonorable state → the owning stage refuses CONSTRUCTIVELY (`plan_trim`: a refusal renders untrimmed); (4) program bugs → the ENGINE INIT tripwires, the last point before silently wrong bytes; (5) advisory signals, stderr-and-continue, never fatal. A predicate may stand at two boundaries only when the downstream owner cannot catch it cleanly, the upstream site has words the downstream lacks, or an architect symmetry ruling covers it — the justification stated at the site. THE TYPE RULE: an error arm exists iff a producer exists (reachable, breach-only or IO), the site naming which; total normalizers return plain values, partial compilers keep `std::expected`. Hit tests, the zone map, the cursor cue and the domain clamps are not guards.
- ROUNDING AND THE UNIT (architect 2026-10-02): every chrome length is authored in WINDOWS-95 PIXELS (the number Windows 95 drew at 96 dpi) and gui_scale is the integer percent of device px per Windows px (the tablet 275, the laptop 138); `scaled_px` is the one road, rounding AT THE ELEMENT (`std::nearbyint`) and never at the scale — a composite is the sum of its rounded parts (a button case = offset + glyph + offset), never a rounded whole. `std::nearbyint` wherever values convert to grid points; `snap_authored_frame` is the only double→authored route; screen pixels are cells (`containing_pixel`); the painter grid step is in sixteenths of a frame (`painter_quantized_spp`); chrome labels centre the cap band via `redesign_baseline`, a text line takes `line_baseline`.
- NAMES: marker and related GUI types carry the `Gui` prefix; warp and phase reset are co-equal axes, "phase reset" is one token, warp is never the unmarked default; a new type name follows the symmetry (`src/gui/warpmarkers.h`'s head).
- COLOURS ARE A THEME'S ROLES, NEVER DERIVED IN THE APP (architect 2026-10-03; theme files 2026-10-04): every colour the GUI paints is one of 36 ROLES (`kGuiThemeRoles`, `src/gui/theme_file.h`, the one enumeration): the chrome (the caption's active and inactive start, gradient end and text — a file naming a start without its end gets a flat caption; ground, label, the relief quartet Hilight / 3DLight / Shadow / DkShadow, the selected and field pairs, the time fields' ground and text, the card's ground, text and frame) and the program's own elements (the waveform's canvas, ink and lit outline; a face and a selected face per FLAG KIND — warp, phase reset, the history's added and removed, the invalid flag wearing the removed pair; one flag label and one selected label; the playhead's stem and the scanner; the playhead's head is WordPad's ruler marker in chrome roles, 2026-10-05). ONE BUILT-IN, compiled: `windows-95-standard` (Windows 95 Standard's recorded chrome, the program's colours from Windows' 20 solid colours), the default `theme`; every other theme is a FILE `<key>.theme` in `themes/` beside the device config, read once at launch, `role=value` lines (`#rrggbb` or one of the 20 names), a role it does not name taking the built-in's value, any violation the launch's first-error hard fail; the bundled files (the imported catalog, `warptempo`, his picker presets) are generated into the repository's `assets/themes/` (`tools/theme_catalog/gen_theme_files.py`; regenerate, never hand-edit) and copied in at every launch, the bundle winning for its own names (architect 2026-10-05; the APK packs them as assets, the laptop reads the path compiled in). The device key `theme` chooses (no level: the dark level is dropped). Text over a fill is the theme's recorded pair (no luminance rule); every disabled word and glyph is Windows' DSS_DISABLED emboss (its light copy Hilight); the one named literal beside the palette is the flag editor's black frame; a refusal recolours no frame (the whole text selected, the reason on a card). Every colour is opaque, THE PALETTE COMPOSITES NOTHING (no paint-time alpha), no gradients but THE CAPTION'S (2026-10-05: start to end per channel, quantised to 15-bit high colour under the ordered 4x4 dither read off his Windows 2000 reference, one Windows px a cell — `paint_caption_gradient`, render.cpp; a flat caption the exact colour), no rounded corners, no hover faces; the edges are Windows' two-line DrawEdge families (SOFT on the toolbar and the caption buttons, PLAIN on push buttons, the restored laptop's sizing frame, thumbs, menus, fields and the well, their sunken mirrors, the one-line STATUS panel and the time fields, etched ticks) and the cards' and tooltip's one-line flat frame. `src/gui/render.h`'s palette block (`palette()`) is authoritative; codex is skipped for colour tuning.
- TEXT follows kdenlive's conventions: names Title Case, descriptions sentence case; a tooltip is the act's name and nothing else; a card is one clause and a prompt is a question; no key hints in UI text (`src/gui/paint_handler.cpp`'s capitalization block, `src/gui/notifications.h`'s head).
- ON SCREEN IS AS PAINTED: input acts on the picture the user is looking at — a press resolves against the geometry and the face the painter last put on screen, never a live derivation a tick ahead (`displayed_or_live_target_map`, `src/gui/app_state.h`); every roster button is truthful, greying whenever its act would be a no-op (`redesign_button_enabled`); the keyboard answers with its own card (`chord_is_bound`, `src/gui/gui_input.h`).
