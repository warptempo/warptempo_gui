# Warptempo GUI

Custom C++23 in-process PGHI phase-vocoder GUI (Arch / labwc / Wayland / JACK, plus an Android build for one tablet) for time-warping audio toward historically-informed tempos. Single developer and user (the architect); one laptop, one tablet. THE PROJECT IS NEAR FEATURE COMPLETE (architect 2026-10-25): what remains is palette updates, a background-sound function, small bug fixes and layout refinement. THE DESIGN IS SETTLED: one look, the hi-fi panel; no other visual theme, icon set or chrome vocabulary will ever be built or proposed.

THE CODE IS THE AUTHORITY. Every rule and its reason lives in a comment at the symbol that owns it; when this file, a doc or a memory disagrees with the code, the code wins — read it before asserting anything. `docs/engineering/closed_questions.md` lists, one line each, every question the architect has closed: never re-propose one (its lines about retired looks are moot, not open). `docs/INSTALL.md` is the runbook, `docs/HELP.md` the user's concepts, the tooltips the interface's own words.

## Build Commands

```bash
cmake -B build -S . -DWARPTEMPO_BUILD_CLI=ON          # configure (first time or after CMakeLists changes)
cmake --build build -j$(nproc)                        # no CMAKE_BUILD_TYPE: asserts live; -O3 -march=native -ffp-contract=off always on
cmake -B build-debug -S . -DCMAKE_BUILD_TYPE=Debug    # debug in its own dir; never reconfigure build/ with -O0
cmake -B build-nogit -S . -DWARPTEMPO_GUI_GIT=OFF -DWARPTEMPO_CANVAS=cpu   # a host without libgit2 or EGL: git a stub, the cairo canvas
bash android/app/build_apk.sh                         # the tablet: cross-build + APK against android/prebuilt (GL canvas)
WT_CANVAS=cpu bash android/app/build_apk.sh           # the CPU-canvas reference APK, for the screencap identity proof alone
adb -s 192.168.1.87:5555 install -r android/app/build-android/warptempo.apk
adb -s 192.168.1.87:5555 shell am start -n com.warptempo.gui/.MainActivity
```

`build/warptempo_gui` is the default build's only product; `warptempo_cli` (opt-in; `-DWARPTEMPO_BUILD_GUI=OFF` for a headless host) is the headless insurance render, byte-identical to the GUI through the shared stages. No library archives: per-directory source lists compiled directly. `tools/` holds standalone utilities with no link path from product targets. `-ffp-contract=off` is load-bearing: renders are byte-reproducible across rebuilds and `-march` choices (`docs/engineering/perf_campaign_2026_07.md` §15). The laptop builds both products over the one portable GUI (`GuiPlatform`, `src/gui/platform.h`). Linux binaries are not portable (`-march=native`); the APK is. The tablet (Galaxy Tab S10 FE) is adb-drivable (install, launch, screencap, single-touch, logcat); multi-touch and feel are the architect's own glass pass.

## Dependencies

pkg-config: `fftw3` (+`fftw3_threads`), `wayland-client`, `wayland-cursor`, `wayland-protocols`, `xkbcommon`, `egl`, `glesv2`, `wayland-egl` (the GL canvas, `WARPTEMPO_CANVAS=gl`, the default; `cpu` is the cairo reference), `cairo`, `cairo-ft`, `harfbuzz`, `jack`, `libgit2` (GUI only; `-DWARPTEMPO_GUI_GIT=OFF` swaps in `src/gui/git_repo_stub.cpp`); `wayland-scanner` at build time; Rust (rustup) for resvg, built from a pinned source into `build/resvg/` (`android/deps/85_resvg.sh` on the tablet side). The APK build also needs host `resvg` and ImageMagick 7's `magick` (the launcher icon). The APK carries libgit2 over libssh2 over OpenSSL's libcrypto, static from `android/prebuilt`. Audio I/O is in-tree and WAV-only. C++23, `-Wall -Wextra`. No Pango, SDL, GTK, GLFW or wlroots-specific protocols. Required Wayland protocols: xdg-shell and xdg-decoration (labwc draws the laptop's title bar and frame; the app paints no window chrome on either device); pointer-constraints + relative-pointer are optional. Statically linked libraries and licences: `THIRD_PARTY.md`.

Text: one face, LIBERATION SANS (Regular and Bold), compiled into both binaries from `fonts/`; the laptop asks fontconfig nothing. Every string goes through the one shaping chokepoint `src/gui/text_shape.{h,cpp}`; the sizes are one table, `kGuiFaceSizes` (`src/gui/gui_font.h`), authored in device px at 300 % and scaled with gui_scale. Text is UTF-8 in free text and ASCII in grammars; editors index by byte and step by codepoint; `text_editor::replace_selection` is the one incoming filter.

## Running

```bash
./build/warptempo_gui                       # opens last_project from the device config, else the first valid project folder
./build/warptempo_gui <project source.wav>  # must be a project's SOURCE directly under projects_path (else a refusal, exit 1)
```

## Testing / Verification

There is NO automated test suite and that is a constraint: Wayland exposes no input-injection path. Do not propose automated tests, regression harnesses or commercial-tool comparisons. The CLI shares the stages with the GUI byte-identically; the architect runs cmp-null and audio verification against it and owns labwc verification. On the tablet: adb `input tap` + `screencap` (two builds driven through the same states and compared byte for byte is the GPU canvas's identity proof, `docs/engineering/gpu_canvas_2026_10.md` §5); `adb logcat -s warptempo:I` when the screen dozes (a dozing tablet screencaps black); `dumpsys SurfaceFlinger --timestats` is the cadence proof. A tablet reboot kills wireless adb: re-arm over USB with `adb tcpip 5555`. The tablet's config is editable through `adb shell run-as com.warptempo.gui`. THE COLOR ROAD for any capture or mock he judges in the tablet's gallery (settled on his glass 2026-10-22 after four sessions of flipping; re-derived once since, so never again): THE iCCP TAG SAYS WHAT THE BYTES ARE — his Fossify Gallery honors the Display-P3 tag every screencap and every screenshot of his carries. A `true_colors=on` screencap (P3 bytes, tagged) is right as it is; a `true_colors=off` one (sRGB bytes, tagged) reads oversaturated and is right only with the tag STRIPPED. A color inserted into a tagged mock goes through the app's transform (`road.py`'s `srgb_to_p3`, `display_transform.h` byte for byte); into an untagged mock it is the plain sRGB byte. A mock composed on a fresh canvas (PIL `Image.new`) carries no tag, so its bytes must be sRGB; a JPEG conversion keeps the ICC profile. Never save P3 bytes untagged (pale) or sRGB bytes tagged (hot). `tools/mockup/README.md` owns the rule, `tools/mockup/road.py` is the tool (`capture` reads the tablet's `true_colors` and keeps or strips the tag; `srgb`, `p3`, `check`) — never re-derive it from a screenshot, which cannot see the panel.

## Standing Rules

- THE LOOK IS THE HI-FI PANEL (architect 2026-10-23, settled): a procedural brushed black-aluminium ground baked once per window geometry, a brighter brushed marker lane that pans with the cues, blank flat keys with an LED and a printed legend naming the act the next press does, two key depths (checked one device px, held two), one-device-px hairlines in two ring tones off the ground's mean, bone F0F0F0 text, an accent off the waveform preset's ink hue for the lit LEDs. A logo lane (the quaver, "Warptempo", the battery + clock legend) is the top strip's upper pad on both devices; the app paints no caption or window frame. An optional `tiles/` folder beside the device config may replace the ground (`Ground.png|jpg`) or the marker strip (`Marker.png|jpg`). Owners: `src/gui/materials.h` (grounds, bake, tones, inks, keys, accent, glow), `cool_edit_paint.h` (`paint_key`, `paint_ce_time_field`), `render.h` (`hairline_px`, `skin_px`, the LOGO LANE block), `paint_handler.cpp` (the legends, `key_legend_layout`), `app_state.h` (`redesign_button_legend`, `redesign_button_enabled`), `src/gui/modal_box.h` (the modal box and controls row), `src/gui/onscreen_keyboard.h`. The only drawings painted are four SVGs in `assets/icons/` (the quaver, the folder, the cards' i and X); the quaver is also the launcher icon.
- WHAT REMAINS OF WINDOWS AND COOL EDIT is what the code holds, nothing more: from Windows, the relief / bevel helpers with mitred two-tone corners and the dialog conventions (underlined access keys on the dialogs' word buttons, OK / Cancel, Enter / Esc); from Cool Edit Pro 2.1, the canvas column's grammar — the view bar, ruler, marker lane, grid and center lines, cues, playhead, stereo divider — with its lengths in `src/gui/program_spec.h` and its tones in `src/gui/cool_edit_derive.h`. Accuracy to Cool Edit ranks below usability. THE WAVEFORM PRESETS ARE THE PROGRAM'S OWN (architect 2026-10-25 night: the phosphor family, Cool Edit's twenty presets deleted that night, git history): `tools/theme_catalog/warptempo_presets.txt` generated into `src/gui/palette_presets.inc` by `tools/theme_catalog/gen_presets.py`, never hand-edited; the user's list `docs/themes/catalog.md` by `catalog_md.py`; the default `warptempo-terminal-default`; the SETUP key's long press (Shift+;) lists them (the preset picker, `folder_overlay.h`).
- ON THE WAVEFORM NOTHING IS SCALED: every line and dot the canvas carries is one device px (`waveform_line_px`); everything off the canvas is scaled. Chrome is not waveform: the divider and frames are inert to every gesture, and a gesture begun on the waveform runs on over chrome until the lift.
- FREEZE: `src/engine/`, `src/parser/`, `src/audio_io/` and `src/prepost/` are under permanent hard freeze, and `src/cli/cli_main.cpp` is freeze-adjacent. A change there is surgical and needs explicit architect approval, recorded at the site and in the commit ("(architect approval YYYY-MM-DD)"); comment-only residue there is pre-approved and still named in the commit. A retired perf candidate needs new measured data (`docs/engineering/perf_campaign_2026_07.md`).
- COMMENTS describe current behavior and rationale only, at the symbol that owns the rule, with the ruling's date; history belongs in git. An exhaustive enumeration lives at exactly one site per concept; before claiming "every site that does X", grep it.
- NO BACKSTOPS FOR ADVERSARIAL USE (architect 2026-09-28): a state reachable only by hand-edited files, tampered git config, a racing second actor or a perverse gesture sequence gets a hard fail and at most a stderr line. THE TWO-CATEGORY RULE at the load boundary: a state the GUI can commit always loads and renders; a state it can never produce hard-fails the load, first error only, identically in both binaries (`src/parser/marker_store_validate.h`). A rare non-silent fault gets no recovery code.
- VALIDATION DOCTRINE: every guard belongs to one of five classes with one owner each — (1) adversarial input → the LOAD boundary, first-error hard fail; (2) ambiguous authored state → the RESOLVER, normalizes and never refuses (`resolve_warp_markers_for_render`); (3) legal-but-unhonorable state → the owning stage refuses CONSTRUCTIVELY (`plan_trim`: a refusal renders untrimmed); (4) program bugs → the ENGINE INIT tripwires; (5) advisory signals, stderr-and-continue. THE TYPE RULE: an error arm exists iff a producer exists; total normalizers return plain values, partial compilers keep `std::expected`. Hit tests, the zone map, the cursor cue and domain clamps are not guards.
- ROUNDING: gui_scale is the integer percent of device px (the tablet 300; the laptop 200 for inspection, about 150 for use). `skin_px` takes device px at 300 %; `scaled_px` takes the older W lengths in `program_spec.h`; both round AT THE ELEMENT (`std::nearbyint`), a composite being the sum of its rounded parts. `snap_authored_frame` is the only double→authored route; screen pixels are cells (`containing_pixel`); the painter grid step is in sixteenths of a frame (`painter_quantized_spp`); chrome labels center the cap band via `redesign_baseline`.
- NAMES: marker and related GUI types carry the `Gui` prefix; warp and phase reset are co-equal axes, "phase reset" is one token, warp is never the unmarked default (`src/gui/warpmarkers.h`'s head). American spelling in new text.
- TEXT follows kdenlive's conventions: names Title Case, descriptions sentence case; a tooltip is the act's name and nothing else; a card is one clause and a prompt is a question; no key hints in UI text except the dialogs' always-shown underlined access keys (`src/gui/notifications.h`'s head).
- ON SCREEN IS AS PAINTED: input acts on the picture last painted (`displayed_or_live_target_map`, `app_state.h`); every button is truthful, greying whenever its act would be a no-op (`redesign_button_enabled`). THREE CLASSES OF SURFACE: the OVERLAYS (render player, project picker) are interface — their opener key sits lit and closes them, they stay standing under their own question; the MODALS (prompts, dialog editors, the progress modal, the flag and bound editors) veil everything, a bound chord silent, Esc and Return the way out (`keyboard_modal_editor_active`, `src/gui/input_handler.h`); the HISTORY VIEW is a view like Source or Phase.
