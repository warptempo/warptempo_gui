# Warptempo GUI

Custom C++23 in-process PGHI phase-vocoder GUI (Arch / labwc / Wayland / JACK) for time-warping audio toward historically-informed tempos. Single developer/user (the architect); one authoring laptop. PROJECT STATUS: FEATURE COMPLETE (architect, 2026-07-25). The authoritative architecture rulings live in `docs/engineering/architecture/` — see the docs map below. ## Build Commands

```bash
# Configure (from project root, first time or after CMakeLists changes)
cmake -B build -S . -DWARPTEMPO_BUILD_CLI=ON

# Build (Release is the project default; -O3 -march=native -ffp-contract=off is always on)
cmake --build build -j$(nproc)

# Debug build into a separate dir; never reconfigure `build/` itself with -O0
cmake -B build-debug -S . -DCMAKE_BUILD_TYPE=Debug
cmake --build build-debug -j$(nproc)
```

```bash
# Android (the tablet): cross-build + APK, statically against android/prebuilt
bash android/app/build_apk.sh        # then: adb install -r android/app/build-android/warptempo.apk
```

`build/warptempo_gui` is the GUI binary and the default build's only product. No library archives: four per-directory source-list variables (`WARPTEMPO_AUDIO_IO_SOURCES`, `WARPTEMPO_PARSER_SOURCES`, `WARPTEMPO_ENGINE_SOURCES`, `WARPTEMPO_PREPOST_SOURCES`) each binary compiles directly — object-code duplication accepted deliberately. One opt-in binary, default OFF: `warptempo_cli` (`-DWARPTEMPO_BUILD_CLI=ON`, the headless insurance render — exactly the terminal Ctrl+Alt+R, byte-identical to the GUI by shared stages; a headless host builds it with `-DWARPTEMPO_BUILD_GUI=OFF`). `tools/` holds standalone one-shot utilities (own CMakeLists, no link path from product targets). `-ffp-contract=off` is load-bearing: renders are byte-reproducible across rebuilds and `-march` choices under the same toolchain (scope in `docs/engineering/perf_campaign_2026_07.md` §15).

THERE IS ONE BUILD HOST, the authoring laptop, and ONE GLASS HOST, the Android tablet (Galaxy Tab S10 FE; the Pi rig is returned — "from the rig" in a source comment is the PROVENANCE of a ruling taken on that panel). The laptop builds BOTH: the Wayland product and, since 2026-08-26, the Android APK over the same portable GUI (`docs/engineering/architecture/platform-seam.md`). A laptop build proves compilation and the pointer/keyboard path only; the tablet is adb-drivable (install, launch, screencap, single-touch injection, logcat), so a coder CAN verify paint and one-finger touch on the device — multi-touch and feel stay the architect's glass pass. Linux binaries are not portable (`-march=native`); the APK is.

## Dependencies

pkg-config: `fftw3` (+`fftw3_threads`), `wayland-client`, `wayland-cursor`, `wayland-protocols`, `xkbcommon`, `cairo`, `cairo-ft`, `harfbuzz`, `jack`; plus `wayland-scanner` at build time. All audio container I/O is in-tree and WAV-only, so the non-GUI sources need only `fftw3`. C++23 (`std::expected` in the parser), `-Wall -Wextra`. Do not introduce Pango, SDL, GTK, GLFW, or wlroots-specific protocols — the GUI is libwayland-client only (`wayland-cursor` the canonical exception). Generated protocol stubs: xdg-shell, xdg-decoration (REQUIRED at startup), pointer-constraints-unstable-v1 + relative-pointer-unstable-v1 (the strip-drag pointer capture — the ONLY optional protocols; absence degrades to clamped absolute motion). The required-globals set is five, `wl_data_device_manager` (system clipboard, core protocol) included.

Text: proportional text measures AND paints through the ONE shaping chokepoint `src/gui/text_shape.{h,cpp}` (contract in its header) on the one sans face (fontconfig "sans", 12pt × gui_scale); the row-8 CLOCK is the product's monospace surface (fontconfig "monospace", normal weight), joined 2026-08-28 by the render player's modal clock — one face, two cells. TEXT IS UTF-8 IN FREE TEXT AND ASCII IN GRAMMARS: editor buffers and free-text settings values take UTF-8 verbatim and round-trip byte-identically; every structural grammar (marker labels, numeric spellings, settings keys/vocabularies, canonical-line payload, the MARKER MEASURE suffix ` //<measure>` on both sidecars — `src/parser/marker_measure.h`, its one-day free-UTF-8 comment predecessor retired 2026-08-20) stays ASCII with one canonical spelling per value. Editors index by byte but step by CODEPOINT; no font fallback, no bidi, graphemes out of scope; `text_editor::replace_selection` is the one incoming filter. Contract at the head of text_editor.h; full ruling in conventions.md.

## Testing / Verification / Roles

There is NO automated test suite and that is a CONSTRAINT, not a preference: Wayland exposes no input-injection path, so a GUI harness is not buildable here. Do not propose automated tests, regression harnesses, or commercial-tool comparisons. The CLI shares the parser/engine/prepost/audio-io stages with the GUI byte-identically; the architect runs cmp-null and audio verification against it, and owns labwc verification.

Roles: the CODER (implementation subagent) is the ONLY writer of source code — it edits files only, runs no MUTATING git (read-only status/diff/log/show fine and encouraged), never stages or commits, never launches labwc or drives the GUI. Build/compile checks are not part of a brief unless the architect asks. The external reviewer (CODEX) is REPORT-ONLY: finds and describes defects and residue, changes no source and no docs, runs read-only git freely — state this in every codex brief. ## Architecture Rules (MUST follow — digests; the topic files are authoritative)

### Freeze Status (architect-declared 2026-07-12)
`src/engine/`, `src/parser/`, `src/audio_io/`, and `src/prepost/` are under PERMANENT HARD FREEZE: surgical changes only, each requiring explicit architect approval to reopen. `src/cli/cli_main.cpp` is freeze-adjacent (same discipline). Only GUI work remains. EVERY GRANTED FROZEN TOUCH RECORDS ITS GRANT at the site and in the commit message ("(architect approval YYYY-MM-DD)"). A retired perf candidate needs new measured data to re-propose (perf_campaign_2026_07.md).

### Authored Domain (→ data-model.md)
Authored positions (marker times, trim bounds) are whole source frames in `int64_t` everywhere at rest; `snap_authored_frame` (app_state.h) is the ONLY double→authored conversion route. Authored tempo is 100-based integer CENTS in [25, 400]; every other value is a bracketed double via `value_format.h`. One serialization domain (`frame_format.h`): canonical integer spelling only — anything else is adversarial load-fatal. Walls are exact integer compares on the shared inclusive [0, total−1] domain. Sources: WAV-only, 16/24-bit PCM, ≥44100 Hz, stereo-only.

### Pixel Anchoring, Viewport, Zoom (→ zoom-viewport-strip.md, kdenlive-redesign.md)
Position gestures anchor to the painted column grid and commit through `authored_frame_at_column` → `snap_authored_frame`; walls win over the grid everywhere. Waveform width floors to a multiple of 16px; `clamp_viewport_start` is the one viewport chokepoint (owns the zoom-level clamp too). Zoom is continuous in [1.0, 17.0]; `c` = working zoom 2.0; `0` = full zoom out, STAMPING the level it leaves into the tab's `zoom_recall_level` (session-only, unpersisted), and at the ceiling the `c` command AT THAT STAMPED LEVEL — plain `c` when nothing is stamped, and plain `c` too when the stamp can no longer move the zoom (a ceiling that fell under it). The TOP STRIP IS SEVEN LANES (menu row / tab row / icon row / overview strip / trim bar / ruler / marker lane) plus ONE unified bottom row; the vertical stack has ONE owner in main.cpp (waveform max height `kWaveformMaxHeightPx`, waveform midpoint = window midpoint, both flexible gaps floor at 0; the kdenlive-redesign.md commit-B section is authoritative for the stack). ### Render Pipeline (→ render-pipeline.md)
The parser is the sole authored→engine compiler (phase resets emit `S − N/2`, no render-time offset anywhere); geometry in `engine_geometry.h`. Trim is a prepost stage: full maps → `plan_trim` (refusal = render untrimmed, never a failed render) → trim-ignorant engine → `post_trim` → unconditional limiter → encode. No subprocesses in the render path. Ctrl+Alt+R is TWO commands selected by the iteration-mode bit (single render / iteration sweep); Ctrl+Alt+Shift+R archival is a consumed no-op in iteration mode. THE TWO OUTPUT FOLDERS (architect 2026-08-27, R1, landed 2026-08-28): the DELIVERABLE `<title>.wav` + `.fingerprint` lands in `<project>/render/` (singular, "because the command is called render"; created at dispatch; the path's ONE owner is the parser's `render_output_directory`, shared by the CLI under a granted frozen touch 2026-08-28, so both products write the identical path), and the DISPOSABLE batch cells (iteration / bpm sweeps, `N_tag/NN.wav`, what `'` loads, what the render player's `tmp` branch lists and the trash road deletes) live in `<project>/tmp/` (lowercase, "to make it clear that that's temporary"; `kBatchFolderName` / `project_batch_root` in renders_dir.h, the GUI's alone). No migration — the architect moves his folders by hand (`mv renders tmp`, the deliverable into `render/`); a wav still in the root is the project model's legacy-layout refusal. A render dispatch kills the running render unconditionally; killed sessions never publish Success; target-view previews may reuse identical completed renders (fingerprint v19, phase-reset component trim-aware). THE BPM SWEEP KEEPS THE MAP'S SHAPE (architect 2026-08-26): each cell rewrites the span as before and rescales every owning marker OUTSIDE it by the owner's own change, banker's-rounded onto the cents grid (`bpm_cell_warp_markers`, the cell's one owner — the sweep per cell, the editor commit at the bracket's two ends; out-of-bracket refuses, never clamps), and `m` refuses a selected run whose members carry different tempos (each a pass or the owner's own value).

### Rounding

SCREEN PIXELS ARE CELLS, NOT POINTS (architect 2026-08-25, landed 2026-08-26): a pixel x covers [x, x+1), so a surface coordinate names the pixel that CONTAINS it — floor, through the ONE owner `containing_pixel` (input_core.h), which every pointer, touch and capture coordinate passes through on its way to an int; before that owner the ABSOLUTE mouse path truncated (`wl_fixed_to_int`) while the finger AND the captured-pointer ledger (the nav drag's virtual position and its release write-back) rounded (`nearbyint`) — the mouse and finger one pixel apart on the 10px endcap bands and the 8px crossing; the ledger's move from rounding to floor is the one LAPTOP-visible consequence (≤1px on the grab-pan's delivered coordinates and on a motionless click right after a capture release), accepted as the rule's own reach into a continuous coordinate. The cell/point distinction is the whole rule; no site restates it.
