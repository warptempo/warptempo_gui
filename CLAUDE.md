# Warptempo GUI

Custom C++23 in-process PGHI phase-vocoder GUI, an Android APK for one tablet (the laptop is the APK's cross-build host and the headless CLI's host, nothing more; its own GUI was dropped 2026-10-30), for time-warping audio toward historically-informed tempos. Single developer and user (the architect); one laptop, one tablet. THE PROJECT IS NEAR FEATURE COMPLETE (architect 2026-10-25): what remains is palette updates, small bug fixes and layout refinement (the background sound landed 2026-10-28 as the NOISE lamp, `src/gui/noise.h`). THE DESIGN IS THE FLAT LOOK (architect 2026-11-01, reversing the hi-fi panel of 2026-10-23 on his own proposal: "whatever ruling it needs to, we need to reverse to go flat"): Ableton Live's grammar and Live's measured numbers, one look; no other visual theme or chrome vocabulary is proposed.

THE CODE IS THE AUTHORITY. Every rule and its reason lives in a comment at the symbol that owns it; when this file, a doc or a memory disagrees with the code, the code wins — read it before asserting anything. `docs/engineering/closed_questions.md` lists, one line each, every question the architect has closed: never re-propose one (its lines about retired looks are moot, not open). `docs/INSTALL.md` is the runbook, `docs/HELP.md` the user's concepts, the tooltips the interface's own words.

## Build Commands

```bash
bash apk/build_apk.sh                                 # THE PRODUCT: cross-build + APK in the main tree, against deps/prebuilt; the commit gate
adb -s 192.168.1.87:5555 install -r apk/build-android/warptempo.apk
adb -s 192.168.1.87:5555 shell am start -n com.warptempo.gui/.MainActivity
cmake -B build -S . && cmake --build build -j$(nproc) # the laptop's one product, build/warptempo_cli; no option, no CMAKE_BUILD_TYPE (asserts live; -O3 -march=native -ffp-contract=off)
cmake -B build-debug -S . -DCMAKE_BUILD_TYPE=Debug    # a debug CLI in its own dir; never reconfigure build/ with -O0
```

CMake has NO OPTIONS (architect 2026-10-30): an Android configuration builds the `warptempo_gui` NativeActivity library, a Linux one builds `warptempo_cli`, the headless insurance render, byte-identical to the GUI through the shared stages. No library archives: per-directory source lists compiled directly. `tools/` holds standalone utilities with no link path from product targets. `-ffp-contract=off` is load-bearing: renders are byte-reproducible across rebuilds and `-march` choices (`docs/engineering/perf_campaign_2026_07.md` §15). The GUI has one platform (`GuiPlatform` is `platform_android.{h,cpp}`, `src/gui/platform.h` its one include) and one canvas road, the GL draw list. The laptop's binary is not portable (`-march=native`); the APK is. THE APK BUILDS IN THE MAIN TREE from the working tree (the `tmp/apk_src` snapshot road is retired); every commit is gated on `bash apk/build_apk.sh`'s real exit code. The tablet (Galaxy Tab S10 FE) is adb-drivable (install, launch, screencap, single-touch, logcat); multi-touch and feel are the architect's own glass pass.

## Dependencies

The CLI on the laptop: pkg-config `fftw3` (+`fftw3_threads`) and nothing else. The APK: every library static from the gitignored `deps/prebuilt/`, cross-built by `deps/*.sh` (fftw, freetype, harfbuzz, pixman, cairo + cairo-ft, OpenSSL's libcrypto under libssh2 under libgit2, resvg from a pinned Rust source by `deps/85_resvg.sh`), the NDK / build-tools / JDK fetched by `deps/toolchain/`; EGL + GLESv3 and AAudio are the platform's. The APK build also needs host `resvg` and ImageMagick 7's `magick` (the launcher icon), `zip`, `meson` + `ninja` for the deps. Cairo stays as the chrome's painter onto the backbuffer under the GL road; the canvas interior is the GPU's draw list alone. Audio I/O is in-tree and WAV-only. C++23, `-Wall -Wextra`. No Pango, SDL, GTK, GLFW. The app paints no window chrome (full screen, both system bars hidden). A HARDWARE KEYBOARD OR MOUSE AT THE TABLET IS CLOSED FOR GOOD (architect 2026-10-30: determinism is per display width, so consistency across sessions commits him to this one panel; a keyboard or mouse would duplicate the pen and the finger and lose the car form factor; `platform_android.cpp`'s key arm owns the ruling). The dead-input arc (82c4334a, d740f1b0 and the words commit) deleted every road nothing on glass feeds: the mouse doors, the wheel, the pointer capture, the cursor kinds, the core's shift / alt / super bits, the dead key arms, the dialogs' access keys. The chord grammar stays as the dispatch's internal key; its two producers are the roster's lift (the long press is Shift, the barrel is Ctrl) and the on-screen keyboard's `synthesize_key`. Statically linked libraries and licences: `THIRD_PARTY.md`.

Text: one face, LIBERATION SANS (Regular and Bold), the APK's assets from `fonts/`; nothing asks fontconfig. Every string goes through the one shaping chokepoint `src/gui/text_shape.{h,cpp}`; the sizes are one table, `kGuiFaceSizes` (`src/gui/gui_font.h`), authored in device px at 300 % and scaled with gui_scale. Text is UTF-8 in free text and ASCII in grammars; editors index by byte and step by codepoint; `text_editor::replace_selection` is the one incoming filter.

## Testing / Verification

There is NO automated test suite and that is a constraint. Do not propose automated tests, regression harnesses or commercial-tool comparisons. The CLI shares the stages with the GUI byte-identically; the architect runs cmp-null and audio verification against it. THERE IS NO LAPTOP EYEBALL ROAD (2026-10-30): every GUI check is adb on the tablet — `input tap` + `screencap` (two builds driven through the same states and compared byte for byte, the clock legend excepted, is the proof that a change left the picture alone; the drop arc was proven so, tmp/drop/); `adb logcat -s warptempo:I` when the screen dozes (a dozing tablet screencaps black); `dumpsys SurfaceFlinger --timestats` is the cadence proof. A tablet reboot kills wireless adb: re-arm over USB with `adb tcpip 5555`. The tablet's config is editable through `adb shell run-as com.warptempo.gui`. THE COLOR ROAD for any capture or mock he judges in the tablet's gallery (settled on his glass 2026-10-22 after four sessions of flipping; re-derived once since, so never again): THE iCCP TAG SAYS WHAT THE BYTES ARE — his Fossify Gallery honors the Display-P3 tag every screencap and every screenshot of his carries. A `true_colors=on` screencap (P3 bytes, tagged) is right as it is; a `true_colors=off` one (sRGB bytes, tagged) reads oversaturated and is right only with the tag STRIPPED. A color inserted into a tagged mock goes through the app's transform (`road.py`'s `srgb_to_p3`, `display_transform.h` byte for byte); into an untagged mock it is the plain sRGB byte. A mock composed on a fresh canvas (PIL `Image.new`) carries no tag, so its bytes must be sRGB; a JPEG conversion keeps the ICC profile. Never save P3 bytes untagged (pale) or sRGB bytes tagged (hot). `tools/mockup/README.md` owns the rule, `tools/mockup/road.py` is the tool (`capture` reads the tablet's `true_colors` and keeps or strips the tag; `srgb`, `p3`, `check`) — never re-derive it from a screenshot, which cannot see the panel.
