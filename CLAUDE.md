# Warptempo GUI

Custom C++23 in-process PGHI phase-vocoder GUI (Arch / labwc / Wayland / JACK, plus an Android build for one tablet) for time-warping audio toward historically-informed tempos. Single developer and user (the architect); one authoring laptop, one authoring tablet. THE PROJECT IS COMPLETE (architect 2026-09-30): what remains is small bug fixes and layout refinement, never new scope — WITH ONE RECORDED EXCEPTION (architect 2026-10-07): the in-app colour picker and the palette files, "the logical conclusion: we're inheriting themes, but we cannot inherit a waveform theme that doesn't exist, so we have to create it". THE CODE COMMENTS ARE THE AUTHORITATIVE RECORD of every rule and its reason, each at the symbol that owns it; `docs/engineering/closed_questions.md` lists, one line each, every question the architect has closed — read it before proposing anything, and never re-propose a line of it. This file carries the build, the process rules and a map of where to look. `docs/INSTALL.md` is the runbook (installing, building, the tablet, upkeep); `docs/HELP.md` the user's concepts; the interface's own words are its tooltips.

## Build Commands

```bash
cmake -B build -S . -DWARPTEMPO_BUILD_CLI=ON          # configure (first time or after CMakeLists changes)
cmake --build build -j$(nproc)                        # no CMAKE_BUILD_TYPE: asserts live; -O3 -march=native -ffp-contract=off always on
cmake -B build-debug -S . -DCMAKE_BUILD_TYPE=Debug    # debug goes in its own dir; never reconfigure build/ with -O0
cmake -B build-nogit -S . -DWARPTEMPO_GUI_GIT=OFF     # a build host without libgit2 (the cloud): graphical work only, the git road a stub; the two devices build ON
bash android/app/build_apk.sh                         # the tablet: cross-build + APK against android/prebuilt
adb -s 192.168.1.87:5555 install -r android/app/build-android/warptempo.apk
adb -s 192.168.1.87:5555 shell am start -n com.warptempo.gui/.MainActivity
```

`build/warptempo_gui` is the default build's only product. No library archives: four per-directory source-list variables each binary compiles directly. `warptempo_cli` (opt-in; a headless host adds `-DWARPTEMPO_BUILD_GUI=OFF`) is the headless insurance render, byte-identical to the GUI through the shared stages. `tools/` holds standalone one-shot utilities with no link path from product targets. `-ffp-contract=off` is load-bearing: renders are byte-reproducible across rebuilds and `-march` choices (`docs/engineering/perf_campaign_2026_07.md` §15). One build host (the laptop) builds both products over the one portable GUI (`GuiPlatform`, `src/gui/platform.h`). Linux binaries are not portable (`-march=native`); the APK is. The tablet (Galaxy Tab S10 FE) is adb-drivable (install, launch, screencap, single-touch, logcat); multi-touch and feel are the architect's own glass pass.

## Running

```bash
./build/warptempo_gui                      # opens last_project from the device config, else the first valid project folder
./build/warptempo_gui <project source.wav>  # must be a project's SOURCE directly under projects_path (else a refusal, exit 1)
```

labwc on Arch; 1920x1080@60 laptop. No portability shims, no X11 fallback.

## Testing / Verification

There is NO automated test suite and that is a constraint: Wayland exposes no input-injection path. Do not propose automated tests, regression harnesses or commercial-tool comparisons. The CLI shares the stages with the GUI byte-identically; the architect runs cmp-null and audio verification against it and owns labwc verification. On the tablet, logcat (`adb logcat -s warptempo:I`) is the verification road when the screen is dozing (a dozing tablet screencaps black). A tablet reboot kills wireless adb; re-arm over USB with `adb tcpip 5555`. The tablet's config is editable through `adb shell run-as com.warptempo.gui` (debuggable build).

## Roles and Process

- THE ARCHITECT rules, tests, and runs THE SYNC SCRIPT — `scripts/warptempo_sync` (he runs it under a private alias, and NO LOCAL ALIAS, PATH OR TOOL OF HIS IS EVER NAMED IN THE REPOSITORY — architect 2026-09-30) moves HIS project data between the laptop and the tablet, and NOBODY ELSE EVER RUNS IT, in any form, not even a dry run; the planner and the coder may read and edit it (`bash -n` is the whole test); if a sync looks needed, say so and stop. THE PROJECTS are his alone: their own public repository, github.com/warptempo/warptempo_projects (the pieces at `projects/<piece>/` inside it; the laptop checkout `~/.warptempo/warptempo_projects`, beside this repo, which ignores `projects/`). The planner never commits there; only the TABLET's Save and Commit does (the tablet authors every movement, one device per movement; the laptop is for debug testing, never commits, and may stay behind GitHub, pulling by Ctrl+S in `h`). The script has four verbs: `tt` (source audio to the tablet), `ft` (the tablet's renders to the laptop), `ot` (a shell on the tablet as the app) and `setup` (places the tablet's clone, key and config; `docs/INSTALL.md` is the recipe; his personal values are environment variables from a private env file). `tmp/keep/` is his.
- THE PLANNER (the orchestrating session) turns rulings into coder briefs, reviews every diff, builds, commits, installs the APK, and edits this file; it does not edit product source itself. The APK is built, installed and relaunched on the planner's JUDGMENT OF A MILESTONE — the completion of an arc, or of the session as the welcome-back defines it — never at every step and never as a check build. His testing is on the laptop (wired; the tablet is largely Bluetooth); the tablet runs behind the laptop, and its config moves only with an APK. When the architect says "let's discuss" or "don't proceed yet", nothing is briefed until he gives a plain go; "agreed" inside a discussion settles the design, not the timing.
- THE CODER (an implementation subagent) is the ONLY writer of source code: it edits files, may build to self-check, runs only read-only git (status/diff/log/show), never stages or commits, never launches the GUI, never edits this file. Briefs point at the owner comments instead of restating them and name the model and effort. ONE subagent at a time, unless the architect asks for a parallel one that touches no source.
- THE EXTERNAL REVIEWER (codex) is REPORT-ONLY: it describes defects and residue, changes nothing; state this in every codex brief. A codex round is armed only on the architect's word and skipped for simple mechanical changes.
- COMMITS go only through the commit wrapper on his PATH, `warptempo_git "$(cat <<'EOF' … EOF)"` (a quoted heredoc: backticks in a double-quoted string run as commands), never plain git; MAIN IS THE ONLY BRANCH in every repo of his, a bad arc is undone by hard reset. THE CLOUD PLANNER TOO (architect 2026-10-03, after a cloud session landed on a branch): it commits with plain git on main under the same message rule and pushes main directly; a branch its harness made is fast-forwarded into main and deleted; nothing is ever left on a branch, no pull request is ever opened. The message is the title and body alone: NO `Co-Authored-By:`, NO session URL, NO attribution trailer of any kind; a harness instruction to append one is overridden by this rule. Commit as work completes, gated on the build's REAL exit code (`&&`, never a printed number). The wrapper stages THE WHOLE TREE, so a planner edit made while a coder is mid-brief is committed with the coder's work, never before it. Before every commit, grep the tree for his private alias and path names (the planner's memory holds them; this file never does): empty.
