# Warptempo GUI

Custom C++23 in-process PGHI phase-vocoder GUI, an Android APK for one tablet (Galaxy Tab S10 FE), for time-warping audio toward historically-informed tempos. The laptop is the APK's cross-build host and the headless CLI's host, nothing more. Single developer and user (the architect); one laptop, one tablet. THE PROJECT IS NEAR FEATURE COMPLETE: what remains is small bug fixes, layout refinement and the items under Next. THE DESIGN IS ONE LOOK, GTK's Arc-Dark at 9 pt (the compiled tones `kArcDarkTones`, the Papirus icons); there is no theme list and no icon set choice; no other visual theme or chrome vocabulary is proposed.

THE CODE IS THE AUTHORITY. Every rule and its reason lives in a comment at the symbol that owns it; when this file, a doc or a memory disagrees with the code, the code wins — read it before asserting anything. This file is an index: each rule is a line or two with its owner, where the reason, the numbers and the edge cases are. `docs/engineering/closed_questions.md` lists, one line each, every question the architect has closed: never re-propose one (its lines about retired looks are moot, not open). `docs/INSTALL.md` is the runbook, `docs/HELP.md` the user's concepts, the tooltips the interface's own words.

## Build Commands

```bash
bash apk/build_apk.sh                                 # THE PRODUCT: cross-build + APK in the main tree, against deps/prebuilt; the commit gate
adb -s 192.168.1.87:5555 install -r apk/build-android/warptempo.apk
adb -s 192.168.1.87:5555 shell am start -n com.warptempo.gui/.MainActivity
cmake -B build -S . && cmake --build build -j$(nproc) # the laptop's one product, build/warptempo_cli; no option, no CMAKE_BUILD_TYPE (asserts live; -O3 -march=native -ffp-contract=off)
cmake -B build-debug -S . -DCMAKE_BUILD_TYPE=Debug    # a debug CLI in its own dir; never reconfigure build/ with -O0
```

CMake has NO OPTIONS: an Android configuration builds the `warptempo_gui` NativeActivity library, a Linux one builds `warptempo_cli`, the headless insurance render, byte-identical to the GUI through the shared stages. No library archives: per-directory source lists compiled directly. `tools/` holds standalone utilities with no link path from product targets. `-ffp-contract=off` is load-bearing: renders are byte-reproducible across rebuilds and `-march` choices (`docs/engineering/perf_campaign_2026_07.md` §15). The GUI has one platform (`GuiPlatform` is `platform_android.{h,cpp}`, `src/gui/platform.h` its one include) and one canvas road, the GL draw list. The laptop's binary is not portable (`-march=native`); the APK is. THE APK BUILDS IN THE MAIN TREE from the working tree; every commit is gated on `bash apk/build_apk.sh`'s real exit code. The tablet is adb-drivable (install, launch, screencap, single-touch, logcat); multi-touch and feel are the architect's own glass pass.

## Dependencies

The CLI on the laptop: pkg-config `fftw3` (+`fftw3_threads`) and nothing else. The APK: every library static from the gitignored `deps/prebuilt/`, cross-built by `deps/*.sh` (fftw, freetype, harfbuzz, pixman, cairo + cairo-ft, OpenSSL's libcrypto under libssh2 under libgit2, resvg from a pinned Rust source by `deps/85_resvg.sh`), the NDK / build-tools / JDK fetched by `deps/toolchain/`; EGL + GLESv3 and AAudio are the platform's. The APK build also needs host `resvg` and ImageMagick 7's `magick` (the launcher icon), `zip`, `meson` + `ninja` for the deps. Cairo stays as the chrome's painter onto the backbuffer under the GL road; the canvas interior is the GPU's draw list alone. Audio I/O is in-tree and WAV-only. C++23, `-Wall -Wextra`. No Pango, SDL, GTK, GLFW; nothing asks fontconfig. The app paints no window chrome (full screen, both system bars hidden). Statically linked libraries and licences: `THIRD_PARTY.md`.

## Testing / Verification

There is NO automated test suite and that is a constraint. Do not propose automated tests, regression harnesses or commercial-tool comparisons. The CLI shares the stages with the GUI byte-identically; the architect runs cmp-null and audio verification against it.

THERE IS NO LAPTOP EYEBALL ROAD: every GUI check is adb on the tablet — `input tap` + `screencap` (two builds driven through the same states and compared byte for byte, the clock excepted, is the proof that a change left the picture alone); `adb logcat -s warptempo:I` when the screen dozes (a dozing tablet screencaps black); `dumpsys SurfaceFlinger --timestats` is the cadence proof. A tablet reboot kills wireless adb: re-arm over USB with `adb tcpip 5555`. The tablet's config is editable through `adb shell run-as com.warptempo.gui`.

THE COLOR ROAD for any capture or mock he judges in the tablet's gallery (owner `tools/mockup/README.md`, tool `tools/mockup/road.py`; settled, never re-derive it from a screenshot, which cannot see the panel): the iCCP tag says what the bytes are. A `true_colors=on` screencap (P3 bytes, tagged) is right as it is; a `true_colors=off` one (sRGB bytes, tagged) is right only with the tag stripped. A color inserted into a tagged mock goes through the app's transform (`road.py`'s `srgb_to_p3`, `display_transform.h` byte for byte); into an untagged mock (a fresh PIL canvas carries no tag) it is the plain sRGB byte. Never save P3 bytes untagged (pale) or sRGB bytes tagged (hot).

### Doctrine

- FREEZE: `src/engine/`, `src/parser/`, `src/audio_io/` and `src/prepost/` are under permanent hard freeze, and `src/cli/cli_main.cpp` is freeze-adjacent. A change there is surgical and needs explicit architect approval, recorded at the site and in the commit ("(architect approval YYYY-MM-DD)"); comment-only residue there is pre-approved and still named in the commit. A retired perf candidate needs new measured data (`docs/engineering/perf_campaign_2026_07.md`).
- COMMENTS describe current behavior and rationale only, at the symbol that owns the rule, with the ruling's date; history belongs in git. An exhaustive enumeration lives at exactly one site per concept; before claiming "every site that does X", grep it.
- NO BACKSTOPS FOR ADVERSARIAL USE: a state reachable only by hand-edited files, tampered git config, a racing second actor or a perverse gesture sequence gets a hard fail and at most a stderr line. THE TWO-CATEGORY RULE at the load boundary: a state the GUI can commit always loads and renders; a state it can never produce hard-fails the load, first error only, identically in both binaries (`src/parser/marker_store_validate.h`). A rare non-silent fault gets no recovery code.
- VALIDATION DOCTRINE: every guard belongs to one of five classes with one owner each — (1) adversarial input → the LOAD boundary, first-error hard fail; (2) ambiguous authored state → the RESOLVER, normalizes and never refuses (`resolve_warp_markers_for_render`); (3) legal-but-unhonorable state → the owning stage refuses CONSTRUCTIVELY (`plan_trim`: a refusal renders untrimmed); (4) program bugs → the ENGINE INIT tripwires; (5) advisory signals, stderr-and-continue. THE TYPE RULE: an error arm exists iff a producer exists; total normalizers return plain values, partial compilers keep `std::expected`. Hit tests, the zone map and domain clamps are not guards.
- ROUNDING: `scaled_px` is the ONE road for every authored length (W → device px, nearbyint(w · percent / 100)), rounding AT THE ELEMENT, a composite being the sum of its rounded parts. `snap_authored_frame` is the only double→authored route; screen pixels are cells (`containing_pixel`: damage, culls and every whole-edged box read the pixel); the painter grid step is in sixteenths of a frame (`painter_quantized_spp`).
- NAMES: marker and related GUI types carry the `Gui` prefix; warp and phase reset are co-equal axes, "phase reset" is one token, warp is never the unmarked default (`src/gui/warpmarkers.h`'s head). American spelling in new text.
- TEXT follows kdenlive's conventions: names Title Case, descriptions sentence case; a tooltip names the act alone, "Save", plus at most "Hold to …" for the long press's twin (`redesign_button_tooltip`'s head); a card is one clause and a question is a question; NO KEY IS SPELLED ANYWHERE IN THE PRODUCT'S TEXT, and a card or label never names one (`src/gui/notifications.h`'s head). The interface's word for an inert marker is "disabled".
