# Warptempo GUI

Custom C++23 in-process PGHI phase-vocoder GUI (Arch / labwc / Wayland / JACK) for time-warping audio toward historically-informed tempos. Single developer/user (the architect); one authoring laptop plus the Raspberry Pi rig. PROJECT STATUS: FEATURE COMPLETE (architect, 2026-07-25). The authoritative architecture rulings live in `docs/engineering/architecture/` — see the docs map below. This file carries the build/process rules, short per-topic digests, and pointers; the topic files are the authoritative detail. When a ruling lands, update the topic file (committed) and this file's digest ONLY if the headline changes — history, quotes and successions belong in the topic files and in git, never here. ## Build Commands

```bash
# Configure (from project root, first time or after CMakeLists changes)
cmake -B build -S . -DWARPTEMPO_BUILD_CLI=ON

# Build (Release is the project default; -O3 -march=native -ffp-contract=off is always on)
cmake --build build -j$(nproc)

# Debug build into a separate dir; never reconfigure `build/` itself with -O0
cmake -B build-debug -S . -DCMAKE_BUILD_TYPE=Debug
cmake --build build-debug -j$(nproc)
```

`build/warptempo_gui` is the GUI binary and the default build's only product. No library archives: four per-directory source-list variables (`WARPTEMPO_AUDIO_IO_SOURCES`, `WARPTEMPO_PARSER_SOURCES`, `WARPTEMPO_ENGINE_SOURCES`, `WARPTEMPO_PREPOST_SOURCES`) each binary compiles directly — object-code duplication accepted deliberately. One opt-in binary, default OFF: `warptempo_cli` (`-DWARPTEMPO_BUILD_CLI=ON`, the headless insurance render — exactly the terminal Ctrl+Alt+R, byte-identical to the GUI by shared stages; a headless host builds it with `-DWARPTEMPO_BUILD_GUI=OFF`). `tools/` holds standalone one-shot utilities (own CMakeLists, no link path from product targets). `-ffp-contract=off` is load-bearing: renders are byte-reproducible across rebuilds and `-march` choices under the same toolchain (scope in `docs/engineering/perf_campaign_2026_07.md` §15).

THE TWO HOSTS BUILD IN LOCKSTEP (architect 2026-08-14): the authoring LAPTOP and the Raspberry Pi RIG (aarch64, the ROADOM touchscreen — the only host with glass, so every touch ruling is verifiable there and nowhere else) are both built and kept at the SAME COMMIT as part of landing work. IF THE RIG IS UNREACHABLE, SAY SO AND STOP — the architect fixes it before development continues. A laptop build proves compilation, never behaviour on glass. Rig connection details are local-only (tmp/rig.md, gitignored). Binaries are not portable (`-march=native`); rebuild on the target host.

## Dependencies

pkg-config: `fftw3` (+`fftw3_threads`), `wayland-client`, `wayland-cursor`, `wayland-protocols`, `xkbcommon`, `cairo`, `cairo-ft`, `harfbuzz`, `jack`; plus `wayland-scanner` at build time. All audio container I/O is in-tree and WAV-only, so the non-GUI sources need only `fftw3`. C++23 (`std::expected` in the parser), `-Wall -Wextra`. Do not introduce Pango, SDL, GTK, GLFW, or wlroots-specific protocols — the GUI is libwayland-client only (`wayland-cursor` the canonical exception). Generated protocol stubs: xdg-shell, xdg-decoration (REQUIRED at startup), pointer-constraints-unstable-v1 + relative-pointer-unstable-v1 (the strip-drag pointer capture — the ONLY optional protocols; absence degrades to clamped absolute motion). The required-globals set is five, `wl_data_device_manager` (system clipboard, core protocol) included.

Text: proportional text measures AND paints through the ONE shaping chokepoint `src/gui/text_shape.{h,cpp}` (contract in its header) on the one sans face (fontconfig "sans", 12pt × gui_scale); the row-8 CLOCK is the product's one monospace surface (fontconfig "monospace", normal weight). TEXT IS UTF-8 IN FREE TEXT AND ASCII IN GRAMMARS: editor buffers and free-text settings values take UTF-8 verbatim and round-trip byte-identically; every structural grammar (marker labels, numeric spellings, settings keys/vocabularies, canonical-line payload) stays ASCII. Editors index by byte but step by CODEPOINT; no font fallback, no bidi, graphemes out of scope; `text_editor::replace_selection` is the one incoming filter. Contract at the head of text_editor.h; full ruling in conventions.md.

## Architecture Rules (MUST follow — digests; the topic files are authoritative)

### Freeze Status (architect-declared 2026-07-12)
`src/engine/`, `src/parser/`, `src/audio_io/`, and `src/prepost/` are under PERMANENT HARD FREEZE: surgical changes only, each requiring explicit architect approval to reopen. `src/cli/cli_main.cpp` is freeze-adjacent (same discipline). Only GUI work remains. EVERY GRANTED FROZEN TOUCH RECORDS ITS GRANT at the site and in the commit message ("(architect approval YYYY-MM-DD)"). A retired perf candidate needs new measured data to re-propose (perf_campaign_2026_07.md).

### Authored Domain (→ data-model.md)
Authored positions (marker times, trim bounds) are whole source frames in `int64_t` everywhere at rest; `snap_authored_frame` (app_state.h) is the ONLY double→authored conversion route. Authored tempo is 100-based integer CENTS in [25, 400]; every other value is a bracketed double via `value_format.h`. One serialization domain (`frame_format.h`): canonical integer spelling only — anything else is adversarial load-fatal. Walls are exact integer compares on the shared inclusive [0, total−1] domain. Sources: WAV-only, 16/24-bit PCM, ≥44100 Hz, stereo-only.

### Pixel Anchoring, Viewport, Zoom (→ zoom-viewport-strip.md, kdenlive-redesign.md)
Position gestures anchor to the painted column grid and commit through `authored_frame_at_column` → `snap_authored_frame`; walls win over the grid everywhere. Waveform width floors to a multiple of 16px; `clamp_viewport_start` is the one viewport chokepoint (owns the zoom-level clamp too). Zoom is continuous in [1.0, 17.0]; `c` = working zoom 2.0; `0` = full zoom out, STAMPING the level it leaves into the tab's `zoom_recall_level` (session-only, unpersisted), and at the ceiling the `c` command AT THAT STAMPED LEVEL — plain `c` when nothing is stamped, and plain `c` too when the stamp can no longer move the zoom (a ceiling that fell under it). The TOP STRIP IS SEVEN LANES (menu row / tab row / icon row / overview strip / trim bar / ruler / marker lane) plus ONE unified bottom row; the vertical stack has ONE owner in main.cpp (waveform max height `kWaveformMaxHeightPx`, waveform midpoint = window midpoint, both flexible gaps floor at 0; the kdenlive-redesign.md commit-B section is authoritative for the stack). The NAVIGATION SURFACE (whole waveform + ruler + empty marker-lane stretches; the whole waveform + lanes in the `h` view; one owner `point_on_nav_surface`) takes ONE vocabulary: PLAIN DRAG = the grab-pan (capture at the 8px crossing, cursor hidden, notional x wraps edge-to-edge across the waveform), MOTIONLESS PLAIN CLICK = playhead placement deferred to the RELEASE, SHIFT+DRAG = the trim sweep (a direct trim write per motion event; the `h` view's is a playhead sweep alone), CTRL+DRAG = the same drag's ZOOM mode — ctrl is LIVE mid-drag; zoom is HORIZONTAL with RIGHT = IN (rate `kNavZoomPxPerLevel`, the product's one drag-zoom rate), pivot = a song frame seated at ctrl-down with edge clamp-and-rebind, the anchor stem painted and the cursor restored onto it. PLAIN WHEEL = the stepped pan; CTRL+WHEEL = one zoom level per detent; every other modified wheel is a swallowed no-op; the right button is unbound. The OVERVIEW STRIP (lane 3, 24px content) carries whole-song bars + viewport box + playhead tick; its vocabulary is drag-the-outline (pan), click-teleport (outside the box, AT THE PRESS — and the SAME press then arms that pan, so a pointer or finger that keeps moving keeps panning; the grab offset is measured after the teleport, never assumed zero), drag-the-bounds (10px grab bands shared with the trim endcaps and the waveform trim overlay's bounds, `kTrimEndcapGrabPx` — a bound is dragged by its own band and nowhere else); the plain lane off the endcaps wears TrimResize throughout; the THIN LANES (overview + trim bar) ignore second fingers entirely. THE PLATE RENDERER is aliased-only ARGB32, per-column raw min/max on the authoring lattice, 13-rung peaks pyramid, one synchronous full render for every user-driven pan/zoom frame. EVERY PAN SUPPRESSES FOLLOW for the playback session (`scroll_viewport` funnel). All view switches take the synchronous rebuild; bare 1/2/3 are absolute view selectors composing the `t`/`p` handlers.

### Render Pipeline (→ render-pipeline.md)
The parser is the sole authored→engine compiler (phase resets emit `S − N/2`, no render-time offset anywhere); geometry in `engine_geometry.h`. Trim is a prepost stage: full maps → `plan_trim` (refusal = render untrimmed, never a failed render) → trim-ignorant engine → `post_trim` → unconditional limiter → encode. No subprocesses in the render path. Ctrl+Alt+R is TWO commands selected by the iteration-mode bit (single render / iteration sweep); Ctrl+Alt+Shift+R archival is a consumed no-op in iteration mode. A render dispatch kills the running render unconditionally; killed sessions never publish Success; target-view previews may reuse identical completed renders (fingerprint v19, phase-reset component trim-aware).

### Colors (→ render.h palette block)
THE PALETTE IS HARD-CODED WHOLE, no user-settable colors, FULLY OPAQUE (no compositing alphas): every painted surface is a constexpr from its sampled kdenlive/Breeze crop or a recorded derivation; a retune is a recompile. The region highlight recolors the CANVAS GROUND under the ink; the marker class ladder is DISABLED > RED > (selected-bright default); stems read the CLASS alone; disabled markers paint no stem. colors.conf and its machinery are deleted. Codex is skipped for simple color tuning.

### Settings (→ settings.md)
`app.engine_settings` is typed truth; all three boundaries are strict (whole-file schema load shared verbatim by GUI and CLI; editor red-flash; typed dispatch). `kSettingsOrder` owns write order, `kEngineKeys` membership; adding an engine key = six edits, four files. EVERY key is required — no absent state, no load-side default. GUI-kind keys commit through each key's own gesture chokepoint, history-less. Numeric values pin to one canonical spelling each. `gui_scale` is an integer percent in [50, 200], the product's ONE scale axis (`gui_scale_factor()`), applied live. Render entries carry the same sidecar set a source does; `'` loads an entry in place, 1:1 in memory.

### Load-Lenient, Render-Normalizing Boundaries (→ normalization-and-boundaries.md)
Gestures move freely and NOTHING POPS: ambiguous authored states normalize at the render boundary (`resolve_warp_markers_for_render`; red flags as the display cue), never refused or force-resolved. The two-category rule: a state the GUI can commit always loads and renders; a state the GUI can never produce is adversarial and hard-fails the load, first error only, identically in both binaries. The same family covers the REPOSITORY: sanctioned use is strict-exact intended use; out-of-app git under `projects/`, a detached HEAD or a hung hook get a blunt terminal error, no in-app recovery. TRIM IS ALWAYS SET (a full ordered pair always rests; crossed pairs reset to the full window; the endcap drag clamps inclusively at the partner, and a coincident release resets to the whole song — the drag's own escape and the finger's only one); THE FULL WINDOW IS SEMANTICALLY THE OLD UNSET STATE through the one predicate `trim_window_is_full`. EVERY route that writes a trim bound clears the selection and parks the playhead at the new trim start (membership at input_trim.cpp's header), and every trim write is the ONE class excluded from `clear_region_highlight`'s inventory. THE SWEEP takes a MINIMUM WIDTH FLOOR instead of a refusal — `kMinTrimSpanFrames` = 65536 whole source frames, derived as the tempo-scale ceiling times `kN`, widening rather than refusing; `x`'s degenerate-result refusal and the former's sliver dissolve are retired with it. Trim has no undo — `Shift+X` is the recovery. NOTHING LOOPS: every audition plays once to its end (song's end in source view, preview buffer's end in target; `Viewport::trim_range` is the NAVIGATION range owner). Undo coalescing is a hybrid: a HELD KEY'S or HELD BUTTON'S synthesized repeats coalesce by repeat identity behind an OPENER that differs per surface — a held key's burst opens with its own PHYSICAL PRESS, a held button's with its FIRST FIRE (the button's act being the lift's) — rapid physical taps at their presses within `kTapCoalesceMs`=500 merge on a standing subject; `record_gesture` stamps only on the accepted path.

### Interaction Model (→ selection-model.md, marker-ui.md, region-scrub-esc.md, pointer-hit-testing.md)
Every plain marker click lands the playhead, AT THE PRESS through the one act owner `run_marker_click_act` (the plain arm alone then arms `PendingMarkerPress`, whose crossing begins the drag and whose motionless lift owes only the double-click seed); shift = inclusive range from the anchor/focus, ctrl = membership toggle, both landing on the focus they set and arming nothing, both FLAG-ONLY (ADD TO SELECTION — bare `k` and its bottom-row lamp — is the STICKY CTRL for glass: while lit a plain flag click takes that same toggle branch, SHIFT BEATS IT, it is scoped to flag hits by construction, and it auto-clears at every `Selection` mutator except the toggle itself) — a modified press over the waveform is the waveform's own gesture in every view. MARKER STEMS ARE POINTER-INERT everywhere; the FLAG BOX is the marker's one pointer surface (stems still paint). The playhead has ONE form and always paints; a selection's cue is its members' brightened flags. THE REGION IS THE TRIM (2026-08-18): `RegionState` is ONE VISIBILITY BIT and nothing else, the overlay DERIVED from the resting trim bounds every frame through `trim_overlay_span`, so the bar, the overlay and the hit test cannot drift. A SHOWN overlay is manipulable ON THE WAVEFORM ALONE (`region_manipulation_hit`, Y-gated to the waveform rect, 10px bands): drag on a bound = that ENDCAP drag, drag inside = the BRIDGE drag, else pan — trim's own drags armed from a second surface, no parallel editor, their motionless lift falling to the waveform's ordinary click act; shift/ctrl bypass it. TOUCHING THE TRIM SHOWS THE TRIM (2026-08-19): `show_trim_region_overlay` is the ONE raise — the hide's counterpart, no framing (unlike `x`'s show half), `h` carved out inside it — called by THE SWEEP'S ARM (`arm_region_drag_at`) and by all THREE of the 9px band's press claims (the plain endcap/bridge press anywhere on the band, the two ctrl bound-set presses), always AT THE PRESS. THE SWEEP (the nav surface's shift+drag and the touch region hold) writes the trim PER MOTION EVENT under the `kMinTrimSpanFrames` floor, so a shown overlay tracks the stroke live; `commit_region_sweep` is its one release owner; the `h` view's shift former is a PLAYHEAD SWEEP that writes no trim and is carved out of both the write and the show. Every former drops the selection its surface owns and carries the playhead on its moving end. BARE `x` SHOWS AND HIDES (the icon row's lit rect-selection twin, named **Show trim region** — the tooltip names a constant act while the lamp carries the state, the read-only toggle's precedent; `Ctrl+Shift+X` is unbound) — the show half brings the span into view via `bring_span_into_view` (the undo restore's own scroll-else-frame, one shared owner) and HIDING DISCARDS NOTHING, the trim persisting; `Shift+X` maximizes to the whole song (the key, or that same button shift-clicked or long-pressed) and is the recovery, trim having no undo. `clear_region_highlight` is a HIDE — bare Esc, the deferred click act, and every playhead-moving or selection-changing route; the deliberately excluded classes are EVERY TRIM WRITE, THE SWEEP'S OWN PRESS, THE TWO VIEW SWITCHES (A/B and S/T, whose in-place resets went 2026-08-19) and THE `h` MODE'S THREE OWN EDGES (exit, `,`/`.` step, walk-or-reading switch) — VISIBILITY IS A VIEW PREFERENCE, NOT A PLAYHEAD/SELECTION/MUTATION CONCERN; the file load keeps the one surviving in-place reset (inventory at its declaration, input_handler.h). CURSORS: named XCursor-theme cursors only, seven kinds, ONE zone map derived from the press routers (`pointer_cursor_kind`), resolved once per run-loop iteration by one owner; a live trim gesture keeps its own cue; the cursor promises the gesture. READ-ONLY protects the authored musical content only — trim gestures, `x`/`Shift+X`, Ctrl+S and both render chords stay legal on a locked tab; the settings editor is disabled there (`read_only_key_blocked`). SPACE always plays from the playhead. HORIZONTAL MOVEMENT IS A FOCUS ACT — groups are never moved; singleton steps CLAMP at walls, group presses REFUSE whole (position_nudge.h). Bare arrows nudge the FOCUSED marker in its home view; every focus-changing route lands the playhead (`land_playhead_on_marker`).
