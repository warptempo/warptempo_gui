# The product's faces

These six files are the product's faces on both devices (the rules at `src/gui/gui_font.h`, the one face owner): THREE FAMILIES, Tahoma, FreeSans and Liberation Sans, each with its bold. The Linux build compiles all six into `warptempo_gui`; the APK carries them as its assets. Both read the names from one list, `kGuiFontFiles` in `gui_font.h`. Neither device asks the system for a font. Each face is drawn as its antialiased outline at every scale, at the em that matches each use's recorded vertical metrics (`GuiFaceSet` in `gui_font.h`). The files' own line metrics are never read, and their embedded bitmap strikes are never drawn.

## The face set

A face set is one face's text: which file each of its four uses is drawn from, its recorded metrics (ascent, descent and one measured height in Windows px — the cap off "H", the digit off "0", or the x-height off "x", `GuiFaceMeasure`) and its tracking (`GuiFaceSet` in `gui_font.h`). THE DEVICE CONFIG'S `font` KEY CHOOSES THE LIVE SET, under every chrome (architect 2026-10-09: "the font is its own drop-down … it doesn't really make sense picking a font via palette or even in the palette picker"): `tahoma`, `free-sans` or `liberation-sans`, absent `tahoma`, picked in the Settings menu's Font row ("Tahoma", "FreeSans", "Liberation Sans") and applied live (`gui_live_face_set` in `gui_font.h`). A scheme carries no face. EVERY SET IS NAMED BY ITS FILES, NEVER BY THE WINDOWS FACE IT STANDS IN FOR (architect 2026-10-09: "I just want to make sure that the fonts are named honestly … Liberation Sans is a stand-in for Arial, and FreeSans is what we're actually providing"). There are three sets. Windows 2000's dates from the Windows 2000 pivot (architect 2026-10-06; Nimbus Sans, the Windows 95 vocabulary's face, was dropped then and stands in git history). The FreeSans set (2026-10-09) stands in for MS Sans Serif, the face Windows set its chrome in before Windows 2000's Standard scheme took Tahoma, at that face's x-height. The Liberation set (2026-10-09), a stand-in for Arial, is THE FALLBACK FACE for a user whom FreeSans's hinting troubles (architect 2026-10-09: "we can drop in Liberation as a fallback if the user has problems"). Windows' faces and the fallback alone (architect 2026-10-09: "Go Sans can be removed because it's not a Windows font").

The ems are worked out from the files at the install (`src/gui/gui_font_bundled.cpp`), for every set at once, because Android installs the faces before it reads the config and a Settings pick swaps the set live. The win2000 body, bold and small come to 11.003, 10.996 and 7.943 Windows px. The FreeSans ones come to 11.450, 11.111 and 8.197: that set's body and bold are measured by THE X-HEIGHT, not the cap (architect 2026-10-09: "authentic to 1 windows px per measure for 1:1 proportion … I'm talking about height"), 6 rows as on the architect's Windows Me capture, off FreeSans's "x" (524 of 1000) and FreeSans Bold's (540), its "0" 732. The capture's caps stand 9 rows, MS Sans Serif's own tall-cap proportion (cap over x 1.5), which a Helvetica does not share (FreeSans's "H" is 729 of 1000 in both files, 1.39 over its "x"), so the cap is derived instead: 8.347 for the body and 8.100 for the bold, the band the chrome's labels center. The Liberation set takes the same x-height measure, its sibling as a stand-in at Windows' metrics: the body 11.357 off Liberation Sans's "x" (1082 of 2048), its cap derived to 7.813 off the "H" (1409), the small 8.474 off the "0" (1450); the bold's em comes off its own "x". Every measure is a height; the faces keep their own widths. A retune swaps a file; only the comments that quote these numbers need working out again.

## Provenance and licences

**Tahoma** (`tahoma.ttf`, `tahomabd.ttf`): Wine Tahoma as ReactOS 0.4.16 ships it. It is ReactOS's maintained fork of Wine's `fonts/tahoma.sfd` (Larry Snyder, 2004, based on Bitstream Vera Sans), with glyphs from Tavmjong Bah's Arev fonts and Greek and Hebrew glyphs and improvements by Katayama Hirofumi MZ. The files are `media/fonts/tahoma.ttf` and `media/fonts/tahomabd.ttf` of https://github.com/reactos/reactos at its `releases/0.4.16` branch, the same commit as the `0.4.16-release` tag, `822e8647792a2c43f033e3e00ed273d59f163c7b`. They are byte-identical to the copies on the ReactOS 0.4.16 i386 ISO. The last change to each was commit `13b69725008a` for the regular (2024-06-12, "[FONTS] Tahoma: Remove bitmap glyph workaround") and `9525593660b0` for the bold (2019-12-08).

The licence statements that travel with them:
- **The files' own name table** (IDs 13 and 14) states the GNU LGPL, version 2.1 or any later version. That is the licence of Wine's sources. Its text is `COPYING-LGPL-2.1.txt`, ReactOS's `COPYING.LIB` at the same commit.
- **ReactOS's licence document for the face** (`media/fonts/doc/Tahoma/LICENSE.txt` at the same commit) travels beside them verbatim as `LICENSE-Tahoma-ReactOS.txt`. It states the Bitstream Vera licence and the Arev licence for the glyphs drawn from those fonts, and says ReactOS's changes are in the public domain.

The product ships the files unmodified under their own name ("Tahoma", as ReactOS ships them). The app draws the face at its own advances (the win2000 set's `tracking_px` is 0, architect 2026-10-07: heights matched, never widths), and the files themselves are unchanged. Its hhea ascent (2049 of 2048) stands above its caps, so a program that seats text on a font's own line box sets it low; the product never does that: the recorded metrics are the only vertical metric source (`src/gui/gui_font.h`).

**FreeSans** (`FreeSans.otf`, `FreeSansBold.otf`): GNU FreeFont's FreeSans and FreeSans Bold from its last release, 20120503, as Arch Linux packages them in `gnu-free-fonts` 20120503-9 (`/usr/share/fonts/gnu-free/`), byte-identical. FreeSans's Latin outlines are URW's Nimbus Sans L, a Helvetica, the genre MS Sans Serif was drawn from; it stands in for MS Sans Serif, which has no open outline (Wine's is bitmap strikes, which the product never draws; Microsoft Sans Serif is proprietary) — architect 2026-10-09, "let's use free sans". Their `name` table says "FreeSans" / "Regular" and "Bold", versions 0412.2268 and 0412.2261, copyright "2002, 2003, 2005, 2008, 2009, 2010, 2012 GNU Freefont contributors".

The licence that travels with them is the files' own: GPL-3.0-or-later WITH THE FONT EXCEPTION (embedding the font in a document does not by itself bring the document under the GPL). The package installs no licence file, so `LICENSE-FreeFont.txt` carries the files' own statement verbatim (their `name` record 13, identical in both) and the GPL version 3 text as Arch's `licenses` package installs it (`/usr/share/licenses/spdx/GPL-3.0-or-later.txt`).

The product ships the files unmodified under their own name ("FreeSans"), with no tracking. They are OpenType CFF; FreeType's one loader takes them as it takes the TrueType faces, and the light target reaches the face's own PostScript hints through FreeType's CFF engine rather than the autohinter (vertical only, every x within 1/64 px of the outline; `src/gui/gui_font_bundled.cpp`). Their hhea ascender (900 of 1000) stands 171 units above the caps, so a program that seats text on the face's own line box sets it low; the product never reads it: the recorded metrics are the only vertical metric source (`src/gui/gui_font.h`). The files carry no bitmap strikes.

**Liberation Sans 2.1.5** (`LiberationSans-Regular.ttf`, `LiberationSans-Bold.ttf`): the liberation-fonts 2.1.5 release (https://github.com/liberationfonts/liberation-fonts), as Arch Linux packages it in `ttf-liberation` 2.1.5-2 (`/usr/share/fonts/liberation/`), byte-identical. Their `name` table says "Liberation Sans" / "Regular" and "Bold", Version 2.1.5. Liberation Sans is metric-compatible with Arial, a stand-in for it, and the product names it by its own name; its kerning is why the architect keeps it ("my go-to font because of the kerning. It looks the best at 1080p … the most well-behaved of all the fonts", 2026-10-09). It was the product's fallback face once before, 2026-10-05 to 2026-10-06, before Nimbus Sans took that place (git history), and returns as the fallback for FreeSans: TrueType, it meets the light autohinter as Tahoma does (`src/gui/gui_font_bundled.cpp`), where FreeSans's own CFF hints snap the round letters' baseline overshoot to a whole row past ~360 %.

The licence that travels with them is the package's `LICENSE`, the SIL Open Font License 1.1, verbatim as `LICENSE-Liberation-OFL.txt`: "Digitized data copyright (c) 2010 Google Corporation with Reserved Font Arimo, Tinos and Cousine. Copyright (c) 2012 Red Hat, Inc." The product ships the files unmodified under their own names, as the OFL's reserved-name clause wants, with no tracking (architect 2026-10-09: no custom font targeted at a few scales is ever shipped — a derived FreeSans was ruled out the same night). Like the others, the face's own line box is never read: the recorded metrics are the only vertical metric source (`src/gui/gui_font.h`).
